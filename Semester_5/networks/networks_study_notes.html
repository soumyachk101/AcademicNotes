Introduction & Physical Layer

Network fundamentals — types, topologies, OSI/TCP-IP models, transmission media

Network Types

Computer networks are classified based on their geographic scope and coverage area:

  • LAN (Local Area Network): Covers a small area like a room, building, or campus. High speed (100 Mbps – 10 Gbps), low error rate. Examples: office network, school computer lab.
  • MAN (Metropolitan Area Network): Spans a city or metropolitan area. Larger than LAN but smaller than WAN. Examples: cable TV network, city-wide broadband.
  • WAN (Wide Area Network): Covers countries or continents. Connects multiple LANs/MANs. Lower speed, higher error rate. The Internet is the largest WAN.
  • PAN (Personal Area Network): Very small network around an individual (typically within 10 meters). Examples: Bluetooth, USB, infrared connections.
  • VPN (Virtual Private Network): Uses public networks (like Internet) to connect remote sites securely as if on a private network.

Network Topologies

The physical layout or structure of a network determines how devices are connected:

  • Bus Topology: All devices share a single communication line (backbone). Simple and cheap but a cable break disables the entire network.
  • Star Topology: All devices connect to a central hub/switch. Most common today. If one cable fails, only that device is affected. Central point is a single point of failure.
  • Ring Topology: Each device connects to two neighbors, forming a ring. Data travels in one direction. A break in the ring can disable the network (unless dual ring).
  • Mesh Topology: Every device connects to every other device. Highly reliable but expensive. Used in critical networks (military, backbone). Can be full mesh or partial mesh.
  • Tree Topology: Hierarchical structure combining star and bus. Useful for large networks organized in levels (e.g., campus network).

OSI vs TCP/IP Model

The OSI (Open Systems Interconnection) model is a 7-layer reference model developed by ISO. The TCP/IP model is a 4-layer model used in the practical Internet.

OSI Layers (7):

  • Physical Layer: Raw bit transmission over physical medium (cables, signals).
  • Data Link Layer: Framing, physical addressing (MAC), error detection, flow control.
  • Network Layer: Logical addressing (IP), routing, path determination.
  • Transport Layer: End-to-end delivery, reliability (TCP), port numbers.
  • Session Layer: Establishes, manages, and terminates sessions between applications.
  • Presentation Layer: Data translation, encryption, compression (formatting).
  • Application Layer: Network applications (HTTP, FTP, SMTP, DNS).

TCP/IP Layers (4):

  • Network Access / Link: Physical + Data Link layers combined.
  • Internet: Network layer (IP, ICMP, ARP).
  • Transport: Transport layer (TCP, UDP).
  • Application: Application + Presentation + Session layers combined.

Transmission Modes

Transmission mode defines the direction of data flow between sender and receiver:

  • Simplex: Data flows in ONE direction only. Example: keyboard → computer, TV broadcast.
  • Half-Duplex: Data flows in BOTH directions, but not simultaneously. Example: walkie-talkie, old Ethernet (hub-based).
  • Full-Duplex: Data flows in BOTH directions SIMULTANEOUSLY. Example: telephone call, modern Ethernet (switch-based).

Transmission Media

Guided Media (Wired):

  • Twisted Pair: Two insulated copper wires twisted together. Categories: Cat5 (100 Mbps), Cat6 (1 Gbps), Cat7 (10 Gbps). Cheap, easy to install, but susceptible to EMI and attenuation. Used in LANs.
  • Coaxial Cable: Central copper conductor surrounded by insulating layer, metallic shield, and outer cover. Better shielding than twisted pair. Used in cable TV, older Ethernet (10BASE2, 10BASE5).
  • Fiber Optic: Glass or plastic fibers transmit light pulses. Highest bandwidth, longest distance, no EMI, most secure. Two types: Single-mode (long distance) and Multi-mode (short distance). Expensive but superior performance.

Unguided Media (Wireless):

  • Radio Waves: Omnidirectional, penetrate walls, used in Wi-Fi, Bluetooth, cellular.
  • Microwaves: Unidirectional, line-of-sight, used in satellite, cellular backhaul.
  • Infrared: Short range, line-of-sight, used in TV remotes, IrDA.

Multiplexing

Multiplexing allows multiple signals to share a single communication channel, maximizing bandwidth utilization:

  • FDM (Frequency Division Multiplexing): Divides bandwidth into frequency bands. Each signal gets its own frequency range. Used in radio/TV broadcasting, cable TV.
  • TDM (Time Division Multiplexing): Divides time into slots. Each signal gets a time slot. Synchronous TDM uses fixed slots; Statistical TDM dynamically allocates slots. Used in digital telephony (PCM).
  • WDM (Wavelength Division Multiplexing): Used in optical fibers. Different wavelengths (colors) of light carry different signals. Increases fiber capacity exponentially. DWDM (Dense WDM) packs even more channels.

Switching Techniques

  • Circuit Switching: A dedicated physical path is established between sender and receiver before data transfer. Used in traditional telephone networks (PSTN). Guaranteed bandwidth but inefficient — path is reserved even when idle.
  • Message Switching: Entire message is stored at each intermediate node (store-and-forward), then forwarded. No dedicated path. Used in email systems. Not suitable for real-time.
  • Packet Switching: Message is divided into packets. Each packet is routed independently. Resources are used on demand. More efficient than circuit switching. Used in the Internet. Two approaches: Datagram (each packet routed independently) and Virtual Circuit (path established first, like a circuit).
Exam Tip: OSI vs TCP/IP is a VERY frequently asked comparison. Always memorize the 7 layers of OSI in order. Remember: OSI is a reference model (theoretical), TCP/IP is what the Internet actually uses (practical). Key difference: OSI has Session and Presentation layers; TCP/IP merges them into Application layer.

Advantages: cheap, easy to install, flexible. Disadvantages: susceptible to EMI, limited bandwidth and distance. Used in LANs and telephone networks.

Explain OSI reference model in detail. Compare each layer's functions with TCP/IP model.

The OSI (Open Systems Interconnection) reference model is a 7-layer conceptual framework developed by ISO (International Organization for Standardization) in 1984. It standardizes how different systems communicate over a network. Each layer performs specific functions and provides services to the layer above it.

Layer 7 — Application Layer: Closest to the end user. Provides network services directly to applications. Functions include identifying communication partners, determining resource availability, and synchronizing communication. Protocols: HTTP, FTP, SMTP, DNS, Telnet.

Layer 6 — Presentation Layer: Handles data translation, encryption, and compression. Converts data from application format to network format (and vice versa). Ensures that data sent by one system can be read by another (e.g., ASCII to EBCDIC conversion). Protocols: SSL/TLS, JPEG, MPEG.

Layer 5 — Session Layer: Establishes, manages, and terminates connections (sessions) between applications. Handles dialog control (who transmits when) and token management. Protocols: NetBIOS, RPC, SCP.

Layer 4 — Transport Layer: Provides end-to-end delivery of data. Ensures reliability through error detection, flow control, and segmentation/reassembly. Uses port numbers to identify applications. Two main protocols: TCP (reliable, connection-oriented) and UDP (unreliable, connectionless).

Layer 3 — Network Layer: Handles logical addressing (IP addresses) and routing of data across multiple networks. Determines the best path for data delivery. Key devices: routers. Protocols: IP, ICMP, ARP, OSPF, BGP.

Layer 2 — Data Link Layer: Provides reliable node-to-node data transfer. Handles framing (adding headers/trailers), physical addressing (MAC addresses), error detection (CRC), and flow control. Key devices: switches, bridges. Protocols: Ethernet (IEEE 802.3), Wi-Fi (IEEE 802.11).

Layer 1 — Physical Layer: Transmits raw bits over a physical medium. Defines electrical, mechanical, and functional specifications: voltage levels, pin layouts, cable types, connectors. Concerned with bit rate, synchronization, and transmission mode. Devices: hubs, repeaters, cables.

Data Link Layer

Framing, error control, flow control, MAC protocols, Ethernet, switching

Framing

Framing is the process of dividing a continuous stream of bits into manageable units called frames. Each frame contains: sender/receiver MAC addresses, payload (data from network layer), error detection bits (CRC), and start/end delimiters.

Framing methods include:

  • Character-oriented (BISYNC): Uses special control characters (STX, ETX) to mark frame boundaries. Vulnerable to data transparency issues.
  • Bit-oriented (HDLC): Uses a unique bit pattern (01111110) as flag. Bit stuffing prevents flag pattern from appearing in data.
  • Byte-count framing: First byte specifies the frame length. Problematic if the count byte is corrupted.

Error Detection and Correction

Error Detection:

  • Parity Check: Adds a parity bit to make total number of 1s even (even parity) or odd (odd parity). Detects single-bit errors only. Simple but limited.
  • Checksum: Sender divides data into k-bit blocks, adds them using 1's complement arithmetic, and sends the sum. Receiver verifies by recomputing. Used in TCP/UDP headers.
  • CRC (Cyclic Redundancy Check): Data is treated as a binary polynomial. Divided by a generator polynomial using modulo-2 division. The remainder (CRC) is appended to data. Receiver divides and checks if remainder is zero. Very powerful — detects all single-bit, double-bit, and odd-numbered-bit errors, and most burst errors. Used in Ethernet, Wi-Fi, USB.

Error Correction:

  • Hamming Code: Adds redundant parity bits at specific positions. Each parity bit checks a specific set of data bits. If error occurs, the combination of failed parity bits identifies the exact bit position. Can correct single-bit errors and detect double-bit errors. For n data bits, need k parity bits where 2^k >= n + k + 1.
  • ARQ (Automatic Repeat reQuest): Receiver requests retransmission of corrupted frames. Types: Stop-and-Wait ARQ, Go-Back-N ARQ, Selective Repeat ARQ.

Flow Control Protocols

Flow control prevents the sender from overwhelming the receiver:

  • Stop-and-Wait: Sender sends one frame, waits for ACK before sending the next. Simple but inefficient (low channel utilization). Channel utilization = (Transmission time) / (Transmission time + RTT).
  • Sliding Window Protocol: Sender can send multiple frames without waiting for individual ACKs. A "window" of size N allows N unacknowledged frames. Types: Go-Back-N (receiver accepts only in-order frames; sender retransmits from the error frame onward) and Selective Repeat (receiver buffers out-of-order frames; sender retransmits only the errored frame). More efficient utilization.
  • Piggybacking: Receiver appends its ACK to the next data frame it sends back, saving bandwidth.

Multiple Access Protocols

When multiple devices share a common channel, protocols are needed to coordinate access:

  • ALOHA: Pure ALOHA — stations transmit whenever they have data. Collisions possible. Slotted ALOHA — time is divided into slots; stations can only transmit at slot boundaries. Efficiency: Pure ALOHA = 18%, Slotted ALOHA = 36%.
  • CSMA/CD (Carrier Sense Multiple Access with Collision Detection): Used in wired Ethernet (half-duplex). Stations listen before transmitting (carrier sense). If collision detected, transmission stops and a jam signal is sent. Stations wait a random backoff time (binary exponential backoff) before retrying. Efficient for low-to-moderate load.
  • CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance): Used in wireless networks (Wi-Fi). Collisions are harder to detect in wireless (hidden terminal problem). Uses RTS/CTS handshake and DCF (Distributed Coordination Function). More conservative than CSMA/CD.

Ethernet and MAC Addressing

Ethernet (IEEE 802.3): The dominant LAN technology. Uses CSMA/CD in half-duplex mode and full-duplex with switches. Frame format includes: Destination MAC (6 bytes), Source MAC (6 bytes), Type/Length (2 bytes), Data (46–1500 bytes), FCS/CRC (4 bytes). Minimum frame size is 64 bytes to ensure collision detection works.

MAC Address: A 48-bit (6-byte) physical address burned into the NIC by the manufacturer. Written as six groups of 2 hex digits separated by colons (e.g., 00:1A:2B:3C:4D:5E). The first 24 bits are the OUI (Organizationally Unique Identifier) assigned by IEEE. The last 24 bits are assigned by the manufacturer. MAC addresses operate at the Data Link layer and are used for local network communication.

Switching

Store-and-Forward Switching: The switch receives the entire frame, checks the CRC/FCS for errors, then looks up the destination MAC address in its forwarding table and forwards the frame out the appropriate port. Reliable but introduces latency.

Cut-Through Switching: The switch starts forwarding the frame as soon as it reads the destination MAC address (first 6 bytes), without waiting for the entire frame. Lower latency but forwards corrupted frames. Two variants: Fragment-Free (waits for first 64 bytes to avoid collisions).

Exam Tip: CRC calculation is a common numerical question. Practice the modulo-2 division steps. CSMA/CD backoff algorithm is also frequently asked. Remember: CSMA/CD for wired Ethernet, CSMA/CA for wireless. Hamming code bit-position formula: 2^k >= n + k + 1.

5 Marks
Explain CSMA/CD protocol.

CSMA/CD (Carrier Sense Multiple Access with Collision Detection) is a medium access control protocol used in traditional half-duplex Ethernet networks.

Working:

  1. Carrier Sense: Before transmitting, a station listens to the channel. If idle, it transmits; if busy, it waits.
  2. Multiple Access: Multiple stations share the same communication channel.
  3. Collision Detection: While transmitting, the station continues to monitor the channel. If it detects a collision (signal distortion), it immediately stops transmitting and sends a jam signal to notify all stations.
  4. Backoff: The station waits for a random period using binary exponential backoff: after the i-th collision, it picks a random number from 0 to 2^i - 1 and waits that many slot times before retrying.

Advantages: Simple, efficient for light-to-moderate traffic, no central coordination needed.

Limitations: Performance degrades as network load increases (more collisions). Maximum network diameter limited by propagation delay (slot time = 512 bits = 51.2 microseconds for 10 Mbps Ethernet). Modern switched Ethernet uses full-duplex, making CSMA/CD unnecessary.

Explain data link layer design issues. Discuss error detection and correction methods with examples. Also explain sliding window protocol.

Data Link Layer Design Issues:

The data link layer is responsible for reliable node-to-node data transfer. Its key design challenges include:

  • Framing: Dividing the bit stream from the network layer into frames with clear boundaries using delimiters (flags).
  • Error Detection: Identifying corrupted frames using techniques like CRC, checksum, or parity bits.
  • Error Correction: Not just detecting but fixing errors using Hamming code or requesting retransmission (ARQ).
  • Flow Control: Preventing a fast sender from overwhelming a slow receiver.
  • Medium Access Control (MAC): Coordinating access to a shared communication channel among multiple stations.

Error Detection Methods:

1. Parity Check: Adds a single parity bit to make the count of 1s even (or odd). Detects only single-bit errors. If two bits flip, parity remains correct but data is corrupted.

2. Checksum: Sender divides data into 16-bit words, adds them using 1's complement, and sends the complement of the sum. Receiver adds all words including checksum; result should be all 1s if error-free. Used in TCP/UDP headers.

3. CRC (Cyclic Redundancy Check): Data polynomial D(x) is divided by generator polynomial G(x). The remainder R(x) becomes the CRC. Transmitted data is D(x) * x^k + R(x). Receiver divides by G(x); remainder 0 means no error. Example: CRC-32 (Ethernet uses polynomial 0x04C11DB7).

Error Correction — Hamming Code:

For data bits d₇d₆d₅d₄d₃d₂d₁ = 1011011, with 4 parity bits p₄p₃p₂p₁ at positions 1, 2, 4, 8:

  • p₁ checks bits: 1, 3, 5, 7, 9 (odd parity positions)
  • p₂ checks bits: 2, 3, 6, 7, 10
  • p₃ checks bits: 4, 5, 6, 7, 12
  • p₄ checks bits: 8, 9, 10, 11, 12

If parity checks at positions p₄ and p₂ fail, error is at position 4+2 = 6. The bit at position 6 is flipped to correct the error.

Sliding Window Protocol:

In sliding window, the sender maintains a "window" of W frames that can be sent without waiting for ACKs. Each frame has a sequence number. The "window slides" forward as ACKs arrive.

Go-Back-N ARQ: Sender can send up to N frames. If frame k is lost or damaged, the receiver discards frame k and all subsequent frames. The sender, upon timeout for frame k, retransmits frames k, k+1, k+2, ... from the error point.

Selective Repeat ARQ: Sender can send up to N frames. The receiver buffers out-of-order frames. Only the specific errored frame is retransmitted. More efficient but requires more buffer space at the receiver.

Window size constraints: For Go-Back-N, N <= 2^n - 1 (where n = sequence number bits). For Selective Repeat, N <= 2^(n-1).

Network Layer

IP addressing, subnetting, routing algorithms, protocols, network devices

IPv4 Addressing

IPv4 uses 32-bit addresses (4 bytes), represented in dotted-decimal notation (e.g., 192.168.1.1). Originally classified into five classes:

  • Class A: First bit = 0. Range: 1.0.0.0 – 126.0.0.0. Default mask: 255.0.0.0 (/8). 128 networks, 16,777,214 hosts per network.
  • Class B: First bits = 10. Range: 128.0.0.0 – 191.255.0.0. Default mask: 255.255.0.0 (/16). 16,384 networks, 65,534 hosts per network.
  • Class C: First bits = 110. Range: 192.0.0.0 – 223.255.255.0. Default mask: 255.255.255.0 (/24). 2,097,152 networks, 254 hosts per network.
  • Class D: First bits = 1110. Range: 224.0.0.0 – 239.255.255.255. Reserved for multicast.
  • Class E: First bits = 1111. Range: 240.0.0.0 – 255.255.255.255. Reserved for experimental use.

Special addresses: 127.0.0.0/8 (loopback), 0.0.0.0 (default route), 255.255.255.255 (limited broadcast).

Subnetting and CIDR

Subnetting divides a large network into smaller sub-networks (subnets). It extends the network portion of the IP address by borrowing bits from the host portion. Benefits: reduced traffic, efficient IP utilization, easier management, and improved security.

Example: Network 200.1.1.0/24 with 6 subnets. Borrow 3 bits (2^3 - 2 = 6 usable subnets). New prefix: /27. Each subnet has 2^5 - 2 = 30 usable hosts.

CIDR (Classless Inter-Domain Routing): Eliminates the rigid class boundaries. Uses a prefix notation (e.g., /24) to indicate how many bits are the network prefix. CIDR enables route aggregation (supernetting) — multiple networks can be advertised as a single route. Example: 200.1.1.0/24, 200.1.2.0/24, 200.1.3.0/24 can be aggregated as 200.1.1.0/22.

IPv6

IPv6 uses 128-bit addresses (16 bytes), written as 8 groups of 4 hex digits separated by colons (e.g., 2001:0db8:85a3::8a2e:370:7334).

  • Larger address space: 2^128 addresses vs IPv4's 2^32. Solves address exhaustion.
  • Simplified header: Fixed 40-byte header with fewer fields. Faster processing by routers.
  • Built-in security: IPsec is mandatory (optional in IPv4).
  • No broadcast: Uses multicast and anycast instead of broadcast. Reduces unnecessary traffic.
  • Auto-configuration: Stateless Address Autoconfiguration (SLAAC) allows devices to configure their own addresses.
  • Better QoS: Flow Label field in the header enables quality of service handling.

Routing Algorithms and Protocols

Distance Vector Routing: Each router maintains a routing table with (destination, next hop, distance). Routers periodically exchange their entire routing tables with neighbors. Uses Bellman-Ford algorithm. Distance = number of hops. Examples: RIP. Problems: slow convergence, count-to-infinity problem, routing loops.

Link State Routing: Each router discovers its neighbors, measures delay to each, builds a complete map of the network topology (link state database), then runs Dijkstra's shortest path algorithm to compute best paths. Examples: OSPF. Faster convergence, more scalable, but requires more memory and CPU.

Key Protocols:

  • RIP (Routing Information Protocol): Distance vector, max hop count = 15, periodic updates every 30 seconds. Simple but slow. Suitable for small networks.
  • OSPF (Open Shortest Path First): Link state, uses areas for hierarchy, fast convergence (triggered updates), supports VLSM and CIDR. Suitable for medium to large networks.
  • BGP (Border Gateway Protocol): Path vector protocol used between autonomous systems (ASes) on the Internet. Uses AS_PATH attribute to prevent loops. The "glue" of the Internet.

Network Protocols and Devices

ARP (Address Resolution Protocol): Maps an IPv4 address to a MAC address. When a host needs to send a packet, it broadcasts an ARP request: "Who has IP X.X.X.X? Tell me your MAC." The owner replies with an ARP reply containing its MAC address.

RARP (Reverse ARP): Maps a MAC address to an IP address. Used by diskless workstations to discover their IP at boot. Largely replaced by BOOTP and DHCP.

ICMP (Internet Control Message Protocol): Used for diagnostic and error reporting in IP networks. Common messages: Echo Request/Reply (ping), Destination Unreachable, Time Exceeded (traceroute), Redirect.

NAT (Network Address Translation): Translates private IP addresses to a public IP address. Allows multiple devices on a private network to share a single public IP. Types: Static NAT, Dynamic NAT, PAT (Port Address Translation / NAT Overload).

DHCP (Dynamic Host Configuration Protocol): Automatically assigns IP addresses, subnet masks, default gateways, and DNS servers to devices on a network. Process: DORA — Discover, Offer, Request, Acknowledgment.

Network Devices:

  • Hub: Layer 1 device. Broadcasts incoming signal to all ports. Creates a single collision domain.
  • Switch: Layer 2 device. Forwards frames based on MAC addresses. Creates separate collision domains per port. More efficient than hubs.
  • Router: Layer 3 device. Forwards packets between different networks based on IP addresses. Creates separate broadcast domains.
  • Gateway: Connects networks using different protocols or architectures. Often a router that also performs protocol conversion.
  • Modem: Modulates digital signals to analog for transmission over telephone lines, and demodulates analog back to digital.
Exam Tip: Subnetting numerical problems are very common. Always practice: given a network address and required subnets/hosts, find the new prefix, subnets, and usable host ranges. CIDR aggregation (supernetting) is also frequently asked. IPv6 address notation rules (compressing zeros with ::) is a common 1-mark question.
1 Mark
What is subnetting?
Subnetting is the process of dividing a large IP network into smaller sub-networks (subnets) by borrowing bits from the host portion of the IP address to create a longer network prefix. This reduces broadcast traffic, improves security, and enables more efficient IP address allocation. For example, subnetting a Class C network (192.168.1.0/24) with a /26 mask creates 4 subnets, each with 62 usable hosts.
1 Mark
Difference between IPv4 and IPv6.
IPv4 uses 32-bit addresses (4.3 billion addresses), supports broadcast, has a variable-length header (20–60 bytes), and checksum is mandatory. IPv6 uses 128-bit addresses (practically unlimited), eliminates broadcast (uses multicast instead), has a fixed 40-byte header for faster routing, IPsec is built-in, and no NAT is needed due to abundant addresses. IPv6 also supports auto-configuration and has a Flow Label for QoS.

Explain distance vector routing algorithm.

Distance Vector Routing is a dynamic routing algorithm where each router maintains a routing table containing the best known distance (metric) to every destination network and the next hop to reach it. The term "distance vector" refers to the pair (destination, distance) that each router shares with its neighbors.

Working (Bellman-Ford Equation):

Each router periodically sends its entire routing table to all directly connected neighbors. Upon receiving updates, each router applies the Bellman-Ford equation:

Dx(y) = min{ C(x,v) + Dv(y) }

Where Dx(y) = cost from x to y, C(x,v) = cost from x to neighbor v, Dv(y) = cost from v to y reported by v.

Steps:

  1. Each router initializes its table: distance = 0 for directly connected networks, infinity for others.
  2. Routers exchange routing tables periodically (e.g., every 30 seconds in RIP).
  3. Each router recalculates its table using the Bellman-Ford equation.
  4. If a better route is found, the table is updated.

Problems:

  • Count-to-infinity: When a link fails, routers may continuously increase the metric to infinity.
  • Slow convergence: It takes time for changes to propagate through the network.
  • Routing loops: Packets may loop between routers during convergence.

Example — RIP: Uses hop count as metric (max 15 hops, 16 = unreachable). Periodic updates every 30 seconds. Simple but limited to small networks.

What is CIDR? Explain with example.

CIDR (Classless Inter-Domain Routing) is a method of IP address allocation and routing that eliminates the rigid class-based addressing system (Class A/B/C). Instead of fixed prefixes, CIDR uses variable-length network prefixes, allowing efficient address allocation and route aggregation.

CIDR notation uses a slash followed by the prefix length: e.g., 192.168.1.0/24 means the first 24 bits are the network prefix.

Example 1 — VLSM (Variable Length Subnet Mask):

A company needs: Subnet A (100 hosts), Subnet B (50 hosts), Subnet C (25 hosts).

  • Subnet A: /25 (128 addresses, 126 usable) → 10.0.0.0/25
  • Subnet B: /26 (64 addresses, 62 usable) → 10.0.0.128/26
  • Subnet C: /27 (32 addresses, 30 usable) → 10.0.0.192/27

CIDR allows different prefix lengths for different subnets, saving IP addresses.

Example 2 — Route Aggregation (Supernetting):

An ISP has four Class C networks: 200.1.1.0/24, 200.1.2.0/24, 200.1.3.0/24, 200.1.4.0/24. Instead of advertising 4 routes, it can aggregate them as a single route: 200.1.0.0/22. This reduces the size of routing tables on the Internet (route aggregation).

Benefits of CIDR:

  • Efficient IP address allocation (reduces waste).
  • Route aggregation reduces routing table size.
  • Flexible subnetting based on actual needs.
  • Slowed down IPv4 address exhaustion (temporary fix).

Transport Layer

TCP, UDP, connection management, flow control, congestion control, QoS

TCP vs UDP

TCP (Transmission Control Protocol): Connection-oriented, reliable, ordered delivery. Uses three-way handshake for connection establishment. Provides flow control (sliding window), congestion control (slow start, congestion avoidance), error detection, and retransmission. Used for: web browsing (HTTP), email (SMTP), file transfer (FTP).

UDP (User Datagram Protocol): Connectionless, unreliable, no guarantee of delivery or order. Minimal overhead (8-byte header). No connection setup, no flow control, no congestion control. Used for: DNS queries, video streaming, VoIP, online gaming, DHCP.

TCP Three-Way Handshake

The three-way handshake establishes a reliable TCP connection:

  1. SYN: Client → Server: "I want to connect. My initial sequence number is X."
  2. SYN-ACK: Server → Client: "I accept. My initial sequence number is Y. I acknowledge your X+1."
  3. ACK: Client → Server: "I acknowledge your Y+1." Connection is now ESTABLISHED.

Connection termination uses a four-way handshake (FIN, ACK, FIN, ACK) since TCP is full-duplex.

Congestion Control

Congestion occurs when too many sources send data too fast for the network to handle, causing packet loss and delay. TCP uses several mechanisms:

  • Slow Start: Congestion window (cwnd) starts at 1 MSS (Maximum Segment Size). For each ACK received, cwnd increases by 1 MSS. This results in exponential growth (1, 2, 4, 8, ...) until the Slow Start Threshold (ssthresh) is reached.
  • Congestion Avoidance: Once cwnd reaches ssthresh, linear growth begins: cwnd increases by 1 MSS per RTT (not per ACK).
  • Fast Retransmit: If the sender receives 3 duplicate ACKs, it retransmits the missing segment without waiting for the timeout.
  • Fast Recovery: After fast retransmit, ssthresh is set to cwnd/2, cwnd is set to ssthresh + 3, and congestion avoidance resumes.
  • Timeout: If retransmission timer expires, ssthresh = cwnd/2, cwnd = 1, and slow start restarts.

TCP Header Format

The TCP header (minimum 20 bytes) contains:

  • Source Port (16 bits): Sender's port number.
  • Destination Port (16 bits): Receiver's port number.
  • Sequence Number (32 bits): Byte number of the first data byte in this segment.
  • Acknowledgment Number (32 bits): Next expected byte number.
  • Header Length (4 bits): Size of TCP header in 32-bit words.
  • Flags (9 bits): URG, ACK, PSH, RST, SYN, FIN.
  • Window Size (16 bits): Receive window size (flow control).
  • Checksum (16 bits): Error detection.
  • Urgent Pointer (16 bits): Points to urgent data (if URG flag set).
  • Options (variable): MSS, window scaling, selective ACK (SACK).

Flow Control vs Congestion Control

Flow Control: A local mechanism between sender and receiver to prevent the sender from overwhelming the receiver's buffer. The receiver advertises its available buffer space (rwnd — receive window) in every ACK. The sender must not send more than min(cwnd, rwnd) bytes.

Congestion Control: A global mechanism to prevent the sender from overwhelming the network. The sender maintains a congestion window (cwnd) based on network conditions. cwnd is adjusted dynamically using slow start, congestion avoidance, fast retransmit, and fast recovery algorithms.

Quality of Service (QoS)

QoS refers to the ability of a network to provide better service to certain types of traffic. Techniques include:

  • Traffic Shaping: Regulating the rate of data transmission (e.g., token bucket algorithm).
  • Leaky Bucket: Fixed-rate output, buffers excess input.
  • Token Bucket: Allows bursty traffic up to a limit while maintaining an average rate.
  • Integrated Services (IntServ): Resource reservation (RSVP protocol) for each flow.
  • Differentiated Services (DiffServ): Traffic is classified into classes; each class gets different priority treatment (DSCP field in IP header).

Port Numbers and Socket Programming

Port numbers are 16-bit identifiers (0–65535) that identify specific processes or services on a host. Categories:

  • Well-known ports (0–1023): Reserved for system services (HTTP: 80, HTTPS: 443, FTP: 21, SSH: 22, SMTP: 25, DNS: 53).
  • Registered ports (1024–49151): Used by user applications.
  • Dynamic/Private ports (49152–65535): Assigned dynamically for client connections.

Socket Programming: A socket is an endpoint for communication, identified by the combination (IP address, port number). The client-server model: the server creates a socket, binds it to a port, listens for connections, accepts, and communicates. The client creates a socket and connects to the server's IP:port.

Explain three-way handshake.

The three-way handshake is the process used by TCP to establish a reliable connection between a client and server before data transfer begins.

Step 1 — SYN: The client sends a TCP segment with the SYN (synchronize) flag set to 1 and an initial sequence number (ISN) = x. This says: "I want to connect, and my starting sequence number is x."

Step 2 — SYN-ACK: The server responds with a segment having both SYN and ACK flags set to 1. It sends its own ISN = y, and acknowledges the client's ISN by sending ACK = x + 1. This says: "I accept. My starting sequence number is y, and I received your x."

Step 3 — ACK: The client sends an acknowledgment segment with ACK = y + 1. This says: "I acknowledge your y."

After this, the connection is in the ESTABLISHED state and data transfer can begin in both directions.

Why three steps? Two steps are insufficient because of potential delayed duplicate SYN segments from a previous connection. The third ACK confirms that both sides are actively participating, preventing old duplicate connection requests from creating invalid connections.

Connection Termination: TCP uses a four-way handshake to close the connection. Each side sends a FIN (finish) segment, and the other side ACKs it. Since TCP is full-duplex, each direction is closed independently.

Explain TCP in detail. Discuss header format, connection establishment and release, flow control and congestion control mechanisms.

TCP (Transmission Control Protocol) is a reliable, connection-oriented transport layer protocol. It provides a byte-stream service with guaranteed delivery, ordering, and integrity.

TCP Header Format (minimum 20 bytes):

  • Source Port (16 bits): Port number of the sending application.
  • Destination Port (16 bits): Port number of the receiving application.
  • Sequence Number (32 bits): Byte number of the first data byte in this segment. Used for ordering and acknowledgment.
  • Acknowledgment Number (32 bits): Next expected byte number (cumulative ACK). Valid when ACK flag is set.
  • Header Length (4 bits): Size of TCP header in 32-bit words (min 5 = 20 bytes).
  • Reserved (3 bits): Reserved for future use.
  • Flags (9 bits): URG (urgent), ACK (acknowledgment), PSH (push), RST (reset), SYN (synchronize), FIN (finish).
  • Window Size (16 bits): Receive window size — number of bytes the receiver is willing to accept (flow control).
  • Checksum (16 bits): Covers TCP header, data, and a pseudo-header from IP.
  • Urgent Pointer (16 bits): Points to the last byte of urgent data when URG flag is set.
  • Options (variable): MSS, window scale factor, SACK permitted, SACK blocks, timestamps.

Connection Establishment (3-Way Handshake):

1. Client sends SYN with ISN = x.
2. Server responds with SYN-ACK with ISN = y, ACK = x+1.
3. Client sends ACK = y+1. Connection is ESTABLISHED.

Connection Release (4-Way Handshake):

Since TCP is full-duplex, each direction closes independently:
1. Side A sends FIN (I'm done sending).
2. Side B sends ACK.
3. Side B sends its own FIN (when done).
4. Side A sends ACK. After TIME_WAIT (2*MSL), the connection fully closes.

Flow Control:

Flow control prevents the sender from overwhelming the receiver. The receiver advertises its available buffer space (rwnd — receive window) in every ACK. The sender's sending rate is limited by: send_window = min(cwnd, rwnd).

Congestion Control:

1. Slow Start: cwnd starts at 1 MSS. For each ACK received, cwnd += 1 MSS. Exponential growth: 1, 2, 4, 8, 16... until cwnd >= ssthresh.

2. Congestion Avoidance: When cwnd >= ssthresh, growth becomes linear: cwnd += 1 MSS per RTT.

3. Fast Retransmit: On receiving 3 duplicate ACKs, retransmit the missing segment immediately.

4. Fast Recovery: After fast retransmit: ssthresh = cwnd/2, cwnd = ssthresh + 3, then resume congestion avoidance.

5. Timeout: If retransmission timer fires: ssthresh = cwnd/2, cwnd = 1, restart slow start.

Application Layer

Web, DNS, email, file transfer, network security, socket programming

HTTP and HTTPS

HTTP (Hypertext Transfer Protocol): The foundation of the World Wide Web. It is a request-response protocol where a client (browser) sends an HTTP request to a server, which returns an HTTP response. HTTP is stateless — each request is independent. Common methods: GET (retrieve), POST (submit data), PUT (update), DELETE (remove), HEAD (headers only).

HTTPS (HTTP Secure): HTTP over TLS/SSL. Encrypts the communication between client and server using asymmetric encryption for key exchange and symmetric encryption for data transfer. Port 443 vs HTTP's port 80. Essential for secure transactions (banking, e-commerce). The TLS handshake involves: client hello, server hello, certificate exchange, key exchange, and encrypted communication begins.

DNS (Domain Name System)

DNS is a hierarchical, distributed database that maps domain names (human-readable) to IP addresses (machine-readable). It operates over UDP port 53 (small queries) and TCP port 53 (large responses, zone transfers).

DNS Resolution Process:

  1. Browser checks its cache for the IP address.
  2. OS checks the hosts file and DNS resolver cache.
  3. Query sent to the configured DNS resolver (usually ISP's DNS server).
  4. If not cached, the resolver queries a root DNS server.
  5. Root server responds with the TLD (Top-Level Domain) server address (e.g., .com server).
  6. Resolver queries the TLD server.
  7. TLD server responds with the authoritative name server for the domain.
  8. Resolver queries the authoritative name server.
  9. Authoritative server returns the IP address.
  10. Resolver returns the IP to the client (with caching).

DNS record types: A (IPv4 address), AAAA (IPv6 address), MX (mail server), CNAME (canonical name/alias), PTR (reverse DNS), NS (name server), TXT (text record).

Email Protocols (SMTP, POP3, IMAP)

SMTP (Simple Mail Transfer Protocol): Used for sending emails from client to server and between mail servers. Push protocol. Uses TCP port 25. Command-based (HELO, MAIL FROM, RCPT TO, DATA, QUIT). Transfers mail in a series of request/response exchanges.

POP3 (Post Office Protocol v3): Used for retrieving emails from a mail server to a local client. Downloads and typically deletes emails from the server. Uses TCP port 110 (unencrypted) or 995 (SSL). Simple but limited — only one client can access the mailbox at a time.

IMAP (Internet Message Access Protocol): Used for retrieving and managing emails while keeping them on the server. Supports multiple clients accessing the same mailbox. Uses TCP port 143 (unencrypted) or 993 (SSL). More feature-rich than POP3 (folders, server-side search).

FTP and Telnet

FTP (File Transfer Protocol): Used for transferring files between client and server. Uses two connections: Control connection (TCP port 21, persistent throughout session) and Data connection (TCP port 20, established per file transfer). Commands include USER, PASS, LIST, RETR (retrieve), STOR (store), QUIT. Anonymous FTP allows public file access without authentication.

Telnet: A remote login protocol that provides a bidirectional interactive text-oriented communication facility. Uses TCP port 23. Allows a user to log into a remote host and execute commands as if sitting at that host. Telnet is unencrypted — all data including passwords is sent in plaintext. SSH (Secure Shell) has largely replaced Telnet due to security concerns.

SNMP and World Wide Web

SNMP (Simple Network Management Protocol): Used for network management and monitoring. It allows administrators to monitor network-attached devices (routers, switches, servers) for conditions that warrant attention. Uses UDP ports 161 (queries) and 162 (traps). Three components: Manager (central monitoring station), Agent (software on managed devices), and Management Information Base (MIB — database of managed objects).

World Wide Web (WWW): A system of interlinked hypertext documents accessed via the Internet. Components: Web browser (client), Web server (hosts websites), HTML (document format), URL (address format: scheme://host:port/path), and HTTP (transfer protocol).

Network Security Basics

Encryption: Converting plaintext into ciphertext using an algorithm and key. Two types:

  • Symmetric Encryption: Same key for encryption and decryption (e.g., AES, DES). Fast but key distribution is a challenge.
  • Asymmetric Encryption: Uses a public key (for encryption) and private key (for decryption). Slower but solves the key distribution problem (e.g., RSA, ECC).

Decryption: Converting ciphertext back to plaintext using the appropriate key.

Firewall: A security system that monitors and controls incoming and outgoing network traffic based on predetermined security rules. Types: Packet Filtering (checks IP/port), Stateful Inspection (tracks connection state), Application Gateway (proxy), and Next-Generation Firewall (deep packet inspection + intrusion prevention).

Other security concepts: Digital signatures (authentication + non-repudiation), Digital certificates (issued by Certificate Authorities), SSL/TLS (secure communication), VPN (secure tunneling), and Malware (viruses, worms, trojans, ransomware).

Network security terms (encryption types, firewall types) are easy 1-mark questions. Remember: HTTP is stateless (cookies/sessions needed), HTTPS adds TLS encryption.

Explain DNS in detail.

DNS (Domain Name System) is a distributed, hierarchical database that maps domain names to IP addresses, making the Internet usable for humans.

DNS Hierarchy:

  • Root DNS Servers: 13 logical root servers (actually hundreds of physical instances). Know the addresses of all TLD servers.
  • TLD Servers: Manage top-level domains (.com, .org, .net, .in, .edu, country codes).
  • Authoritative DNS Servers: Store actual DNS records for specific domains. Every organization must have one.
  • Local DNS Servers (Resolvers): ISP-provided or organizational DNS caches. First point of contact for DNS queries.

DNS Resolution Steps:

  1. Client sends query to local DNS resolver.
  2. If not cached, resolver queries a root server → gets TLD server address.
  3. Resolver queries TLD server → gets authoritative server address.
  4. Resolver queries authoritative server → gets the actual IP address.
  5. Resolver returns IP to client and caches the result.

DNS Record Types:

  • A Record: Maps domain name to IPv4 address.
  • AAAA Record: Maps domain name to IPv6 address.
  • MX Record: Specifies the mail server for a domain.
  • CNAME Record: Creates an alias for another domain name.
  • PTR Record: Maps IP address to domain name (reverse DNS).
  • NS Record: Specifies the name server for a domain.

DNS uses UDP port 53 for normal queries (fast, low overhead). TCP port 53 is used for large responses (>512 bytes) and zone transfers. DNS caching at multiple levels (browser, OS, local DNS) reduces query latency and load on authoritative servers.

Explain application layer protocols (HTTP, DNS, SMTP, FTP) in detail. Discuss how a URL is resolved to an IP using DNS.

1. HTTP (Hypertext Transfer Protocol):

HTTP is the core protocol of the World Wide Web. It defines how messages are formatted and transmitted, and how web servers and browsers respond to commands. Key characteristics:

  • Stateless: Each request is independent. Server doesn't remember previous requests. State is maintained via cookies, sessions, or tokens.
  • Request Methods: GET (retrieve), POST (submit form data), PUT (update resource), DELETE (remove), HEAD (headers only), OPTIONS (allowed methods).
  • Status Codes: 1xx (informational), 2xx (success: 200 OK), 3xx (redirect: 301 Moved), 4xx (client error: 404 Not Found), 5xx (server error: 500 Internal Error).
  • Versions: HTTP/1.0 (separate connection per request), HTTP/1.1 (persistent connections, pipelining), HTTP/2 (multiplexing, binary framing, header compression), HTTP/3 (QUIC over UDP).

2. DNS (Domain Name System):

DNS translates domain names to IP addresses. The complete resolution process:

  1. User types "www.google.com" in the browser.
  2. Browser checks its own DNS cache.
  3. OS checks its DNS resolver cache and hosts file.
  4. Query is sent to the local DNS resolver (configured in network settings).
  5. If the resolver doesn't have the answer cached, it sends a query to one of the 13 root DNS servers (logical, physically replicated globally).
  6. Root server responds with the address of the .com TLD server.
  7. Resolver queries the .com TLD server.
  8. TLD server responds with the address of google.com's authoritative DNS server.
  9. Resolver queries google.com's authoritative DNS server.
  10. Authoritative server returns the IP address (e.g., 142.250.80.46).
  11. Resolver returns the IP to the client and caches it (typically for TTL duration).
  12. Browser now connects to the server using the IP address.

3. SMTP (Simple Mail Transfer Protocol):

SMTP is used for sending emails. It operates over TCP port 25. The mail sending process:

  • Sender's mail client connects to the sender's mail server (MUA → MSA).
  • Sender's mail server uses SMTP to connect to the recipient's mail server (MTA → MTA).
  • Email is stored in the recipient's mail server (MDA).
  • Recipient uses POP3 or IMAP to retrieve the email from the mail server (MUA ← MDA).

SMTP commands: EHLO (extended hello), MAIL FROM, RCPT TO, DATA (email content), QUIT. Responses are 3-digit codes (250 = OK, 550 = mailbox unavailable).

4. FTP (File Transfer Protocol):

FTP transfers files between client and server using two connections:

  • Control Connection (Port 21): Persistent throughout the session. Used for sending commands (USER, PASS, LIST, RETR, STOR, QUIT).
  • Data Connection (Port 20): Created for each file transfer. Closes after the transfer.

Two modes: Active mode (server connects back to client for data) and Passive mode (client initiates both connections — preferred for firewall compatibility).

Other Application Layer Protocols:

  • POP3 (Port 110/995): Downloads emails to client, typically deletes from server.
  • IMAP (Port 143/993): Keeps emails on server, allows multiple clients.
  • SSH (Port 22): Secure remote login and command execution.
  • SNMP (Port 161/162): Network device monitoring and management.
