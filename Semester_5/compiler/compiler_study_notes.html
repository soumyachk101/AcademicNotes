Introduction & Lexical Analysis

Compiler structure · Lexical analysis · Regular expressions · Finite automata · Lex tool

💡

Exam Tip: Module 1 is foundational. Questions on compiler phases, lexical analyzer role, regular expressions, NFA/DFA, and Thompson's construction appear every year. Draw diagrams for NFA/DFA — they carry marks in 5M and 15M questions.

1M
1M Define: token, pattern, and lexeme.
  • Lexeme: A character sequence forming a syntactic unit (e.g., "sum", "+", "123").
  • Token: A pair: token name + optional attribute value (e.g., <id, pointer>).
  • Pattern: Rule describing the set of lexemes for a token (usually a regular expression).
1M What are the three groups of compiler phases?
  • Front End: Lexical, syntax, semantic analysis, IR generation — language-dependent, machine-independent.
  • Middle End: Optimization on IR — machine-independent.
  • Back End: Target code generation — machine-dependent.
1M What is the role of a lexical analyzer?

The lexical analyzer (scanner) is the first compiler phase. It reads the source program character by character, groups characters into tokens (lexemes), removes whitespace/comments, reports lexical errors, and creates symbol table entries for identifiers.

1M What is a sentinel in input buffering?

A sentinel is a special character (e.g., EOF marker) placed at the end of the input buffer. It eliminates the need for a boundary check at every character, because the scanner only needs to check whether it has hit the sentinel to know it must reload the buffer.

1M Name the tool used for generating a lexical analyzer.

Lex (Unix) or Flex (Fast Lexical Analyzer Generator). The programmer specifies token patterns as regular expressions; the tool generates C code for the scanner.

1M What are regular expressions? Give examples.

Regular expressions are algebraic notations used to describe patterns of character sequences (languages of tokens). Examples: [a-zA-Z][a-zA-Z0-9]* for identifiers, [0-9]+ for integers, [a-zA-Z][a-zA-Z0-9_]* for keywords.

1M What is a symbol table?

A symbol table is a data structure maintained throughout all compiler phases. It stores information about identifiers — name, type, scope, storage location, and other attributes. It supports operations like insert, lookup, and delete.

1M What is a finite automaton (FA)?

A finite automaton is a mathematical model with a finite set of states, input alphabet, transition function, start state, and accept states. It accepts a string if processing it ends in an accept state. FA is the theoretical foundation of lexical analyzers.

1M What is the difference between NFA and DFA?

NFA: Can have multiple transitions on the same input and epsilon (ε) transitions. DFA: Exactly one transition per input symbol from any state, no ε-transitions. Every DFA is an NFA, but not vice versa.

1M What is ε-closure in NFA-to-DFA conversion?

The ε-closure of a state is the set of all states reachable from it via zero or more ε-transitions. It is used in the subset construction algorithm to convert an NFA to a DFA.

1M What is peephole optimization? PYQ

Peephole optimization examines a small window ("peephole") of target instructions and replaces them with equivalent but faster/shorter sequences. Applied after code generation. Examples: removing redundant push/pop, strength reduction (y*2 → y<<1).

5M
5M Explain the phases of a compiler with a brief description of each. PYQ

1. Lexical Analysis: Reads source characters, groups into tokens, removes whitespace/comments. Output: token stream.

2. Syntax Analysis: Checks grammar using a CFG, builds a parse tree. Output: parse tree.

3. Semantic Analysis: Type checking, scope resolution. Uses SDD to traverse the parse tree.

4. Intermediate Code Generation: Produces platform-independent IR (e.g., three-address code).

5. Code Optimization: Improves IR for efficiency — constant folding, CSE, dead code elimination, loop optimization.

6. Code Generation: Translates optimized IR to target machine code. Handles register allocation and instruction selection.

5M Describe input buffering and the sentinel technique in lexical analysis.

The input is read in large chunks into a buffer (two halves: BUFFER1 and BUFFER2). Two pointers — lexemeBegin and forward — advance through the buffer. A sentinel (special EOF character) is appended at the end of each buffer half. This eliminates the boundary check per character — the scanner simply checks if forward has hit the sentinel.

5M Explain Thompson's construction for converting a regular expression to an NFA. PYQ

Thompson's construction builds an NFA from a regular expression recursively:

  • For symbol a: two states with a transition on a.
  • For r | s: new start with ε-transitions to both NFA roots.
  • For rs: ε-transition from r's accept to s's start.
  • For r*: new start with ε to first state of r and ε to accept; loop back from accept state to first state of r.
  • For r+ (one or more): like r* but requires at least one occurrence.
  • For r? (zero or one): ε-transition to both r and the accept state.
5M What is constant folding and constant propagation?

Constant Folding: Evaluating constant expressions at compile time. Example: 3 + 5 replaced with 8. Constant Propagation: Replacing a variable that always holds the same constant value with that constant. Example: if x = 5 and x is never modified, replace all uses of x with 5.

5M What is common subexpression elimination (CSE)?

CSE replaces multiple evaluations of the same expression with a single computation that stores the result in a temporary variable. Example: if a = b + c appears twice, compute once and reuse. CSE can be local (within a basic block) or global (across basic blocks).

5M Describe input buffering with the two-buffer scheme and sentinel technique. PYQ

Input is read in chunks into two buffers. lexemeBegin marks the start of the current lexeme and forward scans forward to find the end. Both buffers end with a sentinel (EOF character) so the scanner can detect the end of a buffer without an explicit boundary check on every character. When the sentinel is reached, the next half-buffer is loaded.

15M
15M Discuss the various phases of a compiler in detail with a neat diagram. PYQ

A compiler has 6 phases organized as a linear pipeline:

1. Lexical Analysis: Reads source code character-by-character, groups them into tokens (lexemes), removes whitespace/comments, reports lexical errors, and populates the symbol table. Tools: Lex/Flex.

2. Syntax Analysis (Parsing): Takes the token stream and checks if it conforms to the grammar of the language. Builds a parse tree / syntax tree. Uses a context-free grammar (CFG). Output: parse tree.

3. Semantic Analysis: Checks the meaning of the construct — type checking, scope resolution, ensuring operands have compatible types. Uses syntax-directed translation (SDT) / syntax-directed definitions (SDD) to decorate the parse tree. Output: decorated syntax tree.

4. Intermediate Code Generation: Translates the decorated syntax tree into a platform-independent intermediate representation. Three-address code (TAC) is the most common IR. Other forms: DAG, P-code, quadruples.

5. Code Optimization: Improves the IR for efficiency. Techniques: constant folding, constant propagation, CSE, dead code elimination, loop optimization, peephole optimization.

6. Code Generation: Translates the optimized IR into target machine code. Handles register allocation and instruction selection. Produces the final relocatable machine code.

[Lexical Analyzer] → Token Stream + Symbol Table
    ↓
[Syntax Analyzer] → Parse Tree
    ↓
[Semantic Analyzer] → Decorated Syntax Tree
    ↓
[IR Generator] → Intermediate Code (3AC)

15M Explain regular expressions, finite automata, and their role in lexical analysis. Also discuss the conversion from regular expression to NFA using Thompson's construction. PYQ

Regular Expressions: Algebraic notations for describing token patterns. Operators: union (|), concatenation, closure (*), plus (+), optional (?). Example: [a-z][a-z0-9]* matches identifiers.

Finite Automata (FA): A 5-tuple (Q, Σ, δ, q₀, F) — set of states, alphabet, transition function, start state, accept states. FA recognizes patterns. Two types:

  • NFA: Multiple transitions per symbol, ε-transitions allowed.
  • DFA: Exactly one transition per symbol, no ε-transitions.

Thompson's Construction: Recursively builds an NFA from a regex:
• a → 2 states, transition on a
• r|s → new start, ε to both roots
• rs → ε from r's accept to s's start
• r* → loop with ε-transitions
• r+ → like r* but must consume at least one
• r? → ε to r and ε to accept

The resulting NFA is then converted to DFA via subset construction using ε-closure, and the DFA is minimized.

Syntax Analysis (Parsing)

Context-free grammar · Top-down parsing · LL(1) · Bottom-up parsing · SLR, CLR, LALR

💡

Exam Tip: Parsing is the most important module for exams. LL(1) parsing table construction and SLR/CLR/LALR parse table questions are asked every year. Practice constructing FIRST, FOLLOW, and parsing tables from given grammars.

1M
1M What is a context-free grammar (CFG)?

A CFG is a 4-tuple G = (V, T, P, S) where V is the set of variables (non-terminals), T is the set of terminals, P is the set of productions, and S is the start symbol. CFGs can express nested, recursive constructs that regular expressions cannot.

1M What is a parse tree?

A parse tree is a tree-structured representation of how a string is derived from a grammar. Interior nodes are non-terminals, leaves are terminals or ε. The root is the start symbol. It shows the hierarchical syntactic structure.

1M What is left recursion? How do you eliminate it?

A production A → Aα has left recursion. It causes immediate left-recursion in top-down parsers. Eliminate by rewriting:
A → Aα₁ | Aα₂ | ... | Aβ₁ | Aβ₂ | ... | γ
becomes:
A → β₁A' | β₂A' | ... ; A' → α₁A' | α₂A' | ... | ε

1M What is left factoring?

Left factoring rewrites productions with common prefixes to make them suitable for top-down parsing. For A → αβ | αγ, rewrite as A → αA' ; A' → β | γ.

1M What is FIRST and FOLLOW in parsing? PYQ

FIRST(α): Set of terminals that can begin strings derived from α. If α ⇒ ε, then ε ∈ FIRST(α).

FOLLOW(A): Set of terminals that can appear immediately to the right of A in some sentential form. If A is the start symbol, $ ∈ FOLLOW(A).

1M What is the difference between top-down and bottom-up parsing?

Top-down: Starts from the start symbol, expands productions to match the input string (leftmost derivation). Examples: Recursive Descent, LL(1). Bottom-up: Starts from the input string, reduces to the start symbol (rightmost derivation in reverse). Examples: SLR, CLR, LALR, LR.

5M
5M What is an LL(1) parser? How do you construct an LL(1) parsing table? PYQ

LL(1) means: L = left-to-right scan, L = leftmost derivation, (1) = 1 token lookahead. An LL(1) parser uses a parsing table M[A, a] which gives the production to apply when non-terminal A is at the top of the stack and the next input token is a.

Construction steps:

  1. Eliminate left recursion from the grammar.
  2. Left factor the grammar.
  3. Compute FIRST and FOLLOW for all non-terminals.
  4. For each production A → α:
    • For each terminal a in FIRST(α), add A → α to M[A, a].
    • If ε ∈ FIRST(α), for each terminal b in FOLLOW(A), add A → α to M[A, b].
    • If ε ∈ FIRST(α) and $ ∈ FOLLOW(A), add A → α to M[A, $].

The grammar is LL(1) iff no table entry has more than one production.

5M Explain the concept of a shift-reduce parser. What are handle pruning and viable prefixes? PYQ

Shift-reduce parsing is a bottom-up parsing technique. It performs four actions:

  • Shift: Move the next input token onto the stack.
  • Reduce: Apply a production in reverse (reduce RHS to LHS on the stack).
  • Accept: Input is successfully parsed.
  • Error: Unrecoverable syntax error found.

A handle is a substring that matches the RHS of a production and whose reduction represents one step of a rightmost derivation. Handle pruning is the process of identifying and reducing handles in a rightmost derivation.

A viable prefix is a prefix of a right-sentential form that does not extend past the rightmost handle. The set of viable prefixes is a regular language and can be recognized by an LR parser's stack.

5M What is operator precedence parsing?

Operator precedence parsing is a simple bottom-up parsing technique for expression grammars. It uses three precedence relations between terminal pairs: < (lower precedence), = (equal precedence), > (higher precedence). The parser uses a stack and a precedence table to decide when to shift or reduce. It cannot handle ambiguous grammars with adjacent non-terminals.

5M What is LALR parsing? How does it differ from CLR parsing? PYQ

CLR (Canonical LR): Uses canonical LR(1) items (production + 1 lookahead token). Constructs the full set of LR(1) states. Produces the largest and most precise parse tables but is very large.

LALR (Look-Ahead LR): Merges CLR states with the same LR(0) core but different lookahead sets. This produces smaller tables than CLR while detecting more errors than SLR. The construction: build the LR(1) states, merge those with identical cores, then construct the parse table.

Key difference: CLR has distinct entries for different lookahead sets; LALR merges them, so fewer states but may have reduce-reduce conflicts.

5M Explain recursive descent parsing.

Recursive descent parsing is a top-down technique where each non-terminal is implemented as a function. The parser reads tokens from the input and uses recursive function calls to match productions. It requires the grammar to be free of left recursion and to be left-factored. If a choice is ambiguous, a backtracking recursive descent parser can try alternatives, but standard predictive parsers use only FIRST/FOLLOW to choose.

15M Explain SLR, CLR, and LALR parsers in detail. Compare them. PYQ

SLR (Simple LR):

  • Uses LR(0) items (production dot + no lookahead).
  • FOLLOW of LHS is used to decide reduce actions.
  • Smallest tables, but may have false reduce-reduce conflicts.
  • May reject some valid grammars that CLR/LALR can handle.

CLR (Canonical LR):

  • Uses LR(1) items (production dot + 1 lookahead token).
  • Most powerful — handles the widest class of grammars.
  • Largest tables (most states).
  • No spurious conflicts.

LALR (Look-Ahead LR):

  • Merges CLR states with the same LR(0) core.
  • Table size ≈ SLR size but more powerful.
  • May have reduce-reduce conflicts (rare with well-designed grammars).
  • Most commonly used in practice (Yacc/Bison use LALR).

15M What is an LR parser? Describe the LR parsing algorithm and the construction of SLR parse tables. PYQ

LR Parser: A bottom-up parser that reads input Left-to-right and constructs a Rightmost derivation (in reverse). It uses a stack of states and a parsing table with ACTION and GOTO sub-tables.

Algorithm:

  1. Initialize stack with state s₀ and input buffer with the string + $.
  2. Let s = top of stack, a = next input token.
  3. Consult ACTION[s, a]:
    • shift s': push a, then s' onto stack.
    • reduce A → β: pop 2×|β| symbols, push goto[s, A].
    • accept: parsing successful.
    • error: syntax error.

SLR Table Construction:

  1. Augment grammar: add S' → S.
  2. Construct LR(0) items (states).
  3. Build DFA on LR(0) items (states = item sets).
  4. For each state i and terminal a: if item [A → α·aβ] in Iᵢ and goto(Iᵢ, a) = Iⱼ, set ACTION[i,a] = shift j.
  5. For each state i and item [A → α·] in Iᵢ: for each a in FOLLOW(A), set ACTION[i,a] = reduce A → α. If A = S', set ACTION[i,$] = accept.
  6. GOTO[i, A] = j where goto(Iᵢ, A) = Iⱼ.
15M What is syntax-directed translation? Explain synthesized and inherited attributes with examples. PYQ

Syntax-Directed Translation (SDT): Associates semantic rules with grammar productions. These rules compute attribute values as the parse tree is traversed. A syntax-directed definition (SDD) specifies semantic rules for each production.

Synthesized Attributes: Values computed from children's attribute values (bottom-up). Example: in a expression E → E₁ + T, the value of E is synthesized from E₁.val and T.val.

Inherited Attributes: Values passed down from parent or siblings (top-down). Example: in D → T L, the type from T is inherited by L (the identifier list) to check all identifiers have that type.

Example: Type checking with inherited attributes
D → T L          { L.inh = T.type }
T → int          { T.type = integer }
T → real         { T.type = real }
L → id           { addType(id.entry, L.inh) }
L → L₁, id       { L.inh = L₁.inh; addType(id.entry, L.inh) }

⚡ Quick Revision

  • LL(1): Top-down, predictive, uses stack + parsing table
  • FIRST(α): Set of terminals α can begin with
  • FOLLOW(A): Set of terminals that can follow A
  • LR parsers: Bottom-up, shift-reduce, handle pruning
  • SLR < LALR < CLR in power; CLR has largest tables

Semantic Analysis & Intermediate Code

Syntax-directed definitions · Three-address code · Quadruples & triples · Type checking

💡

Exam Tip: SDD/ SDT questions are common in 5M. Three-address code generation from an SDD is a standard 15M question. Practice converting infix expressions to TAC using SDD rules.

1M
1M What is semantic analysis?

Semantic analysis is the third compiler phase. It checks the meaning of the source program — type checking, scope resolution, ensuring operands have compatible types, and verifying that declarations exist before use. It uses syntax-directed definitions (SDD) to traverse the parse tree.

1M What is three-address code (TAC)?

Three-address code is an intermediate representation where each instruction has at most one operator. Format: A = B op C. Examples: t1 = a + b, t2 = t1 * c, a = t2. It simplifies code generation by breaking complex expressions into simple atomic operations.

1M What is a quadruple?

A quadruple is a 4-tuple representation of a TAC instruction: (op, arg1, arg2, result). For example, (+, a, b, t1) represents t1 = a + b. Quadruples are stored in an array and can be reordered easily for optimization.

1M What is a triple?

A triple is a 3-tuple (op, arg1, arg2) where positions refer to instruction numbers rather than temporary variable names. This avoids the need for a result field. Triples are used when doing code optimization because reordering doesn't require updating temporary name references.

1M What is an indirect triple?

An indirect triple uses an array of pointers to triples. It allows instructions to be reordered more easily than direct triples because you simply reorder the pointer array rather than the triples themselves. Useful for optimization phases.

1M What is a syntax-directed definition (SDD)?

An SDD is a CFG augmented with semantic rules and/or actions. Each production has associated semantic rules that compute attribute values. Attributes can be synthesized (computed bottom-up) or inherited (passed top-down). SDDs are used to implement semantic analysis and IR generation.

5M
5M Explain synthesized and inherited attributes with examples. PYQ

Synthesized Attributes: Computed from the children's attribute values, flowing bottom-up the parse tree.

E → E₁ + T    { E.val = E₁.val + T.val }
T → num        { T.val = num.value }

Here, E.val is synthesized from E₁.val and T.val.

Inherited Attributes: Passed down from parent or siblings, flowing top-down.

D → T L        { L.inh = T.type }
T → int         { T.type = 'integer' }
L → id          { addType(id, L.inh) }
L → L₁, id      { L.inh = L₁.inh; addType(id, L.inh) }

Here, L.inh inherits the type from T.type, passing it down the identifier list.

5M Generate three-address code for the expression: a = b * (-c) + b * (-c) using SDD. PYQ

Using the SDD for expressions:

Grammar & SDD:
E → E₁ + T     { E.code = E₁.code || T.code || gen('add', E₁.place, T.place, E.place) }
E → T          { E.code = T.code; E.place = T.place }
T → ( E )      { T.code = E.code; T.place = E.place }
T → id         { T.code = ''; T.place = id.name }
T → - T₁       { T.code = T₁.code || gen('uminus', T₁.place, '-', T.place) }

Generated TAC:

t1 = uminus c
t2 = b * t1
t3 = uminus c
t4 = b * t3
a  = t2 + t4

After CSE optimization: t1 = uminus c; t2 = b * t1; a = t2 + t2

5M What are the different types of intermediate code representations?

1. Three-Address Code (TAC): x = y op z — most common, easy to generate and optimize.

2. Quadruples: (op, arg1, arg2, result) — fixed 4-field structure.

3. Triples: (op, arg1, arg2) — uses instruction positions, not temp names.

4. Indirect Triples: Array of pointers to triples for easy reordering.

5. Postfix (Polish) Notation: op arg1 arg2 — stack-based, easy to evaluate.

6. Abstract Syntax Tree (AST): Tree representation where interior nodes are operators and leaves are operands.

7. DAG (Directed Acyclic Graph): Like AST but shares common subexpression nodes.

15M
15M Explain syntax-directed translation (SDT). Generate three-address code for a given expression using SDD. PYQ

SDT is the implementation of an SDD — it associates semantic actions with grammar productions. These actions generate intermediate code, perform type checking, or build symbol table entries.

SDD for expressions:

E → E₁ + T     { E.place = newTemp();
                    gen(E.place, '=', E₁.place, '+', T.place) }
E → E₁ - T     { E.place = newTemp();
                    gen(E.place, '=', E₁.place, '-', T.place) }
E → T          { E.place = T.place }
T → ( E )      { T.place = E.place }
T → id         { T.place = id.place }

Example: For input a = b + c * d, TAC generated:

t1 = c * d
t2 = b + t1
a  = t2

The SDD rules are applied during a depth-first traversal of the parse tree (S-attributed: all synthesized attributes; L-attributed: synthesized + inherited along parse tree edges).

Three-Address Code (TAC): Each instruction does one operation and stores the result. Example: t1 = a + b; t2 = t1 * c; d = t2.

15M What is type checking in semantic analysis? Explain type expressions and type equivalence. PYQ

Type Checking: Verifies that operands in an expression have compatible types. Done during semantic analysis using an SDD that propagates type information up the parse tree.

Type Expressions: Recursively defined:
• Basic types: integer, real, boolean, char
• Array type: array(type, lower, upper)
• Record type: record(name₁: type₁, name₂: type₂, ...)
• Function type: (type₁, type₂, ...) → return_type
• Pointer type: ↑type

Type Equivalence:

Name equivalence: Two types are equivalent if they have the same type name. Strict and unambiguous.

Structural equivalence: Two types are equivalent if they have the same structure (same components with equivalent types). More flexible.

Type Conversion: If operands are not equivalent, the compiler may insert type conversion operators. Example: int + float → convert int to float first.

Code Optimization

Optimization basics · Peephole optimization · Data flow analysis · Loops · DAGs

💡

Exam Tip: Optimization is a favorite for 15M questions. Draw DAGs for expression optimization. Questions on constant folding, CSE, loop optimization, and peephole optimization appear very frequently.

1M
1M What is code optimization?

Code optimization is the process of improving the intermediate code so that it runs faster or uses less space, without changing the output of the program. It is machine-independent and performed on the IR. Types: local (within a basic block), global (across basic blocks), loop optimization, peephole optimization.

1M What is a basic block?

A basic block is a sequence of consecutive statements where control enters at the beginning and leaves at the end without any jumps or branching (except at the end). Basic blocks are the fundamental units for optimization and data flow analysis.

1M What is a leader in basic block construction?

A leader is the first statement of a basic block. A statement is a leader if: (1) It is the first statement of the program, (2) It is the target of a conditional or unconditional goto, or (3) It immediately follows a conditional or unconditional goto.

1M What is peephole optimization? PYQ

Peephole optimization examines a small window ("peephole") of target instructions and replaces them with equivalent but faster/shorter sequences. Applied after code generation. Examples: removing redundant push/pop, strength reduction (y*2 → y<<1).

1M What is dead code elimination?

Dead code elimination removes code that computes values that are never used. A statement is dead if its result is never used and it has no side effects. Example: x = 5; y = 10; where x is never read — the first assignment is dead.

1M What is loop optimization?

Loop optimization targets loops since they consume most execution time. Techniques include: loop invariant code motion (moving invariant computations outside the loop), induction variable elimination, strength reduction (replacing expensive ops with cheaper ones), and loop unrolling.

1M What is DAG in code optimization?

A DAG (Directed Acyclic Graph) represents expressions where common subexpressions share nodes. Leaves are identifiers/constants, interior nodes are operators. A DAG identifies common subexpressions and eliminates them. It also supports constant folding.

5M
5M What is constant folding and constant propagation?

Constant Folding: Evaluating constant expressions at compile time. Example: 3 + 5 replaced with 8. Constant Propagation: Replacing a variable that always holds the same constant value with that constant. Example: if x = 5 and x is never modified, replace all uses of x with 5.

5M What is common subexpression elimination (CSE)?

CSE replaces multiple evaluations of the same expression with a single computation that stores the result in a temporary variable. Example: if a = b + c appears twice, compute once and reuse. CSE can be local (within a basic block) or global (across basic blocks).

5M Construct a DAG for a given sequence of statements and show optimized code. PYQ

Example statements:

(1) a = b + c
(2) b = a - d
(3) c = b + c
(4) e = b + c
(5) a = e + d

DAG construction:

  • Node 1: + with children b, c → labeled a
  • Node 2: - with children Node 1, d → labeled b
  • Node 3: + with children Node 2, c → labeled c (b + c, new value)
  • Node 4: + with children Node 2, c → labeled e (same as Node 3 — common subexpression!)
  • Node 5: + with children Node 4, d → labeled a

Optimized code:

t1 = b + c
t2 = t1 - d
t3 = t2 + c     -- used by both c and e
a  = t3 + d
5M Explain loop optimization techniques: loop invariant code motion and induction variable elimination. PYQ

Loop Invariant Code Motion: Statements whose values don't change within a loop are moved outside the loop body, so they're computed only once instead of on every iteration.

for i = 1 to 100:
    x = a * b + c    -- a, b, c don't change in loop
    arr[i] = x

After optimization:
t = a * b + c       -- moved outside loop
for i = 1 to 100:
    arr[i] = t

Induction Variable Elimination: Variables that change by a constant amount each iteration can be replaced. If j = 4*i where i increments by 1, replace uses of j with 4*i and eliminate j.

5M What is copy propagation and dead code elimination?

Copy Propagation: Replaces uses of a variable with the value it was copied from. If a = b, replace all subsequent uses of a with b.

Before: a = b + c; x = a * d
After:  x = (b + c) * d   -- may reveal more optimization

Dead Code Elimination: Removes unreachable or unused code. Example: after constant propagation reveals x = 5 but x is never used — remove the assignment.

15M
15M Explain peephole optimization. List and describe various peephole optimization techniques with examples. PYQ

Peephole Optimization: Examines a small sliding window ("peephole") of target instructions and replaces patterns with more efficient equivalents. Applied after code generation.

Techniques:

  1. Redundant instruction elimination: Remove unnecessary instructions.
    e.g., MOV R0, R0 → removed
  2. Unreachable code elimination: Remove code after an unconditional jump.
    e.g., JMP L2; MOV R0, 5; L2: MOV R1, 6 → remove MOV R0,5
  3. Algebraic simplifications: Replace with simpler equivalent.
    e.g., x = x + 0 → removed; x = x * 1 → removed
  4. Strength reduction: Replace expensive ops with cheaper ones.
    e.g., x * 2 → x << 1; x / 4 → x >> 2
  5. Eliminating jump to jump:
    e.g., JMP L1; L1: JMP L2 → JMP L2
  6. Eliminating stack operations:
    e.g., PUSH R1; POP R1 → removed
  7. Procedure call reduction:
    e.g., CALL p; RET → JMP p
15M Explain DAG-based code optimization. How does a DAG help in common subexpression elimination and dead code elimination? PYQ

DAG (Directed Acyclic Graph): Each node represents a computation (operator), and leaves represent identifiers or constants. Nodes are shared when they represent the same computation (common subexpression).

Construction algorithm:

  1. For each statement, check if an identical node already exists.
  2. If found, reuse it (CSE).
  3. If the node's computed value is no longer needed, mark it as dead.

Example:

Statements:
a = b + c
b = a - d
c = b + c     -- b+c is same as original, so reuse node
e = b + c     -- same computation, reuse node again
a = e + d

DAG:

   (+) ← b, c → labeled a
      |
   (-) ← (+), d → labeled b, e
      |
   (+) ← (-), c → labeled c
      |
   (+) ← (+), d → labeled a (new)

Nodes for b+c are shared — that's CSE. If a computed value is never used, its node can be removed — that's dead code elimination.

15M Explain data flow analysis. Describe reaching definitions, live variable analysis, and available expressions analysis. PYQ

Data Flow Analysis: A framework for collecting information about how data flows through a program. It analyzes the flow of data across basic blocks.

Reaching Definitions: A definition d (assignment) reaches point p if there is a path from d to p where d is not killed (redefined) along the path. Used for constant propagation and dead code elimination.

Live Variable Analysis: A variable x is live at point p if its value at p may be used before being redefined. Used for register allocation (dead variable elimination).

Available Expressions: An expression x op y is available at point p if on every path from the entry to p, the expression has been computed and neither x nor y has been redefined since. Used for common subexpression elimination.

All use iterative algorithms with IN/OUT sets propagated along the control flow graph until convergence.

Code Generation

Code generation issues · Register allocation · Target machine · DAG-based generation · Peephole

💡

Exam Tip: Register allocation (graph coloring) is a guaranteed 5M or 15M question. Code generation from TAC using a descriptor-based approach is also frequently tested. Know the different addressing modes well.

1M
1M What is code generation in a compiler?

Code generation is the final compiler phase that translates the optimized intermediate representation into the target machine's instruction set. It must handle instruction selection, register allocation, and instruction ordering while ensuring correctness and efficiency.

1M What is register allocation?

Register allocation assigns program variables to CPU registers (limited resource). The goal is to keep frequently used variables in registers, minimizing memory accesses. Graph coloring is a popular technique: build an interference graph, color with k colors (k = available registers).

1M What is an activation record (AR)?

An activation record (AR or stack frame) is a block of memory allocated on the call stack when a function is called. It contains: return address, dynamic link (pointer to caller's AR), parameters, local variables, saved registers, and return value. Size determined by ARD (activation record descriptor).

1M What are the different addressing modes?

Immediate: Operand is in the instruction itself. Register: Operand is in a register. Direct/Absolute: Address of operand is in instruction. Indirect: Instruction gives address of memory location containing operand address. Register Indirect: Register contains address of operand. Displacement/Indexed: Base + displacement, e.g., base(reg) or indexed addressing.

1M What is a descriptor in code generation?

A descriptor tracks information about variables. A address descriptor tells where the current value of a name is (register, memory address, or both). A register descriptor tracks which variable is currently stored in a given register. These are used to make optimal code generation decisions for TAC instructions.

1M What is a register descriptor? PYQ

A register descriptor tracks, for each register, which variable name currently has its value in that register (if any). When generating code for an instruction x = y op z, the descriptor tells whether y and z are already in registers, avoiding unnecessary load instructions.

5M
5M What issues must a code generator handle when generating target code from three-address code? PYQ

1. Input format: TAC in a linear representation (quadruples/triples).

2. Instruction selection: Choosing target machine instructions for TAC ops. Straightforward but must consider addressing modes.

3. Register allocation: Deciding which variables stay in registers and which go to memory. Graph coloring or heuristic approaches.

4. Ordering of evaluation: Order of evaluating operands affects register pressure.

5. Descriptor management: Maintaining address and register descriptors to generate optimal loads/stores.

6. Control flow: Proper handling of jumps, conditionals, and procedure calls.

7. Procedure calls/returns: Parameter passing, saving/restoring registers, managing AR.

5M Explain register allocation using graph coloring. PYQ

Graph coloring approach:

  1. Build an interference graph: each node is a variable; an edge exists between two nodes if their live ranges overlap (they are simultaneously live).
  2. Simplify: repeatedly remove a node with fewer than k neighbors (k = available registers).
  3. If all nodes are removed, the graph is k-colorable — assign colors (registers) during backtracking.
  4. If stuck (node has ≥ k neighbors), spill a variable to memory.
  5. Insert load/store instructions for spilled variables.

Example: If R0–R3 are available (k=4) and a variable has ≤ 3 interfering variables, it can be assigned a register.

5M Describe the different activation record (AR) schemes: static allocation, stack allocation, and dynamic allocation.

Static Allocation: Names bound to fixed storage locations at compile time. Simple but cannot support recursion or dynamic data structures.

Stack Allocation: ARs are allocated/deallocated in LIFO order on a call stack. Supports recursion. Used in most modern languages (C, Pascal, Java). The sp (stack pointer) points to the top of the stack; fp (frame pointer) points to a fixed position in the current AR.

Dynamic Allocation: Memory allocated at runtime from a heap. Used for dynamically sized data (linked lists, arrays whose size is known only at runtime). The heap pointer grows in the opposite direction from the stack.

15M
15M Explain code generation from three-address code using address and register descriptors. Generate target code for given TAC statements. PYQ

Descriptors:

Address Descriptor (AD[x]): Where is the current value of x? (Register R, Memory address M, or both).

Register Descriptor (RD[R]): Which variable's value is currently in register R?

Algorithm:

For each TAC statement:
1. Ensure source operands are in registers.
   If y not in register: gen('LD R, y')
   If z not in register: gen('LD R, z')
2. Generate the operation: gen('OP R, y, z, x')
3. Update AD[x] = {R} (or {R, M} if also in memory)
4. Update RD[R] = x

Example: TAC: t1 = a + b; t2 = t1 * c; a = t2

Assuming R1, R2 available:

LD   R1, a        -- AD[a] = {R1}; RD[R1] = a
ADD  R1, b        -- AD[b] = {R1}; RD[R1] = t1
MUL  R1, c        -- AD[c] updated; RD[R1] = t2
ST   a, R1        -- store t2 into a
                    AD[a] = {a, R1}

This minimizes memory accesses by keeping values in registers as long as possible.

Runtime & Advanced Topics

Symbol table organization · Hashing · Scoping · Garbage collection · Storage organization

💡

Exam Tip: Runtime topics are short-answer favorites (1M and 5M). Symbol table implementation (hashing, trees) and garbage collection are frequently asked. Know block-structured language scoping well.

1M
1M What is a symbol table? What operations does it support?

A symbol table is a data structure used by the compiler to store information about identifiers — name, type, scope, storage class, and other attributes. Core operations: insert (add a new entry), lookup (find an entry by name), and delete (remove an entry, e.g., when a scope ends).

1M What is garbage collection?

Garbage collection (GC) is an automatic memory management technique that reclaims memory occupied by objects that are no longer reachable (no longer referenced by any live variable). The collector identifies garbage objects and frees their memory. Common algorithms: mark-and-sweep, reference counting, generational GC.

1M What is scope in a programming language?

Scope is the region of the program where a particular identifier binding is valid. In block-structured languages, each block creates a new scope. An identifier declared in an inner block shadows one with the same name in an outer block. Scoping rules determine which declaration applies at each use of an identifier.

1M What is a mark-and-sweep garbage collector? PYQ

Mark-and-sweep GC operates in two phases: (1) Mark phase: Starting from root references (globals, stack, registers), recursively mark all reachable objects. (2) Sweep phase: Scan all heap memory; unmarked objects are garbage and their memory is reclaimed.

1M What is storage organization in a compiler?

The runtime memory is typically organized as: Code segment (machine instructions), Static/Data segment (global/static variables), Heap (dynamically allocated memory), Stack (activation records for procedure calls). The stack grows downward and heap grows upward, meeting in the middle.

1M What is the difference between static and dynamic scoping?

Static (lexical) scoping: Scope is determined by the program text. An identifier's binding is determined by its position in the source code. Most modern languages (C, Java, Python) use static scoping. Dynamic scoping: Scope is determined by the sequence of function calls at runtime. Used in some older languages like early Lisp.

5M
5M Explain symbol table organization using different data structures. PYQ

1. Linear List (Unordered): Simple array or linked list. Insert O(1), but lookup O(n). Only practical for small tables.

2. Sorted List / Binary Search Tree: Keeps entries sorted by name. Lookup O(log n). Can use self-balancing trees (AVL, red-black) to guarantee O(log n).

3. Hash Table: Uses a hash function h(name) to map names to table indices. Average lookup O(1). Collisions handled by chaining (linked list at each bucket) or open addressing (linear/quadratic probing).

4. Self-Organizing List: Reorders on access — recently accessed items move to front. Good if there's temporal locality.

Block-structured languages: Use a stack of symbol tables — push a new scope's table on entry, pop on exit. Lookup searches from top (innermost) scope downward.

5M Explain hashing for symbol table organization. What are the collision handling techniques? PYQ

Hashing: A hash function maps an identifier name to an integer index. The identifier is stored at table[h(name)].

Hash function: Typically sums the character codes: h(name) = Σ cᵢ mod table_size. A better approach multiplies each character by a position-dependent constant before summing.

Collision handling:

  1. Chaining (Open hashing): Each table slot holds a linked list of identifiers that hash to the same index. Simple, handles arbitrary load factor.
  2. Open Addressing (Closed hashing): All identifiers stored directly in the table. On collision, probe for next empty slot:
    • Linear probing: Try h, h+1, h+2, ... (clustering problem)
    • Quadratic probing: Try h, h+1², h+2², ...
    • Double hashing: Use a second hash function to determine probe sequence.
5M Describe the runtime storage organization — stack, heap, and static areas. PYQ

Static Area (Data Segment): Stores global and static variables. Size known at compile time. Fixed addresses throughout execution.

Stack (Activation Records): Used for procedure/function calls. Each call creates an AR on top of the stack. Contains:

  • Actual parameters
  • Return address
  • Dynamic link (pointer to caller's AR)
  • Saved registers and status
  • Local variables
  • Return value

Heap: Used for dynamically allocated data (new, malloc). Grows upward from the other end of memory. Managed by the runtime system / garbage collector.

Stack and heap grow toward each other; an overflow condition occurs if they meet.

5M Explain block-structured languages and how scope is managed in symbol tables. PYQ

In block-structured languages (e.g., Algol, Pascal), each block { ... } creates a new scope. Variables declared in an inner block are local to that block and shadow outer declarations.

Symbol table management:

  • On block entry: push a new symbol table onto a stack.
  • New declarations are inserted into the top table.
  • On lookup: search from the top (innermost scope) downward.
  • On block exit: pop the top table from the stack.

This ensures correct resolution of identifiers according to static (lexical) scoping rules. Each identifier maps to its most closely enclosing declaration.

15M
15M Explain garbage collection. Describe mark-and-sweep and reference counting algorithms in detail. PYQ

Garbage Collection (GC): Automatically reclaims heap memory occupied by objects no longer accessible by the program. Prevents memory leaks and dangling pointer errors.

Mark-and-Sweep:

  1. Mark phase: Starting from root references (globals, stack, registers), recursively visit and mark all reachable objects.
  2. Sweep phase: Scan the entire heap; unmarked objects are garbage — add them to the free list. Unmark all marked objects for the next cycle.

Advantages: Handles cyclic structures correctly. Disadvantages: Pauses program execution; requires free pointer to distinguish used from free memory.

Reference Counting:

  • Each object stores a count of references to it.
  • When a reference is created/destroyed, the count is incremented/decremented.
  • When count reaches 0, the object is immediately freed.

Advantages: Incremental, no pauses. Disadvantages: Cannot handle circular references (A → B → A keeps both alive forever); overhead of maintaining counts on every reference update.

Generational GC: Heap divided into generations. Young objects collected frequently (minor GC), old objects collected rarely (major GC). Based on the generational hypothesis — most objects die young.
