Why compilation is necessary:

  1. Efficiency: Compiled code runs faster than interpreted code because translation happens once.
  2. Error detection: Compilers catch syntax and semantic errors before execution, saving debugging time.
  3. Optimization: Compilers perform sophisticated transformations for speed and size.
  4. Portability: Same source code can be compiled for different machines with different target compilers.
  5. Abstraction: Programmers can write in human-readable high-level languages instead of binary machine code.

Lexical Analysis

Role of Lexical Analyzer · Input Buffering · Tokens · Regular Expressions · Finite Automata · DFA · NFA · Lex Tool

2.1 Key Definitions

Lexical Analysis: The first phase of compilation. Reads source characters, groups them into tokens, removes whitespace/comments.

Token: A pair <token-name, attribute-value> produced by the lexer. Examples: <ID, pointer>, <NUM, 42>, <IF, –>.

Pattern: The rule describing the form of lexemes for a token. Described by a regular expression.

Lexeme: The actual character sequence matching a pattern. E.g., "count" is a lexeme matching the identifier pattern.

Input Buffering: Technique to efficiently read source characters. Uses a buffer divided into two halves with sentinel markers. Uses lexemeBegin and forward pointers.

Sentinel: A special character (NUL or EOF) at the end of each buffer half to avoid boundary checks.

Lexeme specification: Rules defining what constitutes a valid token (using regular expressions).

Lexeme recognition: The process of matching input against specifications.

2.2 Regular Expressions (RE)

Regular expressions describe patterns of strings. Operations:

  • Union: r | s (match r OR s)
  • Concatenation: rs (r followed by s)
  • Kleene Closure: r* (zero or more r)
  • Positive Closure: r+ (one or more r)
  • Optional: r? (zero or one r)

Precedence (highest → lowest): * (closure) → concatenation → | (union)

Common RE examples:

  • Identifier: letter (letter | digit)*
  • Integer: digit+
  • Real number: digit+ . digit* ( . digit+ )?
  • Binary number: (0|1)+
  • Strings: " (any char except ")* "

2.3 Finite Automata

NFA (Nondeterministic Finite Automaton): Can have multiple next states for a given input; allows ε-transitions.

DFA (Deterministic Finite Automaton): Exactly one next state for each input symbol; no ε-transitions.

Transition Diagram: Circles = states, arrows = transitions, double circle = accepting state.

2.4 DFA Minimisation (Table-filling Algorithm)

  1. Eliminate unreachable states from the start state.
  2. Mark distinguishable pairs: any pair where one is final and the other is not.
  3. For each unmarked pair (p,q), mark it if for some input 'a', the pair (δ(p,a), δ(q,a)) is already marked.
  4. Repeat step 3 until no more marks are added.
  5. Unmarked pairs are equivalent; merge them.

2.5 Lex Tool

Lex (Flex) generates a lexical analyzer from specifications. A .l file contains:

  • Declarations: Definitions, %{ C code %}
  • Translation rules: Pattern { Action }
  • Auxiliary functions: Supporting C code

Lex generates a C file with function yylex() that reads input and returns tokens.

Differentiate lexeme and pattern. [2023]

What is input buffering in a lexical analyzer? [2023]

Input buffering reads source characters in large blocks (buffers) to reduce I/O operations. Uses two halves with a sentinel character at the end of each half to avoid boundary checks.

1 Mark

What is a sentinel in input buffering?

A sentinel is a special character (NUL or EOF) placed at the end of each buffer half. It signals buffer end without requiring an explicit boundary check on every character read.

1 Mark

What is a DFA?

A DFA (Deterministic Finite Automaton) is a finite state machine where for each state and input symbol there is exactly one next state. It has no ε-transitions.

1 Mark

What is an NFA?

An NFA (Nondeterministic Finite Automaton) is a finite state machine where for a state and input symbol, there can be multiple next states (or none). It allows ε-transitions.

1 Mark

What is the Kleene closure?

The Kleene closure of a regular expression r, written r*, denotes zero or more concatenations of r.

(letter | _)(letter | digit | _)* — an identifier starts with a letter or underscore, followed by any combination of letters, digits, underscores.

5-Mark Questions

5 Marks

Explain the role of a lexical analyzer. What are tokens, patterns and lexemes? [2023]

Role of Lexical Analyzer (Scanner/Tokenizer):

  1. Reads source program characters from left to right.
  2. Groups characters into lexemes, identifies token type for each.
  3. Produces a stream of tokens as output to the syntax analyzer.
  4. Removes whitespace, comments, and other ignorable characters.
  5. Enters identifiers into the symbol table.
  6. Reports lexical errors (illegal characters, unmatched strings).

Terminology:

  • Token: A pair <token-name, attribute-value>. E.g., <id, 1> where 1 is the symbol table entry.
  • Pattern: A rule describing the set of lexemes that match a token. E.g., the pattern for identifier is "letter followed by letters or digits".
  • Lexeme: The actual sequence of characters matched by a pattern. E.g., "counter", "x1", "temp_value".

Example: For source count = 5 + 3;, the tokens produced are: <ID, "count">, <ASSIGN, >, <NUM, 5>, <PLUS, >, <NUM, 3>, <SEMI, >.

5 Marks

Explain input buffering in lexical analysis. Why are sentinels used? [2023]

Reading source one character at a time is inefficient due to many I/O calls. Input buffering reads a large block of source into memory at once.

Buffer Pairs with Sentinels: The buffer is divided into two halves of size N (e.g., 4096 bytes). Two pointers are used:

  • lexemeBegin: marks the start of the current lexeme.
  • forward: scans ahead to find the end of the lexeme.

When forward reaches the end of a half, the other half is loaded with the next chunk of input. A sentinel (NUL '\0' or EOF) is placed at the boundary so that the scanner can check for end-of-buffer with one comparison instead of two.

  lexemeBegin →  forward →
  ┌──────────┬──────────┐
  │    H1    │    H2    │  '\0' EOF
  └──────────┴──────────┘

Advantage: One test per character instead of two (test for character + test for buffer end).

5 Marks

Explain the DFA minimization algorithm with an example. [2021]

Table-Filling Algorithm:

  1. Draw a table of all pairs of states (p, q) where p < q.
  2. Mark all pairs where one state is accepting and the other is not — these are distinguishable.
  3. For each unmarked pair (p,q) and each input symbol 'a', check the pair (δ(p,a), δ(q,a)). If that pair is marked, mark (p,q) too.
  4. Repeat step 3 iteratively until no new pairs are marked.
  5. Unmarked pairs are equivalent and can be merged.

Example: Consider DFA for "ends with 01":

  States: A (start), B (read 0), C (read 01) [final]
  Transitions:
    A --0--> B    A --1--> A
    B --0--> B    B --1--> C
    C --0--> B    C --1--> A

Apply algorithm: Pairs (A,B) — same behavior → equivalent. Merge into one state. Result: 2-state DFA.

5 Marks

Explain regular expressions and their operators with precedence. [2022]

A Regular Expression (RE) is a notation to describe the set of strings accepted by a finite automaton.

RE Operators:

  • Union (|): r | s means r or s
  • Concatenation: rs means r followed by s
  • Kleene Star (*): r* means zero or more occurrences
  • Plus (+): r+ means one or more occurrences
  • Optional (?): r? means zero or one occurrence
  • Parentheses: Used for grouping

Precedence (highest to lowest): * (closure) → concatenation → | (union)

Examples:

  • (a|b)* — any string of a's and b's (including empty)
  • (a|b)+ — non-empty string of a's and b's
  • a*b — any a's followed by a single b
  • (0|1)*01 — any binary string ending in 01

Construct NFA for the regular expression (0+1)*01 and convert it to DFA using subset construction. [2023]

Step 1: NFA for (0+1)*01 using Thompson's Construction:

   ┌─1─┐   │        │ε
   │   ▼   │        ▼

                  ε            accept

Construct NFAs for each subexpression (0+1), (0+1)*, 0, 1, 01 and connect with ε-transitions. Final state represents acceptance of the whole RE.

Step 2: NFA to DFA via Subset Construction:

DFA StateOn 0On 1
{A} (start){A,B}{A}
{A,B}{A,B}{A,C}
{A,C}{A,B,D}{A}
{A,B,D} ★{A,B,D}{A,C,E}
{A,C,E} ★{A,B,D}{A,C,E}

★ indicates accepting states (contain original NFA final state). 5 DFA states accept all strings ending in "01".

Step 3: Minimized DFA: Apply table-filling — states {A,C,E} and {A,B,D} are both accepting. After partitioning, minimize to 4 states.

15 Marks

Minimize the given DFA using the table-filling algorithm. Given DFA accepts all binary strings ending with '01'. [2022]

Given DFA (5 states):

   A --0--> B    A --1--> A
   B --0--> B    B --1--> C
   C --0--> D    C --1--> A
   D --0--> D    D --1--> E  ★
   E --0--> D    E --1--> A  ★
  (A = start, D,E = final)

Step 1: Initial marking — mark all pairs where one is final, one is not:

Pairs to check: (A,B), (A,C), (A,D), (A,E), (B,C), (B,D), (B,E), (C,D), (C,E), (D,E)

Mark (A,D), (A,E), (B,D), (B,E), (C,D), (C,E) — final/non-final pairs.

Step 2: Iterate — for each unmarked pair, check all inputs:

  • (A,B): On 0 → (B,B) not in table; on 1 → (A,C). (A,C) not marked. So (A,B) unmarked.
  • (A,C): On 0 → (B,D) marked! So mark (A,C).
  • (B,C): On 0 → (B,D) marked! So mark (B,C).

Step 3: Result — Only pair (A,B) remains unmarked → A and B are equivalent.

Step 4: Merge A and B into single state AB. Final minimized DFA has 4 states.

15 Marks

Explain the Lex tool. Write a Lex specification to count number of words in an input file. [2021]

Lex (Flex): A tool that generates a lexical analyzer from RE-based specifications. Input: .l file. Output: C source for yylex().

Structure of a Lex file:

  %{                 ← Declarations (C global vars, #include)
  #include <stdio.h>
  int word_count = 0;
  %}
  %%                 ← Translation rules (RE { Action })
  [a-zA-Z]+   { word_count++; }
  [ \t\n]+    { /* skip whitespace */ }
  .           { /* skip other chars */ }
  %%                 ← Auxiliary C functions
  int main() {
    yylex();
    printf("Word count: %d\n", word_count);
    return 0;
  }

Working:

  1. User writes .l file with RE patterns and actions.
  2. Lex (or Flex) compiles it into C code (lex.yy.c).
  3. The C compiler compiles this into executable scanner.
  4. When scanner runs, yylex() reads input, matches patterns, executes corresponding actions.

Components:

  • Definitions section: %{ %} for C declarations, named patterns.
  • Rules section: RE patterns with associated C actions.
  • User code section: Auxiliary functions (main, helper routines).
