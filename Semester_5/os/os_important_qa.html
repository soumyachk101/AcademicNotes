Q11Explain Dining Philosophers Problem and deadlock avoidance.

Detailed 5-Mark Solution:

1. Core Definition: Banker's Algorithm avoids deadlock by testing resource requests against maximum claimed demand matrix.

2. Data Structures & Safety Check:

  • \(Available[m]\): Free instances of resource \(j\).
  • \(Max[n][m]\): Maximum demand of process \(i\) for resource \(j\).
  • \(Allocation[n][m]\): Resources currently allocated to process \(i\).
  • \(Need[n][m] = Max[n][m] - Allocation[n][m]\).
  • Safety Check: Find process \(P_i\) where \(Need_i \le Work\), update \(Work = Work + Allocation_i\), and mark finished. If all processes finish, state is safe.

Q16Explain Paging Architecture with Address Translation diagram.

Detailed 5-Mark Solution:

1. Core Concept: Paging is a non-contiguous memory allocation scheme that eliminates external fragmentation by dividing physical memory into fixed-size frames and logical memory into equal-sized pages.

graph LR CPU -->|p, d| LA[Logical Address] LA -- p --> PT[Page Table] PT -- f --> PA[Physical Address] LA -- d --> PA PA --> RAM[(Physical Memory)]
Figure: Paging Hardware & Logical to Physical Address Translation

2. Address Translation Mechanism:

  • Logical Address: Consists of Page Number \(p\) and Offset \(d\).
  • Page Table Lookup: \(p\) indexes into the Page Table to retrieve Frame Number \(f\).
  • Physical Address: Formed by concatenating Frame Number \(f\) with Offset \(d\): \(\text{Physical Address} = (f \times \text{Page Size}) + d\).

graph LR Start[Head Starts] --> Dir[Moves in One Direction] Dir --> End[Reaches End of Disk] End --> Rev[Reverses Direction] Rev --> Serv[Services Remaining Requests]

2. Characteristics: Provides lower variance in response time compared to FCFS/SSTF and eliminates starvation for middle cylinders.

graph LR Inode[Inode Metadata] Inode --> DP[12 Direct Pointers] Inode --> SIP[Single Indirect Pointer] Inode --> DIP[Double Indirect Pointer] DP --> DB1[(Data Blocks)] SIP --> IB1[Index Block] --> DB2[(Data Blocks)]

Q1a) Solve Banker's Algorithm: Processes: P0, P1, P2, P3, P4. Allocation: P0(0,1,0), P1(2,0,0), P2(3,0,2), P3(2,1,1), P4(0,0,2). Max: P0(7,5,3), P1(3,2,2), P2(9,0,2), P3(2,2,2), P4(4,3,3). Available: (3,3,2). 1. Calculate Need Matrix. 2. Find Safe Sequence. 3. Is request from P1 for (1,0,2) granted immediately? b) Explain Deadlock Recovery techniques.

15-Mark Master Exam Solution:

Part (a) Banker's Safety Algorithm Complete Calculation:

Given 5 processes \(P_0 \dots P_4\) and 3 resource types \(A(10), B(5), C(7)\).

  • 1. Need Matrix Calculation (\(Need = Max - Allocation\)):
    \(P_0\) Need = [7,4,3] - [0,1,0] = [7,3,3]
    \(P_1\) Need = [3,2,2] - [2,0,0] = [1,2,2]
    \(P_2\) Need = [9,0,2] - [3,0,2] = [6,0,0]
    \(P_3\) Need = [2,2,2] - [2,1,1] = [0,1,1]
    \(P_4\) Need = [4,3,3] - [0,0,2] = [4,3,1]
