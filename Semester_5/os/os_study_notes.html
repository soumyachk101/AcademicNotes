Introduction to Operating Systems

What is OS, its functions, types, and system structures

What is an Operating System?

An operating system (OS) is a system software that acts as an interface between the user and the computer hardware. It manages hardware resources and provides services to application programs. The OS is the most essential software running on a computer — without it, the hardware is useless.

The OS performs two main roles:

  • As a resource manager: Allocates CPU, memory, I/O devices among competing programs.
  • As a control program: Manages execution of user programs and prevents errors.

Functions of Operating System

Key functions include:

  • Process Management: Creating, scheduling, and terminating processes.
  • Memory Management: Allocating and deallocating memory space.
  • File System Management: Storing, retrieving, and organizing files on storage.
  • Device Management: Managing I/O devices through device drivers.
  • Security & Protection: Protecting resources from unauthorized access.
  • User Interface: Providing CLI (command line) or GUI (graphical) interfaces.
  • Booting & Shutdown: Loading the OS into memory and safe system termination.

Types of Operating Systems

1. Batch OS: Jobs are grouped into batches with similar requirements and processed together. No direct user interaction. Examples: Payroll systems, transaction processing.

2. Multiprogramming OS: Multiple programs are kept in memory simultaneously. When one program waits for I/O, the CPU switches to another program. Maximizes CPU utilization.

3. Multiprocessing OS: Uses two or more CPUs working in parallel. True parallel processing. Examples: Linux, Windows Server.

4. Real-Time OS (RTOS): Must respond within strict time constraints. Used in embedded systems, robotics, air traffic control. Two types: Hard real-time (missed deadline = failure) and Soft real-time (degraded performance).

5. Distributed OS: Manages a group of independent computers and makes them appear as a single computer. Resources are shared across the network. Examples: LOCUS, Amoeba.

OS Structures

Monolithic Structure: The entire OS runs as a single program in kernel mode. All services (file management, memory management, device drivers) are bundled together. Simple but difficult to maintain. Example: UNIX, Linux.

Microkernel Structure: Only essential services (IPC, memory management, basic scheduling) run in kernel mode. Other services (file systems, device drivers) run in user mode as separate processes. More stable — a crash in one service doesn't bring down the whole system. Example: Minix, QNX, macOS XNU.

Modular Structure: The OS is divided into modules (layers), each providing specific services. Each module communicates only with the layer directly below it. Easier to maintain and extend. Example: Windows NT, macOS.

System Calls and Booting Process

System Calls are the programming interface between the OS and application programs. They allow user programs to request services from the OS kernel. Common categories:

  • Process Control: fork(), exit(), wait()
  • File Management: open(), read(), write(), close()
  • Device Management: ioctl(), read(), write()
  • Information Maintenance: getpid(), alarm(), sleep()
  • Communication: pipe(), shmget(), mmap()

Booting Process: The sequence of events when a computer is powered on:

  • BIOS/UEFI performs POST (Power-On Self-Test)
  • Bootloader (GRUB/LILO) loads the OS kernel into memory
  • Kernel initializes hardware and mounts the root filesystem
  • init/systemd starts system services and processes
Key Concept: The kernel is the core of the OS — it's the only part that runs in privileged mode (kernel mode). Everything else (shell, utilities, applications) runs in user mode and must use system calls to access hardware or privileged operations.
Exam Tip: OS types are a very common 1-mark question. Memorize the 5 types with one-line definitions. For 5-mark questions, compare two types (e.g., batch vs multiprogramming, RTOS vs general-purpose OS). The 15-mark question almost always asks for OS definition + functions + types + structures combined.

Explain OS architecture — monolithic, microkernel, and modular.

Monolithic: The entire OS (kernel, file system, memory management, device drivers) runs as one large program in kernel mode. All components can directly call each other. Advantage: fast. Disadvantage: one bug can crash the whole system, hard to maintain.

Process Management

Processes, threads, scheduling, and inter-process communication

Process vs Program

A program is a passive set of instructions stored on disk — it is just a file containing code. A process is a program in execution — it is an active entity that needs CPU time, memory, and other resources.

  • A program has no address space; a process has its own address space.
  • A program cannot perform any action; a process performs actions.
  • One program can create multiple processes (e.g., opening two Chrome windows).

Process States and PCB

A process can be in one of five states:

  • New: The process is being created.
  • Ready: The process is loaded in memory and waiting for the CPU.
  • Running: The process is currently being executed by the CPU.
  • Waiting/Blocked: The process is waiting for an event (I/O completion, signal).
  • Terminated/Exit: The process has finished execution.

The Process Control Block (PCB) is a data structure maintained by the OS for each process. It contains:

  • Process state (new, ready, running, etc.)
  • Process ID (PID) and Parent PID
  • CPU registers, program counter, stack pointer
  • Memory management info (page tables, memory limits)
  • Accounting info (CPU time used, process limits)
  • I/O status (list of open files, I/O devices allocated)

Process Scheduling and Context Switching

Process scheduling is the mechanism by which the OS selects which process gets the CPU next. The long-term scheduler selects processes from the pool and loads them into memory. The short-term scheduler (CPU scheduler) selects a ready process and allocates the CPU to it.

Context switching is the process of saving the state (context) of the currently running process and loading the state of the next process. It involves saving registers, program counter, and stack pointer to the PCB. Context switching is pure overhead — it adds latency but enables multitasking.

Inter-Process Communication (IPC)

IPC allows processes to communicate and synchronize their actions. Two main methods:

1. Shared Memory: A region of memory is shared between cooperating processes. Processes communicate by reading and writing to this shared region. Fast but requires synchronization (e.g., mutexes, semaphores) to avoid race conditions.

2. Message Passing: Processes communicate by exchanging messages. Can be direct (process names known) or indirect (through a mailbox/port). Advantage: easier to implement in distributed systems, no need for shared memory. Disadvantage: slower than shared memory due to kernel involvement.

Threads and Multithreading

A thread is the smallest unit of CPU execution within a process. A process can have multiple threads, all sharing the same address space and resources.

Process vs Thread:

  • A process has its own address space; threads share the address space of their parent process.
  • Process creation is expensive (new address space); thread creation is lightweight.
  • Inter-process communication requires OS support; threads can communicate directly via shared memory.
  • A process crash does not affect others; one thread crash can bring down the whole process.

Multithreading Models:

  • Many-to-One: Many user threads mapped to one kernel thread. If one thread blocks, the whole process blocks.
  • One-to-One: Each user thread maps to a separate kernel thread. Better concurrency but higher overhead.
  • Many-to-Many: Many user threads multiplexed onto a smaller/equal number of kernel threads. Best of both approaches.
Key Concept: Context switching between threads of the same process is cheaper than between processes because threads share the same address space — only the stack pointer, registers, and program counter need to be switched, not the entire memory map.
Exam Tip: "Process states" and "PCB" are guaranteed 1-mark questions. For 5-marks, always draw the 5-state process diagram (new → ready → running → waiting → terminated) with arrows. IPC (shared memory vs message passing) and threads vs processes are frequent 5-mark topics.

Explain process states with diagram.

A process can be in one of five states:

1. New: The process is being created. OS allocates PCB and initializes resources.

2. Ready: Process is loaded in memory, waiting for CPU allocation. Multiple ready processes form a ready queue.

5 Marks
What is IPC? Explain shared memory and message passing.

Inter-Process Communication (IPC) is a mechanism that allows processes to communicate and synchronize their actions. Two main methods:

Shared Memory: A region of memory is established that multiple processes can access. One process creates the shared memory segment, others attach to it. Processes communicate by reading/writing this shared region. It is fast because data does not need to be copied between processes. However, it requires synchronization mechanisms (semaphores, mutexes) to prevent race conditions when multiple processes access the same memory simultaneously.

Message Passing: Processes exchange data by sending and receiving messages. This can be done through direct communication (processes name each other explicitly) or indirect communication (using mailboxes/ports). Message passing is useful in distributed systems and is easier to implement than shared memory, but it is slower because each message transfer involves the kernel.

Explain process management in detail. Discuss process states, PCB, context switching, and inter-process communication mechanisms.

Process Management is one of the core functions of an operating system. A process is a program in execution that needs resources (CPU time, memory, I/O devices) to accomplish its task.

Process States: A process moves through five states: New (being created), Ready (waiting for CPU), Running (executing on CPU), Waiting/Blocked (waiting for I/O or event), and Terminated (finished execution). Transitions occur when the OS scheduler makes decisions or events like I/O completion occur.

Process Control Block (PCB): Each process is represented by a PCB — a data structure containing the process state, PID, CPU registers, memory management information, scheduling info, and I/O status. The PCB is created when the process is created and deleted when it terminates. It is the key mechanism that enables the OS to manage multiple processes.

Context Switching: When the CPU switches from executing one process to another, it performs a context switch: it saves the current process's context (registers, program counter, stack pointer) into its PCB and loads the next process's context from its PCB. Context switching is pure overhead — it adds latency but is essential for multitasking.

IPC Mechanisms:

  • Shared Memory: A block of memory shared between processes. Fast but requires synchronization (semaphores, mutexes) to avoid race conditions.
  • Message Passing: Processes exchange messages directly or through mailboxes. Slower but safer; suitable for distributed systems.

CPU Scheduling

Scheduling algorithms, Gantt charts, and deadlock handling

Scheduling Criteria

The OS uses scheduling algorithms to decide which process gets the CPU. Key criteria for evaluating algorithms:

  • CPU Utilization: Keep the CPU as busy as possible (ideally 100%).
  • Throughput: Number of processes completed per unit time.
  • Turnaround Time: Total time from submission to completion = Waiting time + Burst time.
  • Waiting Time: Total time spent in the ready queue.
  • Response Time: Time from request submission to the first response (important for interactive systems).

CPU Scheduling Algorithms

1. FCFS (First Come First Serve): Processes are executed in the order they arrive. Non-preemptive. Simple but can cause the "convoy effect" where short processes wait for long ones. Average waiting time is generally high.

2. SJF (Shortest Job First): Selects the process with the smallest burst time. Can be preemptive (SRTF — Shortest Remaining Time First) or non-preemptive. Optimal for minimum average waiting time but requires knowing burst times in advance.

3. Priority Scheduling: Each process has a priority. The CPU is allocated to the highest priority process. Can be preemptive or non-preemptive. Problem: starvation (low-priority processes may never execute). Solved by aging (gradually increasing priority of waiting processes).

4. Round Robin (RR): Each process gets a fixed time slice (time quantum) in a cyclic manner. If a process doesn't finish in its quantum, it goes to the back of the ready queue. Preemptive. Good for time-sharing systems. Performance depends heavily on the size of the time quantum.

5. Multilevel Queue: Processes are divided into multiple queues based on priority or type (e.g., system processes, interactive processes, batch processes). Each queue has its own scheduling algorithm.

6. Multilevel Feedback Queue: Processes can move between queues based on their behavior. A process that uses too much CPU time is moved to a lower-priority queue. Allows differentiation and prevents starvation.

Gantt Chart and Performance Calculations

A Gantt chart is a bar chart that visually represents the schedule of processes on the CPU. It shows when each process runs and for how long.

From the Gantt chart, we calculate:

  • Completion Time (CT): When a process finishes.
  • Turnaround Time (TAT): CT - Arrival Time. Total time in the system.
  • Waiting Time (WT): TAT - Burst Time. Time spent waiting in the ready queue.
  • Response Time: First response time - Arrival Time.

Thrashing

Thrashing occurs when a system spends more time swapping pages in and out of memory than executing actual processes. This happens when the degree of multiprogramming is too high — there are so many processes in memory that each has too few frames, causing frequent page faults.

Thrashing is detected by monitoring the page-fault frequency. To prevent it: use local replacement policies, working set model, or page-fault frequency algorithms.

Deadlock

A deadlock is a situation where a set of processes are blocked because each process is holding a resource and waiting for another resource held by another process in the set.

Necessary Conditions (all four must hold simultaneously):

  • Mutual Exclusion: At least one resource is non-sharable.
  • Hold and Wait: A process holds one resource and waits for another.
  • No Preemption: Resources cannot be forcibly taken from a process.
  • Circular Wait: A circular chain of processes exists where each waits for a resource held by the next.

Handling Deadlock:

  • Prevention: Ensure at least one of the four conditions cannot occur. e.g., require all resources at once (break hold-and-wait), allow preemption, use resource ordering (break circular wait).
  • Avoidance: The OS dynamically checks resource allocation to avoid deadlock. Uses the Banker's Algorithm — only allocates resources if the resulting state is safe.
  • Detection and Recovery: Allow deadlock to occur, detect it using resource allocation graphs, then recover by terminating processes or preempting resources.
  • Ignorance: Most OSes (UNIX, Windows) simply ignore deadlock and assume it won't happen — it's cheaper to reboot than to implement prevention.
Key Concept: SJF is optimal for minimum average waiting time, but it requires knowing the burst time in advance. In practice, we estimate it using exponential averaging: S(n+1) = alpha × T(n) + (1 - alpha) × S(n), where T(n) is the actual burst time and S(n) is the predicted burst time.
Exam Tip: SJF calculations with Gantt charts are the most common numerical question. Always draw the Gantt chart first, then calculate TAT = completion time - arrival time, WT = TAT - burst time. For deadlock, memorize all four conditions and the four handling strategies. Banker's Algorithm questions often appear for 5-10 marks.

Explain deadlock prevention strategies.

Deadlock prevention works by ensuring that at least one of the four necessary conditions for deadlock cannot occur:

1. Breaking Mutual Exclusion: Make all resources sharable. Not practical for non-sharable resources like printers.

2. Breaking Hold and Wait: Require processes to request all resources at once before execution begins. If any resource is unavailable, the process waits without holding any resources. Problem: resource utilization may be low.

3. Breaking No Preemption: Allow the OS to preempt resources from a process. If a process holding resources requests a new resource that cannot be allocated, all its held resources are released. Problem: can cause starvation.

4. Breaking Circular Wait: Impose a total ordering of resource types. A process can only request resources in increasing order of their assigned numbers. This prevents circular chains from forming. This is the most practical prevention strategy.

Memory Management

Address spaces, paging, segmentation, and virtual memory

Logical vs Physical Address

A logical address (virtual address) is generated by the CPU and used by processes. It ranges from 0 to the maximum address space. A physical address (real address) is the actual address in physical memory (RAM). The Memory Management Unit (MMU) maps logical addresses to physical addresses at runtime.

The base register holds the starting physical address of the process. The limit register defines the range of logical addresses. If a process tries to access an address beyond the limit, a trap (segmentation fault) occurs.

Memory Allocation Techniques

Contiguous Allocation: Each process occupies a single contiguous block of memory. Can be fixed-size partitions (multiple partitions of equal size) or variable-size partitions (each process gets exactly what it needs). Problems: external fragmentation.

Paging: Physical memory is divided into fixed-size blocks called frames. Logical memory is divided into blocks of the same size called pages. The OS maintains a page table for each process that maps page numbers to frame numbers. No external fragmentation, but internal fragmentation can occur (last page may not be full).

Segmentation: A program is divided into segments (code, data, stack, heap) of variable sizes. Each segment has a segment number and an offset. A segment table maps segment numbers to physical memory locations. No internal fragmentation, but external fragmentation can occur.

Paged Segmentation: Combines both paging and segmentation. Each segment is divided into pages. Provides the benefits of both: logical grouping (segments) and no external fragmentation (paging).

Virtual Memory

Virtual memory is a technique that gives each process the illusion that it has exclusive access to a large, contiguous memory space, even if the physical RAM is smaller. It is implemented using demand paging — pages are loaded into memory only when they are needed (on a page fault).

The Translation Lookaside Buffer (TLB) is a small, fast cache inside the MMU that stores recent page table entries. It speeds up address translation by avoiding a memory access for every address. TLB hit ratio determines the effective memory access time.

Page Replacement Algorithms

When a page fault occurs and no free frame is available, the OS must replace an existing page. Common algorithms:

  • FIFO (First In First Out): Replace the oldest page. Simple but can replace frequently used pages (Belady's anomaly — increasing frames can increase page faults).
  • Optimal (OPT): Replace the page that will not be used for the longest time in the future. Impossible to implement (requires future knowledge) but serves as a theoretical benchmark.
  • LRU (Least Recently Used): Replace the page that hasn't been used for the longest time. Good approximation of OPT. Implemented using counters, stacks, or hardware support.
  • LFU (Least Frequently Used): Replace the page with the lowest reference count.
  • Clock (Second Chance): Approximation of LRU. Pages are in a circular list with a reference bit. If the bit is 1 (recently used), give a second chance and set it to 0. If 0, replace the page.

Thrashing and Working Set Model

Thrashing occurs when the degree of multiprogramming is too high — processes have too few frames allocated, causing frequent page faults. The system spends more time swapping pages than executing processes.

The Working Set Model defines the working set of a process as the set of pages currently in use. The OS monitors each process's working set size and ensures it has enough frames. If total working set sizes exceed available frames, thrashing occurs.

To prevent thrashing: use the working set model, implement page-fault frequency (PFF) schemes, or use local (per-process) page replacement instead of global replacement.

Key Concept: Effective Memory Access Time (EMAT) = (1 - hit ratio) × Memory access time + hit ratio × TLB access time. For example, if hit ratio = 0.98, memory access = 100ns, TLB access = 10ns: EMAT = 0.02 × 100 + 0.98 × 10 = 11.8ns.
Exam Tip: Page replacement algorithm problems with reference strings are extremely common. Always draw frames as boxes and simulate page by page, marking hits and faults. For LRU, track the most recently used pages. For FIFO, use a queue. Compare paging vs segmentation as a 5-mark comparison table.

Explain LRU page replacement algorithm with an example.

LRU (Least Recently Used) replaces the page that has not been used for the longest period of time. It is based on the principle that pages used recently are likely to be used again soon.

Example: Reference string: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5. Frame size: 3.

Step-by-step:

  • 1 → Miss (frames: [1, -, -])
  • 2 → Miss (frames: [1, 2, -])
  • 3 → Miss (frames: [1, 2, 3])
  • 4 → Miss. LRU page is 1 (used longest ago). Replace 1. (frames: [4, 2, 3])
  • 1 → Miss. LRU page is 3. Replace 3. (frames: [4, 2, 1])
  • 2 → Hit
  • 5 → Miss. LRU page is 4. Replace 4. (frames: [5, 2, 1])
  • 1 → Hit
  • 2 → Hit
  • 3 → Miss. LRU page is 1. Replace 1. (frames: [5, 2, 3])
  • 4 → Miss. LRU page is 5. Replace 5. (frames: [4, 2, 3])
  • 5 → Miss. LRU page is 2. Replace 2. (frames: [4, 5, 3])

Total page faults: 9 out of 12 references.

Explain memory management techniques (contiguous, paging, segmentation). Discuss virtual memory and page replacement algorithms with examples.

1. Contiguous Allocation: Each process occupies a single contiguous block of memory. Two approaches: fixed partitioning (equal-sized partitions, simple but causes internal fragmentation) and variable partitioning (each process gets exactly what it needs, but causes external fragmentation — solved by compaction).

2. Paging: Logical memory is divided into pages, physical memory into frames. A page table maps each page to a frame. Advantages: no external fragmentation, efficient memory use. Disadvantages: internal fragmentation, overhead of page tables. Solved with multi-level paging and inverted page tables.

3. Segmentation: A program is divided into logical segments (code, data, stack). Each segment has a segment number and offset. A segment table maps segments to physical memory. Advantage: logical view of memory. Disadvantage: external fragmentation.

Virtual Memory: Uses demand paging — pages are loaded only when needed. Benefits: larger logical address space than physical memory, more processes in memory, less I/O for unused pages. Demand paging introduces a page table with a valid/invalid bit. A page fault triggers the OS to load the page from disk.

Page Replacement Algorithms:

  • FIFO: Replace the oldest page. Simple but may replace frequently used pages.
  • Optimal: Replace the page used farthest in the future. Theoretical lower bound.
  • LRU: Replace the least recently used page. Best practical approximation of Optimal.

TLB: A small, fast cache for page table entries. EMAT = (1 - h) × Memory access + h × TLB access, where h is the TLB hit ratio.

File Systems & I/O

File concepts, directory structures, disk scheduling, and I/O management

File Concepts and Access Methods

A file is a named collection of related information stored on secondary storage (disk). It is the smallest unit of logical storage. The OS manages files through a file system, which provides a structured way to store, organize, and retrieve data.

File attributes include: name, type, size, creation/modification timestamps, protection, and location on disk.

Access Methods:

  • Sequential Access: Information is accessed in order (like a tape). Read/write sequentially. Simplest method.
  • Direct/Random Access: Allows reading/writing at any position directly (like a disk). Each block has a unique address. Used by databases.
  • Indexed Access: Uses an index block containing pointers to data blocks. Allows both sequential and direct access.

Directory Structures

A directory is a collection of nodes containing information about files. Directory structures:

  • Single-Level: All files in one flat directory. Simple but no organization; name collisions.
  • Two-Level: Each user has their own directory (UFD). The system has a master directory (MFD) pointing to all UFDs. Solves name collisions but users cannot create subdirectories.
  • Tree-Structured (Hierarchical): Directories can have subdirectories. Users can create their own directory hierarchies. Most common (Windows, Linux). Supports absolute and relative paths.
  • Acyclic Graph: Allows sharing of files and directories through links (hard links and symbolic/symbolic links). Cannot have cycles (no cycles allowed).

File Allocation Methods

1. Contiguous Allocation: Each file occupies a contiguous set of blocks on disk. The directory stores the starting block address and length. Advantage: simple, fast sequential and direct access. Disadvantage: external fragmentation, difficulty in file growth.

2. Linked Allocation: Each file is a linked list of disk blocks. Each block contains a pointer to the next block. The directory stores the address of the first and last block. Advantage: no external fragmentation. Disadvantage: slow random access (must traverse the list), pointer overhead, reliability risk if a pointer is lost.

3. Indexed Allocation: All pointers to a file's blocks are stored in an index block. The directory stores the address of the index block. Advantage: supports direct access, no external fragmentation. Disadvantage: overhead of index block (for small files, the index block itself takes more space than the data). Variants: linked index blocks, multi-level index, combined scheme (Unix inode).

Free Space Management

Methods for tracking free disk blocks:

  • Bit Vector: Each block has one bit (0 = free, 1 = allocated). Simple but requires large contiguous memory for the entire bit vector on large disks.
  • Linked List: All free blocks are linked together. Each free block stores a pointer to the next free block. Simple but slow to find contiguous free blocks.
  • Grouping: The first free block stores addresses of n-1 free blocks plus a pointer to the next group of free blocks.
  • Counting: Stores addresses of first free blocks and counts of contiguous free blocks following each. Efficient for contiguous allocation.

Disk Scheduling Algorithms

The disk head moves between cylinders to read/write data. Disk scheduling determines the order in which I/O requests are served:

  • FCFS (First Come First Serve): Requests served in arrival order. Simple but fair only; not optimal for seek time.
  • SSTF (Shortest Seek Time First): Selects the request closest to the current head position. Minimizes seek time but can cause starvation of distant requests.
  • SCAN (Elevator): Head moves in one direction servicing all requests, then reverses. Like an elevator. Can cause wait time for requests just passed.
  • C-SCAN (Circular SCAN): Head moves in one direction servicing requests, then jumps back to the start (without servicing on the return). More uniform wait time than SCAN.
  • LOOK / C-LOOK: Like SCAN/C-SCAN but the head only goes as far as the last request in each direction (doesn't go to the end of the disk). More efficient than SCAN/C-SCAN.

I/O Hardware, Buffering, Caching, and Spooling

I/O Hardware: I/O devices communicate with the CPU through I/O ports and device controllers. The device driver is the software interface between the OS and the device. I/O can be done through: programmed I/O (CPU polls the device), interrupt-driven I/O (device signals the CPU), and DMA (Direct Memory Access — device transfers data directly to memory without CPU involvement).

Buffering: A buffer is a memory area used to temporarily store data during I/O transfers. It compensates for speed differences between the producer and consumer. Types: single buffering, double buffering, circular buffering.

Caching: A portion of memory used to hold frequently accessed data from a slower device. Accessing the cache is much faster than accessing the original device. Used in disk caching, web caching, etc.

Spooling (Simultaneous Peripheral Operation On-Line): A mechanism where data is temporarily held in a buffer (usually on disk) for later use by a device that operates at a different speed. Example: print spooling — print jobs are queued on disk and sent to the printer when it's ready. Allows the CPU to continue executing other tasks while the slow I/O device processes the data.

Key Concept: SSTF minimizes seek time but may starve requests far from the head. SCAN/C-SCAN provide more uniform wait times. C-SCAN treats the cylinders as a circular list, providing more consistent response times. LOOK is more efficient than SCAN because it doesn't travel to the disk's physical end.
Exam Tip: Disk scheduling calculations are very common. Draw the disk head movement diagram with cylinders marked. Calculate total head movement = sum of all individual movements. Average seek time = total movement / number of requests. File allocation methods (contiguous, linked, indexed) are also very frequent as comparison questions.

Explain different file allocation methods.
