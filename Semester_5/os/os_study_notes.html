Operating System Overview

What is an Operating System?

An Operating System (OS) is a system software that acts as an intermediary between the user and the computer hardware. It provides an environment in which a user can execute programs conveniently and efficiently.

Two main views:
User View: Convenience, ease of use, resource allocation.
System View: Resource allocator, control program, manages CPU, memory, I/O.

Functions of an OS

  • Process Management: Creating, scheduling, terminating processes.
  • Memory Management: Allocating/deallocating memory space.
  • File System Management: Storing, retrieving, organizing files.
  • Device Management: Managing I/O devices via device drivers.
  • Security & Protection: Preventing unauthorized access.
  • Job Scheduling: Deciding which job to execute next.
  • Error Detection: Handling hardware and software errors.

Types of Operating Systems

TypeKey FeatureExample
Batch OSJobs grouped & processed together without interactionIBM OS/360
Multiprogramming OSMultiple programs in memory; CPU switches when one waitsUnix, Windows
Time-Sharing OSCPU time divided into time slices (quantum)Unix, Linux
Distributed OSResources shared across networked computersAmoeba, LOCUS
Real-Time OSHard/soft deadlines; deterministic responseVxWorks, RTLinux
Multiprogramming increases CPU utilization by overlapping I/O and CPU. Time-sharing adds fairness via time slices.

System Calls

System calls provide an interface between a running program and the OS. They are the only way for user programs to request OS services.

CategoryExamples
Process Controlfork(), exec(), exit(), wait(), abort()
File Managementopen(), close(), read(), write(), link(), unlink()
Device Managementioctl(), read(), write()
Information Maintenancegetpid(), alarm(), sleep(), gettimeofday()
Communicationpipe(), shmget(), mmap(), socket()
System calls are invoked via a trap (software interrupt). CPU switches from User Mode to Kernel Mode.

System Programs

System programs provide a convenient environment for program development and execution. They are not part of the kernel but use system calls.

  • File Management: Creating, deleting, copying, renaming files.
  • Status Information: Date, time, memory, disk usage.
  • File Modification: Text editors, debuggers.
  • Programming Language Support: Compilers, assemblers, linkers.
  • Program Loading & Execution: Loaders, linkers, debuggers.
  • Communication: Mail, remote login, file transfer.

Kernel Structures

StructureDescriptionProsCons
MonolithicAll OS services in kernel space; single address spaceFast, efficientUnstable, hard to maintain

Linux = Monolithic (loadable modules). Windows NT = Hybrid. macOS XNU = Hybrid (Mach microkernel + BSD).

Virtual Machines

A Virtual Machine (VM) is a software emulation of a physical computer. It provides an abstraction layer between hardware and the OS.

  • Host OS: Runs the VMM (Virtual Machine Monitor / Hypervisor).
  • Guest OS: Runs inside the VM as if on real hardware.
  • Type 1 (Bare Metal): Hypervisor runs directly on hardware (VMware ESXi, Xen).
  • Type 2 (Hosted): Hypervisor runs as application on host OS (VirtualBox, VMware Workstation).
  • Benefits: Isolation, portability, testing, server consolidation.

The PCB is the OS's data structure for managing processes. Also called Task Control Block (TCB).

Process Scheduling Queues

  • Job Queue: All processes in the system (long-term scheduler selects from here).
  • Ready Queue: Processes in memory, ready to execute.
  • Device Queue: Processes waiting for a specific I/O device.
  • A process migrates between queues based on its state and OS decisions.

Schedulers

SchedulerAlso CalledFunctionFrequency
Long-termJob SchedulerSelects processes from job queue to admit to ready queueLeast frequent (seconds/minutes)
Short-termCPU SchedulerSelects process from ready queue to execute nextFrequent (milliseconds)
Medium-termSwapperSwaps processes in/out of memory to control multiprogramming levelMedium frequency
Long-term controls degree of multiprogramming. Medium-term implements swapping to relieve memory pressure.

CPU Scheduling Algorithms

1. FCFS (First-Come First-Served)

Non-preemptive. Processes served in arrival order. FIFO queue.

  • Simple but suffers convoy effect (short jobs wait for long ones).
  • Not optimal, not starvation-free for all cases.

2. SJF (Shortest Job First)

Selects process with smallest next CPU burst. Can be preemptive (SRTF) or non-preemptive.

  • Optimal: Minimizes average waiting time among all deterministic algorithms.
  • Problem: Hard to know burst time ahead of time (use prediction).
  • Non-preemptive SJF: Process runs to completion once started.
  • Preemptive SRTF: New shorter job preempts running process.

3. Priority Scheduling

Each process has a priority. Lowest/ highest priority number runs first.

  • Can be preemptive or non-preemptive.
  • Problem: Starvation — low-priority processes may never run.
  • Solution: Aging — gradually increase priority of waiting processes.

4. Round Robin (RR)

Each process gets a time quantum (q). Preemptive. Designed for time-sharing.

  • If q is large → FCFS behavior.
  • If q is small → excessive context switches.
  • Rule of thumb: \(q \approx 70-80\%\) of context switch overhead ratio.

5. Multilevel Queue Scheduling

Ready queue partitioned into multiple queues by process type (foreground/background, interactive/batch). Each queue has its own algorithm.

  • Scheduling between queues: Fixed-priority (foreground first), time-slicing, or feedback.
  • Multilevel Feedback Queue (MLFQ): Processes can move between queues based on behavior.

Key Formulas — Scheduling

Completion Time (CT) = Finish time of process
Turnaround Time (TAT) = CT − Arrival Time (AT)
Waiting Time (WT) = TAT − Burst Time (BT) = CT − AT − BT
Response Time (RT) = First response − Arrival Time
Average WT = ΣWT / n   |   Average TAT = ΣTAT / n
Always draw the Gantt chart first — it makes waiting time calculation trivial.

Threads

A thread is a basic unit of CPU utilization. It is the smallest sequence of programmed instructions that can be managed independently by a scheduler.

Multithreading Models

  • Many-to-One: Many user threads mapped to one kernel thread.
  • One-to-One: Each user thread maps to a kernel thread (most common).
  • Many-to-Many: m user threads multiplexed onto n kernel threads.

Process Synchronization & Deadlocks

The Critical Section Problem

A critical section is the portion of code where a process accesses shared resources. The critical section problem requires:

  • Mutual Exclusion: Only one process in CS at a time.
  • Progress: If no process is in CS, a process requesting entry must enter.
  • Bounded Waiting: A process must not wait forever to enter CS.

Peterson's Solution

A software-based solution for two processes using two shared variables: flag[i] (intent to enter) and turn (whose turn).

Process i:
  flag[i] = true; turn = j;
  while (flag[j] && turn == j);
  // critical section
  flag[i] = false;
  // remainder section
Works for 2 processes. Not scalable. Relies on sequential consistency (guaranteed by hardware).

Synchronization Hardware

Test & Set Instruction

Atomic: reads old value and sets memory to true. Returns old value.

boolean test_and_set(boolean *lock) {
  boolean old = *lock;
  *lock = true;
  return old;
}

Swap Instruction

Atomically exchanges two values.

void swap(boolean *a, boolean *b) {
  boolean temp = *a; *a = *b; *b = temp;
}
Both are atomic — cannot be interrupted. Used to implement spinlocks.

Semaphores

A semaphore is an integer variable that, apart from initialization, is accessed only through two atomic operations: wait() (P) and signal() (V).

TypeValue RangeUse
Binary (Mutex)0 or 1Mutual exclusion for a single resource
Counting0, 1, 2, ...Managing a pool of identical resources

Wait (P) Operation

wait(S) {
  while (S <= 0); // busy wait
  S--;
}

Signal (V) Operation

signal(S) {
  S++;
}
Semaphore operations must be atomic. Use hardware support (test-and-set) or disable interrupts.

Classical IPC Problems

Producer-Consumer (Bounded Buffer)

Producer produces items, consumer consumes them. Shared buffer of fixed size. Needs 2 semaphores: empty (counts empty slots) and full (counts filled slots), plus mutex for buffer access.

Reader-Writer Problem

Multiple readers allowed simultaneously; only one writer at a time. Needs: mutex (read count access), wrt (writer access), readcount variable.

Reader-Writer can starve writers. Use read-preference, write-preference, or fair variants.

Dining Philosophers

5 philosophers, 5 chopsticks. Each needs 2 adjacent chopsticks to eat. Can deadlock if all pick left then right. Solutions: limit to 4 philosophers, odd/even pickup order, arbitrator (butler) semaphore.

Deadlock

Characterization — Four Necessary Conditions

ALL four must hold simultaneously for deadlock:

  1. Mutual Exclusion: At least one resource is non-sharable.
  2. Hold & Wait: Process holding resources requests new ones.
  3. No Preemption: Resources cannot be forcibly taken from a process.
  4. Circular Wait: Circular chain of processes, each waiting for next's resource.
If ANY of the 4 conditions is broken, deadlock is impossible. This is the basis for prevention.

Deadlock Handling Methods

MethodApproachTrade-off
PreventionBreak one or more necessary conditionsMay reduce system concurrency
AvoidanceBanker's Algorithm — only grant if safe state maintainedRequires advance knowledge of max needs
DetectionAllow deadlock; periodically check resource allocation graphOverhead of detection + recovery
RecoveryProcess termination or resource preemption after detectionMay lose work, complex to implement

Banker's Algorithm

A deadlock avoidance algorithm. Named after banking — never allocate funds in unsafe state.

Data Structures (for n processes, m resource types):

  • Available[m] — available instances of each resource type
  • Max[n][m] — maximum demand of each process
  • Allocation[n][m] — currently allocated
  • Need[n][m] = Max − Allocation — remaining need

Safety Algorithm

  1. Initialize Work = Available, Finish[i] = false for all i.
  2. Find a process i such that Finish[i] = false AND Need[i] ≤ Work.
  3. If found: Work = Work + Allocation[i], Finish[i] = true, go to step 2.
  4. If all Finish[i] = true, system is safe. Otherwise unsafe.
A safe state means there exists at least one sequence of process completions. An unsafe state does not guarantee deadlock but makes it possible.

Resource Request Algorithm (for process Pi)

  1. If Request[i] ≤ Need[i] → proceed. Else error (process exceeds max claim).
  2. If Request[i] ≤ Available → proceed. Else Pi waits.
  3. Pretend to allocate: Available -= Request[i], Allocation[i] += Request[i], Need[i] -= Request[i].
  4. Run safety check. If safe → commit allocation. If unsafe → rollback and Pi waits.

Resource Allocation Graph (RAG)

Graph with process nodes (circles) and resource nodes (dots/rectangles). Edges: assignment (resource → process) and request (process → resource).

  • No cycles → No deadlock (if each resource has only one instance).
  • Cycle exists → Possible deadlock (certain if single-instance resources).

Memory Management

Memory Allocation Strategies

Contiguous Allocation

  • Fixed Partitioning: Memory divided into fixed-size partitions. One process per partition. Causes internal fragmentation.
  • Variable Partitioning: Partitions created dynamically based on process size. Causes external fragmentation.
Internal Fragmentation = Allocated − Used (wasted within partition)
External Fragmentation = Total free memory − Largest free block

Solutions to External Fragmentation

  • Compaction: Shift processes in memory to consolidate free space. Expensive.
  • Paging / Segmentation: Non-contiguous allocation (eliminates external fragmentation).

Paging

Physical memory divided into frames (fixed size). Logical memory divided into pages (same size). Page table maps page number → frame number.

Physical Address = (Frame Number × Frame Size) + Offset
Logical Address = (Page Number × Page Size) + Offset

Translation Lookaside Buffer (TLB)

  • A small, fast associative register cache for page table entries.
  • TLB hit: Fast translation. TLB miss: Walk page table in memory.
  • Effective Access Time (EAT):
EAT = (1 − α) × m + α × (m + s)
= m + α × s
where α = TLB hit ratio, m = memory access time, s = TLB search time

Page Table Structures

StructureDescription
Single-levelOne large table per process. High memory overhead for large address spaces.
Multi-levelHierarchical page tables. Outer table indexed, then inner. Reduces memory for sparse address spaces.
Inverted Page TableOne entry per frame (not per page). Saves memory but requires hash/search to find page.
Hashed Page TablePage number hashed → bucket → linked list of PTEs. Common in 64-bit systems.

Segmentation

Program divided into segments (logical units: code, data, stack). Each segment has a name and length. Segment table maps segment number → (base, limit).

Physical Address = Segment Table Base + Offset
(must check: Offset < Limit)

Paging vs Segmentation

AspectPagingSegmentation
DivisionFixed-size pagesVariable-size segments
ViewPhysical (user unaware)Logical (visible to user)
FragmentationInternalExternal
Address1-dimensional2-dimensional (segment + offset)

Segmented Paging

Combine both: logical address = segment → page → frame. Provides both logical grouping and fixed-size blocks.

Virtual Memory

Virtual Memory allows a process to execute even when not entirely in physical memory. Uses demand paging — pages loaded only when needed.

Page Fault

Trap to OS when a referenced page is not in memory (valid-invalid bit = invalid).

EAT (with page faults) = (1 − p) × m + p × (page fault service time + m)
= m + p × f
where p = page fault rate, f = page fault service time

Page Fault Service Time Steps

  1. OS checks PCB and determines valid reference / illegal access.
  2. Find a free frame (or use replacement algorithm).
  3. Schedule disk read to bring page into frame.
  4. OS updates page table and TLB.
  5. Restart the instruction.

Page Replacement Algorithms

AlgorithmDescriptionNotes
FIFOReplace oldest page (first in)Belady's anomaly: more frames → more faults
Optimal (OPT)Replace page used farthest in futureUnrealizable; used as benchmark lower bound
LRUReplace least recently used pageGood approximation of Optimal; needs counter or stack
LFUReplace page with lowest reference countDoes not age well; once popular stays popular
MFUReplace page with highest reference countRarely used

LRU Counter Implementation

Each page has a counter. On every memory reference, set counter = current clock. Replace page with smallest counter value.

LRU via Stack

Maintain stack of page numbers. Top = most recently used. Move referenced page to top. Replace bottom page.

FIFO is easy to implement but poor. LRU is near-optimal but costly. OPT is theoretical best. Always calculate Belady's anomaly for FIFO.

Thrashing

Thrashing occurs when a process spends more time swapping pages in/out than executing. Caused when degree of multiprogramming is too high.

Working Set Model: For a process, the working set W(t, Δ) = pages referenced in the last Δ time units. OS ensures enough frames to hold the working set of all processes. If not → thrashing.

Solutions to Thrashing

  • Local replacement: Process replaces its own pages (doesn't affect others).
  • Working set model: Track working set size; swap out if working set > allocated frames.
  • Page Fault Frequency (PFF): Set upper and lower bounds on page fault rate.

File System & Disk Management

File Concepts

A file is a named collection of related information recorded on secondary storage.

File Attributes

  • Name (human-readable), Identifier (unique OS ID, e.g., inode number)
  • Type (executable, text, directory, etc.)
  • Location (pointer to file on device)
  • Size (current and maximum)
  • Protection (access-control info)
  • Time, Date, User Identification (audit info)

File Operations

create, open, close, read, write, append, delete, truncate, seek, get/set attributes.

File Access Methods

MethodDescriptionUse Case
SequentialRead/write in order; read-next advances pointerTape, streaming
Direct / RandomJump to any block directly via block numberDatabases, disks
IndexedIndex block with pointers to all data blocksMulti-index (UNIX inode)

Acyclic-Graph Directory

Allows shared files/subdirectories via hard links or aliasing. A file can have multiple paths. Deletion requires reference counting — only delete when last reference is removed.

File Allocation Methods

MethodAdvantageDisadvantage
ContiguousSimple, fast sequential + random accessExternal fragmentation, file growth problem
LinkedNo external fragmentation, easy file growthNo random access, pointer overhead, reliability
IndexedSupports direct access, no external fragOverhead of index block; large files need multi-level
Linked allocation's FAT (File Allocation Table) in FAT32 is a special case — table stored at disk start for fast lookup.

Disk Structure

A disk consists of platters, each divided into tracks, further divided into sectors. A cylinder = all tracks at same radius across all platters.

Disk Access Time Components

Access Time = Seek Time + Rotational Latency + Transfer Time
Seek Time = moving the head to the correct track
Rotational Latency = waiting for sector to rotate under head
Transfer Time = actually reading/writing data

Disk Scheduling Algorithms

Goal: Minimize seek time. Head starts at some position, services requests in queue.

AlgorithmDescriptionProsCons
FCFSServe in arrival orderFair, simplePoor performance, high seek time
SSTFServe nearest track (greedy)Better than FCFSStarvation possible
SCANHead moves in one direction, services all, reversesUniform wait timeLong wait at ends
C-SCANHead moves in one direction, jumps back to startMore uniform than SCANNo reverse services
LOOKLike SCAN but stops at last request (not end)EfficientSame as SCAN otherwise
C-LOOKLike C-SCAN but stops at last requestMost efficientSame as C-SCAN otherwise
C-LOOK is generally the best. Always draw the head movement diagram to compute total seek distance.

UNIX & Linux Internals

UNIX File System Structure

The UNIX file system is a hierarchical tree with root at /. Every file has a unique inode number.

/ (root)
├── bin/       — user commands and utilities
├── etc/       — system configuration files
├── home/      — user home directories
├── dev/       — device files
├── lib/       — shared libraries
├── tmp/       — temporary files
├── usr/       — secondary hierarchy
│   ├── bin/   — more commands
│   ├── lib/   — more libraries
│   └── src/   — source code
└── var/       — variable data (logs, mail)

Inode

An inode (index node) is a data structure that stores metadata about a file (everything except the filename).

Fields in an Inode

  • File type: Regular file, directory, symbolic link, device, socket.
  • Owner information: User ID, group ID.
  • Permissions: Read (r), Write (w), Execute (x) for owner, group, others.
  • Timestamps: atime (access), mtime (modify), ctime (inode change).
  • Size: File size in bytes.
  • Link count: Number of directory entries pointing to this inode.
  • Pointers: Direct (10), Single indirect, Double indirect, Triple indirect block pointers.
The filename is NOT in the inode. It is stored in the directory, which maps names to inode numbers. Multiple names can point to the same inode (hard links).

File Descriptors

A file descriptor is a non-negative integer that the kernel uses to identify an open file for a process.

  • Each process has a per-process file descriptor table in its PCB.
  • Entries 0, 1, 2 are reserved by convention: 0 = stdin, 1 = stdout, 2 = stderr.
  • Each entry points to a system-wide open file table entry (shared across processes).
  • The open file table entry points to the inode of the file.
When a process forks(), child gets copy of descriptor table pointing to same open file entries (shared file offset unless O_APPEND).

Shell Basics

The shell is a command-line interpreter that provides a user interface to the OS kernel.

  • Bash (/bin/bash): Bourne-Again SHell — most common default shell.
  • Shell script: Program written in shell language (shebang: #!/bin/bash).
  • I/O Redirection: > (overwrite), >> (append), < (input), 2> (stderr).
  • Piping: cmd1 | cmd2 — stdout of cmd1 feeds stdin of cmd2.
  • Environment variables: export VAR=value, accessed as $VAR.
  • Wildcards: * (any), ? (single char), [...] (character class).

Protection & Security

Protection Goals

Protection ensures that resources are used only as intended by authorized programs/users. The four key goals:

  1. Confidentiality: No unauthorized reading of resources.
  2. Integrity: No unauthorized modification of resources.
  3. Availability: Resources available to authorized users when needed.
  4. Authenticity: Verify identity of users and source of data.

Protection Domains & Matrix

A protection domain is a set of (object, access right) pairs. Each process executes within a domain.

  • Objects: Files, devices, memory segments, processes.
  • Access Rights: Read (r), Write (w), Execute (e), Create, Delete.
  • A process can switch domains via domains switches (e.g., system call to kernel domain).

Protection Matrix

A matrix where rows = domains and columns = objects. Entry (i,j) = access rights of domain i to object j.

  • Access Control List (ACL): Column-oriented — list of (domain, rights) for each object.
  • Capability List: Row-oriented — list of (object, rights) for each domain.
Capability = unforgeable token granting specific rights. A process presents its capability list to access objects.

Security Threats & Types

VirusAttaches to executable files; spreads when file runsReplicates, corrupts, steals data

Attack Types

  • Denial of Service (DoS): Overwhelm resources to make service unavailable.
  • Man-in-the-Middle: Intercept and possibly alter communications.
  • SQL Injection: Inject malicious SQL through user input.
  • Phishing: Trick users into revealing sensitive info via fake communications.

Authentication Methods

Authentication verifies the identity of a user, process, or system.

Password-basedSomething you knowSimple, ubiquitousWeak if reused/simple

Common Encryption

  • Symmetric: Same key for encrypt/decrypt (AES, DES). Fast but key distribution problem.
  • Asymmetric: Public key + private key (RSA, ECC). Slow, solves key distribution.
  • Hashing: One-way function (SHA-256, MD5). For integrity verification, not encryption.
Salt + hash for password storage. Never store plaintext or reversible-encrypted passwords.

Common Exam Mistakes to Avoid

  • Confusing turnaround time (CT − AT) with waiting time (TAT − BT).
  • Forgetting to include arrival time in TAT calculations when processes arrive at different times.
  • Mixing up preemptive (SRTF, Priority with preemption, RR) vs non-preemptive (FCFS, SJF non-preemptive, Priority non-preemptive) scheduling.
  • Confusing internal fragmentation (inside allocated block) vs external fragmentation (free but unusable holes).
  • Forgetting that demand paging is the mechanism for virtual memory — not paging itself.
  • Mixing up page fault rate (p) with page fault frequency — they're related but different concepts.
  • Confusing seek time (head movement) with rotational latency (waiting for sector).
  • Confusing ACL (column-oriented, per-object) with capability list (row-oriented, per-domain).
  • Forgetting that mutual exclusion alone is not enough for the critical section problem — need progress and bounded waiting too.
  • Confusing Belady's anomaly (FIFO: more frames → more faults) with normal behavior (more frames should reduce faults).

Practice Questions — All Groups

Group A — 1 Mark Questions (Very Short Answer)

Q: What is an Operating System?

An Operating System is a system software that acts as an intermediary between the user and the computer hardware. It provides an environment in which users can execute programs conveniently and efficiently.

Q: What is a Process?

A process is a program in execution. It is an active entity, unlike a program which is a passive set of instructions stored on disk.

Q: What is a PCB?

Process Control Block (PCB) is a data structure maintained by the OS for each process, containing its state, PID, program counter, CPU registers, and scheduling information. Also called Task Control Block (TCB).

Q: What are the four necessary conditions for deadlock?

Mutual Exclusion, Hold and Wait, No Preemption, and Circular Wait. All four must hold simultaneously for a deadlock to occur.

Q: What is a semaphore?

A semaphore is an integer variable used for synchronization, accessed only through two atomic operations: wait() (P) and signal() (V). Types: binary (0 or 1) and counting.

Q: What is thrashing?

Thrashing is a condition where a process spends more time swapping pages in and out of memory than executing its actual instructions, caused by excessive multiprogramming.

Q: What is Belady's anomaly?

Belady's anomaly is the counterintuitive phenomenon where increasing the number of page frames available to a process increases the number of page faults. It occurs with the FIFO page replacement algorithm.

Q: What is an inode?

An inode (index node) is a data structure in UNIX/Linux file systems that stores all metadata about a file except its filename — type, permissions, owner, size, timestamps, and pointers to data blocks.

Q: What is a system call?

A system call is the programmatic way for a program to request a service from the OS kernel. It switches CPU from User Mode to Kernel Mode via a trap (software interrupt).

Q: Name the three types of schedulers in an OS.

Long-term scheduler (Job Scheduler), Short-term scheduler (CPU Scheduler), and Medium-term scheduler (Swapper).

Q: What is the critical section problem?

The critical section problem requires ensuring that when multiple processes share data, only one process executes in its critical section at a time, satisfying mutual exclusion, progress, and bounded waiting.

Q: What is TLB?

Translation Lookaside Buffer (TLB) is a small, fast associative register cache that stores recently used page table entries to speed up virtual-to-physical address translation.

Group B — 5 Mark Questions (Short Answer)

Q: Explain the different types of operating systems with examples.

Batch OS: Groups similar jobs together and processes them without user interaction. Examples: IBM OS/360. Advantage: efficient resource use. Disadvantage: no interactivity.

Multiprogramming OS: Keeps multiple programs in memory simultaneously; when one process waits for I/O, the CPU switches to another. This increases CPU utilization. Examples: Unix, Windows.

Time-Sharing OS: CPU time is divided into small slices called time quanta. Each process gets a quantum, then the scheduler switches. Provides quick response to users. Examples: Linux, Unix.

Distributed OS: Manages resources across a network of computers. Users access remote resources as if local. Examples: Amoeba, LOCUS.

Real-Time OS (RTOS): Designed for time-critical tasks. Hard real-time (deadline misses = failure, e.g., aircraft control) and soft real-time (deadline misses degrade quality, e.g., streaming). Examples: VxWorks, RTLinux.

Q: Explain the process state diagram. What are the different states a process can be in?

A process moves through several states during its lifetime:

New: Process is being created. OS allocates PCB and initializes.
Ready: Process is loaded in memory and waiting for CPU. Multiple ready processes are queued.
Running: Process is currently executing on the CPU.
Waiting (Blocked): Process is waiting for an event (I/O completion, signal). It cannot proceed until the event occurs.
Terminated (Exit): Process has finished execution. OS reclaims its resources and deletes the PCB.

Transitions: New → Ready (admitted), Ready → Running (dispatcher assigns CPU), Running → Ready (time slice expires or interrupt), Running → Waiting (I/O request), Waiting → Ready (I/O complete), Running → Terminated (exit). The 7-state model adds Ready-Suspend and Block-Suspend for swapped-out processes.

Q: Describe the Banker's Algorithm for deadlock avoidance.

The Banker's Algorithm is a deadlock avoidance algorithm. It simulates resource allocation and only grants requests if the resulting state is guaranteed to be safe.

Data Structures (n processes, m resource types):
- Available[m]: Available instances of each resource type.
- Max[n][m]: Maximum demand of each process.
- Allocation[n][m]: Currently allocated resources.
- Need[n][m] = Max - Allocation: Remaining need.

Safety Algorithm:
1. Initialize Work = Available, Finish[i] = false for all i.
2. Find a process i such that Finish[i] = false AND Need[i] ≤ Work.
3. If found: Work = Work + Allocation[i], Finish[i] = true, repeat step 2.
4. If all Finish[i] = true → system is safe. Otherwise → unsafe.

A safe state means there exists at least one sequence of process completions. A safe sequence is an ordering where each process can finish with currently available resources plus those freed by previously finished processes.

Q: Compare FCFS, SJF, and Round Robin scheduling algorithms.

FCFS (First-Come First-Served): Non-preemptive. Processes execute in order of arrival. Simple to implement with FIFO queue. Main drawback: convoy effect — short processes wait behind long ones. Average waiting time can be very high. Not optimal.

SJF (Shortest Job First): Selects process with smallest next CPU burst. Can be non-preemptive or preemptive (SRTF). Optimal algorithm — minimizes average waiting time among all deterministic algorithms. Problem: difficult to predict burst time in advance; can cause starvation for long processes.

Round Robin (RR): Preemptive. Each process gets a fixed time quantum. After quantum expires, process goes to back of ready queue. Designed for time-sharing. If quantum is too large → behaves like FCFS. If too small → excessive context switch overhead. Rule: quantum should be 70-80% of context switch time ratio.

Comparison: SJF is optimal for average waiting time, RR is fairest for time-sharing, FCFS is simplest but least efficient.

Q: Explain the concept of virtual memory and demand paging.

Virtual Memory is a memory management technique that allows a process to execute even when it is not entirely resident in physical memory. It gives each process the illusion of having its own large contiguous memory space.

Demand Paging is the mechanism that implements virtual memory. A page is loaded into physical memory only when it is actually referenced (demanded). Pages not needed are kept on disk.

Each page has a valid-invalid bit in the page table. Valid = page is in memory. Invalid = page is on disk.

When a process references an invalid page, a page fault trap occurs. The OS then: (1) checks the reference is valid, (2) finds a free frame (or uses page replacement), (3) schedules disk read to load the page, (4) updates page table and TLB, (5) restarts the instruction.

Effective Access Time: EAT = (1-p) × m + p × (page fault service time + m) = m + p × f, where p is page fault rate and f is fault service time.

Q: Compare paging and segmentation.

Paging: Physical memory is divided into fixed-size frames, logical memory into equal-size pages. Page table maps page number to frame number. The user/view sees a linear (1-dimensional) address. Causes internal fragmentation. OS-managed; user is unaware of pages.

Segmentation: Logical memory divided into variable-size segments (code, data, stack, heap). Each segment has a name and length. Segment table maps (segment number, offset) to (base, limit). The user/view sees a 2-dimensional address space (segment + offset). Causes external fragmentation. Logical grouping is visible to the user/programmer.

Segmented Paging combines both: logical address = segment number → page number → frame number. The segment table points to page tables. This provides both logical grouping and fixed-size allocation, eliminating external fragmentation while maintaining user-visible segments.

Q: Explain deadlock prevention and avoidance methods.

Deadlock Prevention ensures that at least one of the four necessary conditions is never satisfied:
- Break Mutual Exclusion: Make resources sharable (not always possible).
- Break Hold and Wait: Require processes to request all resources at once (all-or-nothing).
- Break No Preemption: Allow OS to preempt resources from processes.
- Break Circular Wait: Impose a total ordering on resource types; processes must request in increasing order.

Deadlock Avoidance (Banker's Algorithm) allows requests only if the resulting state is safe. Requires advance knowledge of maximum resource needs for each process. Simulates allocation and runs the safety algorithm to check if a safe sequence exists. Less restrictive than prevention but requires a priori information.

Prevention is conservative — it may reduce concurrency. Avoidance is more flexible but needs runtime checks.

Group C — 15 Mark Questions (Long Answer)

Q: Describe the functions and types of operating systems. Explain in detail the views of OS (user view and system view) and the different types of OS with examples.

Views of an Operating System:

From the User View, the OS is a convenience provider. Users care about usability, interface, response time, and resource availability — not about CPU cycles or memory management details. The goal is to make the computer easy and convenient to use.

From the System View, the OS is a resource allocator and control program. It manages CPU, memory, I/O devices, and data among competing processes. It acts as a control program that supervises user program execution to prevent errors and improper use of the computer.

Functions of an OS:
1. Process Management: Creating, scheduling, synchronizing, and terminating processes. Includes context switching and inter-process communication.
2. Memory Management: Allocating and deallocating memory space to processes, tracking which parts are in use, and implementing virtual memory.
3. File System Management: Storing, retrieving, organizing, and protecting files on secondary storage.
4. Device Management: Managing I/O devices through device drivers, handling interrupts, and buffering.
5. Security and Protection: Preventing unauthorized access to resources and ensuring data integrity.
6. Job Scheduling: Deciding which job to execute next from the job queue.
7. Error Detection: Handling hardware and software errors to maintain system stability.

Types of Operating Systems:

1. Batch Operating Systems: Users submit jobs offline (punched cards). Jobs with similar requirements are grouped into batches. No user interaction during execution. Examples: IBM OS/360. Advantage: high throughput. Disadvantage: no interactivity, difficult debugging.

2. Multiprogramming Operating Systems: Multiple programs reside in memory simultaneously. When a process waits for I/O, the CPU switches to another process. This keeps the CPU busy and increases utilization. Examples: Unix, Windows.

3. Time-Sharing Operating Systems: CPU time is divided into time slices (quantum). Each process gets a small quantum, then the scheduler rotates to the next. Uses a clock interrupt. Provides quick response and fairness. Examples: Linux, Unix. A time-sharing system is essentially a multiprogramming system with a quantum-based scheduler.

4. Distributed Operating Systems: Resources are spread across multiple networked computers. Users access remote resources as if they were local. Provides transparency, fault tolerance, and resource sharing. Examples: Amoeba, LOCUS.

5. Real-Time Operating Systems (RTOS): Designed for applications with strict timing constraints. Hard real-time systems (missed deadline = system failure): aircraft control, medical systems. Soft real-time systems (missed deadline degrades quality): streaming, video conferencing. Examples: VxWorks, RTLinux.

6. Network Operating Systems: Manage resources across a network. Provide user authentication, file sharing, and printing services. Examples: Windows Server, Linux with NFS.

Q: Explain process scheduling in detail. Describe FCFS, SJF, Priority, and Round Robin scheduling algorithms with worked examples. Include the key scheduling formulas and Gantt chart construction.

Process Scheduling is the activity of the short-term (CPU) scheduler that selects a process from the ready queue to execute on the CPU next. The goal is to maximize CPU utilization, throughput, and fairness while minimizing waiting time, turnaround time, and response time.

Key Formulas:
- Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT)
- Waiting Time (WT) = TAT − Burst Time (BT) = CT − AT − BT
- Response Time (RT) = First response − Arrival Time
- Throughput = Number of processes completed / Total time
- Average WT = ΣWT / n   |   Average TAT = ΣTAT / n

1. FCFS (First-Come First-Served): Non-preemptive. Processes served in arrival order using a FIFO queue. Simple to implement but suffers from the convoy effect — a long CPU-bound process delays all subsequent short processes. Average waiting time depends heavily on arrival order.
Example: P1(AT=0, BT=24), P2(AT=0, BT=3), P3(AT=0, BT=3). Gantt chart: P1(0→24) | P2(24→27) | P3(27→30). Avg WT = (0 + 24 + 27) / 3 = 17 units.

2. SJF (Shortest Job First): Selects the process with the smallest next CPU burst. Optimal — minimizes average waiting time among all deterministic algorithms. Two variants: non-preemptive (process runs to completion once started) and preemptive (SRTF — Shortest Remaining Time First, new shorter job preempts running process). Main challenge: predicting burst time. Typically estimated using exponential averaging: S(n+1) = α × t(n) + (1−α) × S(n).
SRTF Example: P1(0,8), P2(1,4), P3(2,9), P4(3,5). Gantt: P1(0→1) | P2(1→5) | P4(5→10) | P3(10→19). Avg TAT = (19−0 + 5−1 + 19−2 + 10−3)/4 = 37/4 = 9.25.

3. Priority Scheduling: Each process assigned a priority. The scheduler selects the highest-priority process (or lowest priority number). Can be preemptive or non-preemptive. Major problem: starvation — low-priority processes may never execute if high-priority processes keep arriving. Solution: aging — gradually increase the priority of waiting processes over time.

4. Round Robin (RR): Preemptive, designed for time-sharing. Each process gets a fixed time quantum (q) in a cyclic order. If process doesn't finish in its quantum, it is preempted and placed at the end of the ready queue. Rule of thumb: q should be large compared to context switch overhead but small compared to typical CPU burst (q ≈ 70-80% of context switch ratio). If q is too large → FCFS behavior. If q is too small → excessive context switches degrade performance.
Example: P1(BT=10), P2(BT=5), P3(BT=15), q=4. Gantt: P1(0→4)|P2(4→9)|P3(9→13)|P1(13→17)|P2(17→19)|P3(19→23)|P1(23→24)|P3(24→28). TATs: 24, 15, 19. Avg TAT = 58/3 = 19.33.

How to Draw a Gantt Chart: Always draw the Gantt chart first — it shows exactly when each process runs. From the Gantt chart, CT for each process is the end of its last burst. Then TAT = CT − AT, WT = TAT − BT. For preemptive algorithms, a process may appear in multiple segments on the Gantt chart.

Q: Explain in detail the memory management techniques: paging, page replacement algorithms (FIFO, LRU, Optimal), and thrashing. Include the TLB effective access time formula, Belady's anomaly, and the working set model.

Paging:
Physical memory is divided into fixed-size blocks called frames (typically 4KB or 8KB). Logical memory is divided into equal-size blocks called pages. A page table maps each page number to its corresponding frame number. Address translation: Logical Address = (Page Number × Page Size) + Offset; Physical Address = (Frame Number × Frame Size) + Offset. Paging eliminates external fragmentation but introduces internal fragmentation (last page may not be full).

Translation Lookaside Buffer (TLB): A small, fast associative memory cache that holds recently used page table entries. Without TLB, every memory reference requires two memory accesses (one for page table, one for data). With TLB, a hit requires only one. The Effective Access Time (EAT) is:
EAT = (1 − α) × m + α × (m + s) = m + α × s
where α = TLB hit ratio, m = memory access time, s = TLB search time. With 98% hit ratio and m=100ns, s=10ns: EAT = 100 + 0.98 × 10 = 109.8ns (vs 200ns without TLB).

Page Replacement Algorithms: When a page fault occurs and no free frame exists, the OS must replace an existing page.

FIFO (First-In First-Out): Replace the oldest page in memory. Easy to implement using a queue. Belady's anomaly: increasing frames can increase page faults. Example: reference string 1,2,3,4,1,2,5,1,2,3,4,5 with 3 frames → 9 faults; with 4 frames → 10 faults.

Optimal (OPT/MIN): Replace the page whose next use is farthest in the future. This gives the minimum possible page faults. Not implementable in practice (requires future knowledge) but serves as a theoretical benchmark.

LRU (Least Recently Used): Replace the page that has not been used for the longest time. Approximation of Optimal. Implementations: (1) Counter method — each page has a counter updated on every reference; replace smallest counter. (2) Stack method — maintain a doubly-linked stack; top = most recently used, bottom = LRU. LRU with the same reference string above gives 8 faults (better than FIFO).

Thrashing: Occurs when the degree of multiprogramming is too high. Processes collectively need more frames than available, causing continuous page faults. The CPU spends most time swapping pages rather than executing. The working set of a process is the set of pages it has referenced in the last Δ time units: W(t, Δ). The OS must ensure that the sum of all working sets fits in physical memory.

Solutions to Thrashing:
1. Local replacement: Each process replaces only its own pages, limiting damage to one process.
2. Working set model: Monitor each process's working set size. If a process's working set exceeds its allocated frames, suspend it (swap out completely).
3. Page Fault Frequency (PFF): Set upper and lower bounds on page fault rate. If rate exceeds upper bound, allocate more frames. If below lower bound, reclaim frames.

Q: Explain disk scheduling algorithms in detail. Given a disk with 200 cylinders (0-199) and head starting at 50, with request queue [98, 183, 37, 122, 14, 124, 65, 67], calculate total head movement for FCFS, SSTF, SCAN, C-SCAN, LOOK, and C-LOOK. Also explain disk access time components.

Disk Structure and Access Time:
A disk consists of platters divided into concentric tracks, further divided into sectors. A cylinder = all tracks at the same radius across all platters. Disk access time has three components:
1. Seek Time: Moving the read/write head to the correct track. Dominant component.
2. Rotational Latency: Waiting for the desired sector to rotate under the head. Average = (1/2) × rotation time (e.g., ~4ms for 7200 RPM).
3. Transfer Time: Time to actually read/write data as the sector passes under the head.
Total Access Time = Seek Time + Rotational Latency + Transfer Time.

Disk Scheduling Algorithms (goal: minimize seek time):

Head starts at 50, moving towards higher numbers (standard assumption for SCAN/C-LOOK unless stated otherwise).

1. FCFS (First-Come First-Served):
Order: 50 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
Movement: 48 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = 643 cylinders
Simple but yields poor performance.

2. SSTF (Shortest Seek Time First):
Greedy — serve nearest request. Order: 50 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
Movement: 15 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = 239 cylinders
Better than FCFS but can cause starvation of distant requests.

3. SCAN (Elevator):
Head moves in one direction servicing all requests, then reverses. Order: 50 → 65 → 67 → 98 → 122 → 124 → 183 → (reverse) 37 → 14
Movement: 15 + 2 + 31 + 24 + 2 + 59 + (183 to 0, but stops at 37) → 183-37 = 146 + 23 = 332 cylinders

4. C-SCAN (Circular SCAN):
Head moves in one direction servicing all, then jumps back to start. Order: 50 → 65 → 67 → 98 → 122 → 124 → 183 → (jump to 0) → 14 → 37
Movement: 15 + 2 + 31 + 24 + 2 + 59 + (199-183) + 183 + 14 + 23 = 16+31+24+2+59+16+183+14+23 = 371 cylinders

5. LOOK:
Like SCAN but head only goes as far as the last request. Order: 50 → 65 → 67 → 98 → 122 → 124 → 183 → (reverse) 37 → 14
Movement: 15 + 2 + 31 + 24 + 2 + 59 + (183-37=146) + 23 = 302 cylinders

6. C-LOOK:
Like C-SCAN but head only goes to last request. Order: 50 → 65 → 67 → 98 → 122 → 124 → 183 → (jump to 14) → 37
Movement: 15 + 2 + 31 + 24 + 2 + 59 + (183-14=169) + 23 = 325 cylinders

Summary:
FCFS: 643 | SSTF: 239 | SCAN: 332 | C-SCAN: 371 | LOOK: 302 | C-LOOK: 325

SSTF is most efficient in seek distance but has starvation risk. LOOK and C-LOOK are the most practical choices in real systems (used by Linux). C-LOOK provides the most uniform wait time.

Q: Describe in detail the classical inter-process communication (IPC) problems: Producer-Consumer, Reader-Writer, and Dining Philosophers. Include semaphore-based solutions for each.

Synchronization is required when multiple processes share data. The goal is to ensure consistency of shared data and coordinate process execution. Semaphores provide a clean mechanism for this.

1. Producer-Consumer (Bounded Buffer):
A producer process produces items and puts them into a shared buffer of fixed size. A consumer process consumes items from the buffer. The buffer is a circular queue. Three semaphores are used:
- empty: Counting semaphore, initialized to buffer size (number of empty slots).
- full: Counting semaphore, initialized to 0 (number of filled slots).
- mutex: Binary semaphore, initialized to 1 (mutual exclusion for buffer access).

Producer:
while (true) {
  wait(empty); // wait for empty slot
  wait(mutex); // enter critical section
  // add item to buffer
  signal(mutex); // leave critical section
  signal(full); // increment full count
}

Consumer:
while (true) {
  wait(full); // wait for filled slot
  wait(mutex);
  // remove item from buffer
  signal(mutex);
  signal(empty);
}
Key insight: empty and full must be used before mutex to ensure proper ordering and avoid deadlock.

2. Reader-Writer Problem:
Multiple readers can read simultaneously, but only one writer can write at a time (and no readers during writing). Uses: mutex (binary, protects readcount), wrt (binary, for writer access), readcount (integer, number of active readers).

Reader:
while (true) {
  wait(mutex);
  readcount++;
  if (readcount == 1) wait(wrt); // first reader locks writers
  signal(mutex);
  // READING
  wait(mutex);
  readcount--;
  if (readcount == 0) signal(wrt); // last reader unlocks
  signal(mutex);
}

Writer:
while (true) {
  wait(wrt);
  // WRITING
  signal(wrt);
}
Problem: writer starvation — if readers keep arriving, writers may never get access. Solutions: read-preference (as above), write-preference (new readers wait if writer is waiting), or fair (FIFO) variants.

3. Dining Philosophers:
Five philosophers sit around a table with one chopstick between each pair. Each philosopher alternates between thinking and eating. A philosopher needs both adjacent chopsticks to eat. Problems: (a) Deadlock — if all pick up left chopstick simultaneously, no one can pick up right. (b) Starvation — one philosopher never gets both chopsticks.

Solutions:
- Limit to 4 philosophers: At most 4 can be hungry simultaneously. At least one can eat, releasing chopsticks.
- Odd-even pickup: Odd-numbered philosophers pick left first, even pick right first. Prevents circular wait.
- Butler (arbitrator) semaphore: A binary semaphore initialized to 4. Each philosopher does wait(butler) before picking chopsticks and signal(butler) after eating. Limits concurrent eaters to 4, breaking circular wait.

Q: Explain memory management in detail. Cover contiguous allocation, paging, segmentation, virtual memory with demand paging, and page replacement algorithms with numerical examples. Include formulas for EAT and fragmentation.

Contiguous Allocation:
In fixed partitioning, memory is divided into fixed-size partitions. Each partition holds one process. Causes internal fragmentation: Internal Fragmentation = Allocated Size − Used Size. Small processes waste entire partitions.

In variable (dynamic) partitioning, partitions are created based on process size. Causes external fragmentation: total free memory exists but is scattered in small unusable holes. External Fragmentation = Total Free Memory − Largest Free Block. Solutions: compaction (shift processes to consolidate free space — expensive) or use non-contiguous allocation (paging/segmentation).

Paging:
Divides physical memory into fixed-size frames and logical memory into same-size pages. A page table maps each page number to a frame number. Logical Address = (Page Number × Page Size) + Offset. Physical Address = (Frame Number × Frame Size) + Offset. No external fragmentation; internal fragmentation limited to less than one page.

Page table structures: Single-level (simple but large), Multi-level (hierarchical, reduces memory for sparse spaces), Inverted (one entry per frame, saves memory), Hashed (for 64-bit systems).

TLB and EAT: EAT = m + α × s. Example: m=100ns, s=20ns, α=0.99. EAT = 100 + 19.8 = 119.8ns (vs 200ns without TLB).

Segmentation:
Divides program into variable-size logical segments (code, data, stack). Each segment has a base and limit. Physical Address = Segment Table Base + Offset (offset < limit checked). User-visible 2D address: (segment number, offset). Causes external fragmentation. Segmented paging combines both: segment number indexes a segment table that points to a page table.

Virtual Memory & Demand Paging:
Allows processes to execute without being fully in memory. Pages loaded on demand via page fault trap. Valid-invalid bit in PTE indicates whether page is in memory. Page fault service: check validity → find frame → disk read → update tables → restart.
EAT with page faults: EAT = m + p × f. Example: p=0.001 (0.1% fault rate), f=10ms, m=100ns. EAT = 100ns + 0.001 × 10,000,000ns = 10,100ns. Keeping p low is critical.

Page Replacement: When no free frame exists, replace a victim page. Reference string: 7,0,1,2,0,3,0,4,2,3,0,3,2 with 3 frames.
FIFO: Loads 7,0,1 → fault on 2 (replace 7) → fault on 3 (replace 0) → fault on 4 (replace 1) → fault on 2 (replace 3) → fault on 3 (replace 0) → fault on 2 (replace 4). Total: 12 faults.
OPT (look ahead): Replace page not used for longest. Total: 9 faults.
LRU: Replace least recently used. Total: 9 faults.

With 4 frames, FIFO gives 8 faults — fewer than with 3 frames. This is Belady's anomaly: more frames → more faults (FIFO only).

Thrashing: Caused by σ working set sizes > available frames. CPU spends time swapping instead of executing. Solutions: working set model (track Δ-time working set), page fault frequency (adjust frame allocation based on fault rate), local replacement (process replaces own pages).
