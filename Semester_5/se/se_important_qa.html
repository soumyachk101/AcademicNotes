Q1Explain Classical Waterfall Model phases, advantages, and limitations.

Detailed 5-Mark Solution:

1. Core Definition & Overview: The Classical Waterfall Model is a linear-sequential Software Development Life Cycle (SDLC) model where progress flows downwards like a waterfall through distinct phases: Requirements Analysis → System Design → Implementation → Testing → Deployment → Maintenance.

Figure: Classical Waterfall Model SDLC Execution Flow

2. Key Principles & Workflow:

  • Requirements Analysis: SRS document formulation and baseline verification.
  • System Design: Architectural design, module design, and database schema definition.
  • Implementation & Testing: Coding in targeted programming language followed by unit, integration, and system testing.
  • Phase Gate Rule: Each phase must be frozen and signed off before the next phase begins.

3. Limitations: Inflexible to changing requirements, high risk due to late working prototype delivery, and costly rework if errors are detected in testing.

Q2Explain Spiral Model quadrants and risk-driven approach.

Detailed 5-Mark Solution:

1. Core Definition & Overview: The Spiral Model (Barry Boehm) is a risk-driven software development process model combining iterative prototyping with systematic waterfall control.

Figure: Spiral Model SDLC Quadrants & Risk Analysis Flow

2. Four Spiral Quadrants:

  • Determine Objectives: Identify specific goals, alternatives, and constraints.
  • Identify & Resolve Risks: Detailed risk analysis, benchmarking, and prototyping.
  • Development & Testing: Code construction and system testing.
  • Plan Next Phase: Review customer feedback and plan next iteration spiral.

Q11Explain Cyclomatic Complexity calculation methods with flow graph example.

Detailed 5-Mark Solution:

1. Core Definition & Mathematical Formulas: McCabe's Cyclomatic Complexity V(G) measures the logical complexity of a control flow graph G = (V, E).

  • Formula 1 (Edges & Nodes): V(G) = E - N + 2P (where E = edges, N = nodes, P = connected components).
  • Formula 2 (Decision Nodes): V(G) = D + 1 (where D = number of predicate / decision nodes).
  • Formula 3 (Bounded Regions): V(G) = R (number of closed regions in planar flow graph + 1 outer region).

2. Significance: Determines the upper bound for the number of test cases required to achieve complete basis path coverage.

Q2a) Calculate Effort, Development Time, and Average Staffing for an Organic software project estimated at 32 KLOC using Basic COCOMO Model (a=2.4, b=1.05, c=2.5, d=0.38). b) Calculate Function Points for a system with 10 External Inputs (Simple), 12 External Outputs (Average), 8 External Inquiries (Complex), 4 Internal Logical Files (Average), 6 External Interface Files (Simple). Sum of Complexity Adjustment Factors ΣFi = 45.

15-Mark Master Exam Solution:

Part (a) Basic COCOMO Calculation:

Given software project size = 32 KLOC in Organic Mode (a = 2.4, b = 1.05, c = 2.5, d = 0.38).

  • 1. Effort (E):
    E = a × (KLOC)^b = 2.4 × (32)^1.05 = 2.4 × 38.051 = 91.32 Person-Months
  • 2. Development Time (Tdev):
    Tdev = c × (Effort)^d = 2.5 × (91.32)^0.38 = 2.5 × 5.548 = 13.87 Months
  • 3. Average Staffing (SS):
    SS = Effort / Tdev = 91.32 / 13.87 = 6.58 Persons (≈ 7 Persons)

Part (b) Function Point (FP) Computation Trace:

  • External Inputs (EI): 10 × 3 (Simple) = 30
  • External Outputs (EO): 12 × 5 (Average) = 60
  • External Inquiries (EQ): 8 × 6 (Complex) = 48
  • Internal Logical Files (ILF): 4 × 10 (Average) = 40
  • External Interface Files (EIF): 6 × 5 (Simple) = 30
  • Total Unadjusted Function Points (UFP) = 30 + 60 + 48 + 40 + 30 = 208
  • VAF (Value Adjustment Factor): VAF = 0.65 + (0.01 × ΣFi) = 0.65 + (0.01 × 45) = 1.10
  • Adjusted Function Points (FP): FP = UFP × VAF = 208 × 1.10 = 228.8 FP
