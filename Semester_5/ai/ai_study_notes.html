Unit 1: Introduction to AI & Intelligent Agents

1.1 What is Artificial Intelligence?

Artificial Intelligence (AI) is the science of making machines perform tasks that would normally require human intelligence. These include:

  • Learning — acquiring knowledge from data
  • Reasoning — drawing conclusions from facts
  • Perception — understanding images, speech, signals
  • Planning — choosing sequences of actions
  • Natural Language Understanding — interpreting human language

AI is a multi-disciplinary field drawing from computer science, mathematics, psychology, linguistics, neuroscience, philosophy, and economics.

1.2 Problems of AI

Major problems that AI addresses:

  1. Search and Planning — finding optimal solutions in combinatorial spaces
  2. Knowledge Representation — encoding information efficiently
  3. Reasoning under Uncertainty — probabilistic and fuzzy methods
  4. Machine Learning — automatically discovering patterns
  5. Natural Language Processing — understanding and generating text
  6. Computer Vision — interpreting visual information
  7. Robotics — physical interaction with the world
  8. Generalization and Transfer Learning

1.3 AI Technique

An AI technique is a method that exploits knowledge represented in a structured manner to enable efficient reasoning in complex situations. Key properties of AI techniques:

  • Use domain-specific knowledge instead of brute force
  • Operate on structured representations of facts and rules
  • Must be efficient enough for practical use
  • Should be scalable to large problem instances

Example: Medical diagnosis — instead of checking every possible disease (brute force), an expert system uses rules like "IF fever AND cough THEN possible infection" to reason efficiently.

1.4 Tic-Tac-Toe Problem

The Tic-Tac-Toe problem is a classic AI example demonstrating game-tree search.

  • Total states: $3^9 = 19,683$ (or $9! = 362,880$ considering symmetry)
  • Demonstrates: game tree, search, evaluation function
  • With perfect play, Tic-Tac-Toe is a draw — it is a "solved" game

1.5 Intelligent Agents

An agent is anything that perceives its environment through sensors and acts upon that environment through actuators.

Mathematical definition:

$$\text{Agent function: } f: P^* \to A$$

where $P^*$ is the set of percept sequences and $A$ is the set of actions.

Agent = Architecture + Agent Program

  • Architecture: The physical device (sensors, actuators, computational hardware)
  • Agent Program: The software that implements the agent function

1.6 Rationality

A rational agent is one that for every possible percept sequence, selects an action that maximizes its expected performance measure, given:

  1. The evidence from the percept sequence
  2. Any prior knowledge the agent has
  3. The actions it can perform

Rationality ≠ Omniscience. A rational agent maximizes expected performance based on what it knows.

1.7 PEAS Representation

PEAS defines the task environment of an agent:

  • Performance measure — How is success measured?
  • Environment — Where does the agent operate?
  • Actuators — How does the agent act?
  • Sensors — How does the agent perceive?

Example — Vacuum Cleaner Agent:

  • P: Clean floor, time taken
  • E: Room A, Room B, dirt locations
  • A: Wheels, vacuum pump
  • S: Location sensor, dirt sensor

1.8 Types of Agents

1.9 Simple Reflex Agent

The simplest agent type. Selects actions based only on the current percept, ignoring percept history.

Example rules:

  • IF (percept = dirty) THEN (action = suck)
  • IF (percept = clean) AND (location = A) THEN (action = move right)
  • IF (percept = clean) AND (location = B) THEN (action = move left)

Limitation: Cannot handle partial observability. For example, if the current square is clean but there is dirt two squares away, a simple reflex agent won't know to go there.

1.10 Model-Based Reflex Agent

Maintains an internal state that depends on the percept history and reflects at least some of the unobserved aspects of the current state.

Uses a world model: how the world evolves independently of the agent (transition model) and how the agent's actions affect the world (sensor model).

1.11 Goal-Based Agent

Uses goals to choose between multiple possibilities. It reasons about future actions, considering "what will happen if I do X?" — this is the key advantage over reflex agents.

The agent must consider sequences of actions and find a path that leads to the goal state.

Trade-off: Goal-based agents are more flexible but slower than reflex agents.

1.12 Utility-Based Agent

When there are multiple goals (often conflicting), or when there are multiple ways to achieve the same goal, a utility function maps each possible state to a real number representing how "good" the state is for the agent.

A utility-based agent chooses the action that maximizes expected utility. It enables rational decisions when:

  • Goals are not sufficient to determine the best action
  • Trade-offs between conflicting goals are needed
  • The probability of success is uncertain

1.13 Learning Agent

A learning agent improves its performance over time. It has four conceptual components:

  • Learning Element: Receives feedback and improves performance
  • Performance Element: Selects external actions (the agent itself)
  • Critic: Tells the learning element how well the agent is doing
  • Problem Generator: Suggests exploratory actions that lead to new experiences

This design allows agents to operate in unknown environments and improve automatically with experience.

1.15 Problem Solving as State Space Search

Search is the core technique for AI problem solving. It involves systematically exploring the space of possible solutions.

Components of a Search Problem:

  • Initial State: Where the agent starts
  • Actions: Available moves
  • Transition Model: $Result(s, a)$ — state after action $a$ in state $s$
  • Goal Test: Determines whether a state is a goal
  • Path Cost: Cost of a sequence of actions

The state space is a graph representation of all reachable states.

1.16 Example — 8-Puzzle Problem

  • States: Each tile arrangement
  • Initial State: Any arrangement
  • Actions: Move a tile into the blank (up/down/left/right)
  • Goal Test: Configuration matches goal state
  • Path Cost: Each move costs 1

Search tree branching factor: at most 4, average 3

State space size: $\frac{9!}{2} = 181,440$ reachable states

1.17 Production System

A production system is a computational framework consisting of:

  1. A set of production rules: IF (condition) THEN (action)
  2. A working memory / knowledge base: Stores current state
  3. A control strategy: Determines rule selection order

Conflict Resolution Strategies:

  • Specificity ordering: More specific rules first
  • Recency ordering: Recently used rules first
  • Rule ordering: Predefined priority

1.18 Problem Characteristics

  1. Decomposable: Can the problem be broken into sub-problems? (e.g., $a^2 \cdot b^2 = (a \cdot b)^2$)
  2. Solution steps ignorable: Can any path work? (Chess vs route planning)
  3. Problem universe predictable: Are outcomes certain?
  4. Solution quality measurable: Is there a clear measure?
  5. Internal structure: Is knowledge needed?
  6. Solution requires interaction: Must agent interact with world?

Unit 2: Search Techniques

2.1 Problem-Solving Agents

A problem-solving agent is a goal-based agent that searches for a sequence of actions leading to a goal state. It uses atomic representations (states are indivisible).

The process:

  1. Goal Formulation: What goals to pursue
  2. Problem Formulation: What actions and states to consider
  3. Search: Find a sequence of actions
  4. Execution: Carry out the actions

2.2 Search Algorithm Components

  • Search Tree: Generated during search
  • Search Node: A node in the tree (state + parent + action + path-cost + depth)
  • Frontier / Open List: Set of unexpanded nodes
  • Explored Set / Closed List: Set of expanded nodes (to avoid revisiting)
  • Expansion: Generating successors of a node

2.3 Search Strategy Evaluation

Four criteria to evaluate search strategies:

  1. Completeness: Does it find a solution if one exists?
  2. Optimality: Does it find the best (lowest-cost) solution?
  3. Time Complexity: How long does it take? (nodes generated/expanded)
  4. Space Complexity: How much memory? (nodes kept in memory)

Notation:

  • $b$ = branching factor
  • $d$ = depth of shallowest solution
  • $m$ = maximum depth of search tree
  • $l$ = depth limit

2.4 Breadth-First Search (BFS)

BFS expands nodes in order of depth — all nodes at depth $d$ are expanded before any at depth $d+1$. It uses a FIFO queue.

Complexity:

Time: $O(b^d)$, Space: $O(b^d)$

Complete: Yes | Optimal: Yes (for uniform step costs)

Algorithm:

from collections import deque
def bfs(start, goal_test):
    frontier = deque([start])
    explored = {start}
    while frontier:
        node = frontier.popleft()
        if goal_test(node):
            return node
        for child in expand(node):
            if child not in explored:
                explored.add(child)
                frontier.append(child)
    return None

Drawback: Memory grows exponentially with $b^d$. For $b=10, d=12$: ~28 GB needed.

2.5 Depth-First Search (DFS)

DFS expands the deepest unexpanded node first using a LIFO stack.

Complexity:

Time: $O(b^m)$, Space: $O(bm)$

Complete: No (infinite paths) | Optimal: No

def dfs(start, goal_test):
    frontier = [start]
    explored = set()
    while frontier:
        node = frontier.pop()
        if goal_test(node):
            return node
        if node not in explored:
            explored.add(node)
            for child in expand(node):
                frontier.append(child)
    return None

Pros: Very memory-efficient (only one path in memory at a time).

Cons: Can get stuck in long or infinite paths; not optimal.

2.6 Depth-Limited Search (DLS)

DLS is DFS with a depth limit $\ell$ to avoid infinite paths. If the depth limit is reached without finding a goal, it backtracks.

Properties:

  • Complete: Yes, if $\ell \geq d$
  • Optimal: Yes, if $\ell = d$ (and unit costs)
  • Time: $O(b^\ell)$, Space: $O(b\ell)$

Problem: Choosing $\ell$ requires some knowledge of the problem.

2.7 Iterative Deepening DFS (IDDFS)

IDDFS repeatedly runs DLS with increasing depth limits $\ell = 0, 1, 2, ...$ until a goal is found.

Properties:

  • Complete and optimal
  • Time: $O(b^d)$, Space: $O(bd)$

Although nodes are generated multiple times, the overhead is acceptable because most nodes are at the deepest level. IDDFS combines BFS's optimality with DFS's space efficiency.

2.8 Bidirectional Search

Runs two searches simultaneously — one forward from the initial state, one backward from the goal — and stops when they meet.

Time: $O(b^{d/2})$, Space: $O(b^{d/2})$

Requirements:

  • The reverse action must be defined: $Pred(s, a)$
  • Both searches must meet at a common state

2.10 Heuristic Functions

A heuristic function $h(n)$ estimates the cost of the cheapest path from $n$ to a goal.

Properties:

  • Admissible: $h(n) \leq h^*(n)$ (never overestimates actual cost)
  • Consistent (Monotonic): $h(n) \leq c(n, a, n') + h(n')$

Examples:

  • Manhattan Distance (8-puzzle): sum of horizontal+vertical distances of each tile from goal
  • Euclidean Distance (route finding): straight-line distance
  • Misplaced Tiles (8-puzzle): count of tiles in wrong position

Dominance: If $h_2(n) \geq h_1(n)$ for all $n$, then $h_2$ dominates $h_1$. For solvable problems with unit-cost actions, the heuristic with higher value gives better search efficiency.

2.11 Greedy Best-First Search

Greedy Best-First expands the node with the lowest $h(n)$ value — the node that appears closest to the goal.

$f(n) = h(n)$

Properties:

  • Complete: No (can get stuck in infinite loops)
  • Optimal: No
  • Time: $O(b^m)$, Space: $O(b^m)$ worst case

Example: For driving from Arad to Bucharest, use straight-line distance to Bucharest as heuristic. Greedy goes toward Bucharest but may miss optimal routes.

2.12 A* Search

A* combines path cost and heuristic estimate:

$$f(n) = g(n) + h(n)$$

where $g(n)$ is the actual cost from start to $n$ and $h(n)$ is the estimated cost from $n$ to goal.

Optimality Theorem: If $h(n)$ is admissible, A* is both complete and optimal.

Why optimal? Any suboptimal goal $G_2$ would have $f(G_2) = g(G_2) > f(G_1)$ where $G_1$ is optimal. A* would select $G_1$ before $G_2$ because every node expanded has $f(n) < f(G_2)$.

Consistent Heuristic + A* = Optimal without re-expansion

2.14 Memory-Bounded Heuristic Search

IDA* (Iterative Deepening A*): Uses f-cost as cutoff instead of depth. Each iteration is DLS with f-cost limit.

SMA* (Simplified Memory-Bounded A*): Uses all available memory. When memory is full, drops the worst leaf and writes it to disk. When generating a node already in memory, updates its cost. Recovers forgotten information when needed.

SMA* is optimally efficient — given $M$ memory, no algorithm using $M$ memory can expand fewer nodes than SMA*.

2.15 Hill Climbing Search

Hill climbing is a loop that keeps moving in the direction of increasing value until a peak is reached.

Algorithm:

def hill_climbing(problem):
    current = problem.initial_state()
    while True:
        neighbors = problem.expand(current)
        if not neighbors: return current
        neighbor = max(neighbors, key=problem.evaluate)
        if problem.evaluate(neighbor) <= problem.evaluate(current):
            return current
        current = neighbor

Problems:

  • Local Maxima: Better than neighbors but not global optimum
  • Ridges: Sequence of local maxima making navigation hard
  • Plateaux: Flat region; no uphill direction but not optimum

Variants:

  • Steepest-Ascent: Move to best of all neighbors
  • First-Choice: Move to first better neighbor found
  • Random-Restart: Run multiple times from random starts

2.16 Simulated Annealing

Simulated Annealing (SA) combines hill climbing with a random walk in a way that allows downhill moves to escape local maxima.

Acceptance Probability:

$$P(\text{accept bad move}) = e^{-\Delta E / T}$$

where $\Delta E > 0$ is the energy increase and $T$ is the current temperature.

Algorithm:

import random, math
def simulated_annealing(problem, schedule):
    current = problem.initial_state()
    for t in range(1, 100000):
        T = schedule(t)
        if T == 0: return current
        next_node = random.choice(problem.expand(current))
        delta_e = problem.evaluate(next_node) - problem.evaluate(current)
        if delta_e > 0 or random.random() < math.exp(delta_e / T):
            current = next_node

As $T \to 0$, SA behaves like hill climbing; as $T \to \infty$, it makes random moves.

2.17 Local Beam Search

Beam Search keeps track of $k$ states at each level. At each iteration, all successors of all $k$ states are generated, and the $k$ best are kept.

Stochastic Beam Search: Instead of always picking the $k$ best, sample $k$ successors with probability proportional to their evaluation — maintains diversity.

Beam Search helps when there are many paths of similar cost that can share information.

2.18 Genetic Algorithms

A genetic algorithm (GA) is a stochastic beam search variant with a population of size $k$ and generation operators inspired by evolution.

Steps per generation:

  1. Selection: Choose fit individuals for reproduction
  2. Crossover: Combine pairs to produce offspring
  3. Mutation: Randomly perturb offspring chromosomes
  4. Replacement: Replace weakest with offspring
import random

def fitness(chromosome):
    return sum(1 for i, c in enumerate(chromosome) if c == goal[i])

def crossover(p1, p2):
    point = random.randint(1, len(p1) - 1)
    return p1[:point] + p2[point:]

def mutate(chromosome, rate=0.01):
    return [gene if random.random() > rate else 1 - gene
            for gene in chromosome]

def ga(population, fitness_fn, generations=100):
    for _ in range(generations):
        scored = [(fitness_fn(ind), ind) for ind in population]
        scored.sort(reverse=True)
        selected = [ind for _, ind in scored[:len(population)//2]]
        offspring = []
        while len(offspring) < len(population):
            p1, p2 = random.sample(selected, 2)
            child = mutate(crossover(p1, p2))
            offspring.append(child)
        population = offspring
    return max(population, key=fitness_fn)

2.19 Constraint Satisfaction Problems

A CSP consists of:

  • A set of variables $X = \{X_1, ..., X_n\}$
  • A set of domains $D = \{D_1, ..., D_n\}$
  • A set of constraints $C = \{C_1, ..., C_m\}$

Constraint Types:

  • Unary: Involves one variable (e.g., $X_1 \neq 3$)
  • Binary: Involves two variables (e.g., $X_1 \neq X_2$)
  • Higher-order: Involves 3+ variables

Examples: 8-queens, map coloring, scheduling, Sudoku, crosswords

2.20 Constraint Propagation

Arc Consistency (AC-3): An arc $(X_i, X_j)$ is consistent if for every value in $D_i$, there is some value in $D_j$ that satisfies the binary constraint. AC-3 removes values from domains that cannot be part of any solution.

def ac3(csp):
    queue = [(Xi, Xj) for Xi in csp.vars for Xj in csp.neighbors[Xi]]
    while queue:
        Xi, Xj = queue.pop()
        if revise(csp, Xi, Xj):
            if not csp.domains[Xi]:
                return False
            for Xk in csp.neighbors[Xi] - {Xj}:
                queue.append((Xk, Xi))
    return True

def revise(csp, Xi, Xj):
    revised = False
    for x in set(csp.domains[Xi]):
        if not any(csp.constraint(x, y) for y in csp.domains[Xj]):
            csp.domains[Xi].remove(x)
            revised = True
    return revised

2.21 Backtracking Search

Backtracking is the basic algorithm for CSPs — assigns variables one at a time, backtracking when constraints are violated.

Variable Selection Heuristics:

  • MRV (Minimum Remaining Values): Choose variable with fewest legal values
  • Degree Heuristic: Choose variable involved in most constraints on remaining vars

Value Ordering Heuristic:

  • LCV (Least Constraining Value): Choose value that rules out fewest choices for neighbors

Forward Checking: When $X$ is assigned, delete from neighbors' domains any value inconsistent with $X$'s assignment.

2.22 Adversarial Search (Game Playing)

Games are adversarial problems where multiple agents have conflicting goals. AI games typically assume:

  • Two players (MAX and MIN)
  • Zero-sum (one player's gain = other's loss)
  • Perfect information (chess, checkers)
  • Deterministic (no dice)

:

$$(s) = \begin{cases} u(s) & \text{if terminal} \\ \max_{a} (Result(s,a)) & \text{if MAX's turn} \\ \min_{a} (Result(s,a)) & \text{if MIN's turn} \end{cases}$$

The recursion goes all the way to terminal states, computing utilities for leaves and propagating values up the tree.

2.23 Tree Example

graph TD A["A (MAX)"] --> B["B (MIN)"] A --> C["C (MIN)"] A --> D["D (MIN)"] B --> B1["3"] B --> B2["12"] B --> B3["8"] C --> C1["2"] C --> C2["4"] C --> C3["6"] D --> D1["14"] D --> D2["5"] D --> D3["2"]

A = max(3, 2, 2) = 3 → choose path B

2.24 Alpha-Beta Pruning

Alpha-Beta computes the same value as but prunes branches that cannot influence the decision.

  • $\alpha$: Value of best (highest) choice found for MAX so far
  • $\beta$: Value of best (lowest) choice found for MIN so far
  • Prune when $\alpha \geq \beta$

Properties:

  • With perfect ordering: $O(b^{d/2})$ — can search twice as deep
  • With random ordering: $O(b^{3d/4})$

Best ordering heuristics:

  • Try best moves first (using killer moves, history heuristic)
  • Use iterative deepening to find good moves early

2.25 Iterative Deepening for Games

Iterative Deepening A* (IDA*) combines A* with iterative deepening for game trees with limited time.

Strategy:

  1. Search to depth 1, record best move and value
  2. Search to depth 2, if time permits
  3. Continue until time runs out
  4. Play best move found at deepest completed search

This allows the program to always have a move ready, even when it cannot complete a deep search.

2.26 Additional Game Refinements

Transposition Tables: Store hash of board states to recognize repeated positions.

Quiescence Search: Extend search at "noisy" positions (captures, checks) to avoid horizon effect.

Move Ordering: Try likely good moves first to maximize pruning.

Killer Moves: Heuristic that tracks moves that caused beta cutoffs at a given depth.

Null-Move Pruning: Skip a move to see if current position is still good — useful for pruning.

Late Move Reduction: Search less deeply on late moves in the move list.

Unit 3: Knowledge & Reasoning

3.1 Knowledge Representation (KR)

Knowledge Representation is the field of AI concerned with encoding knowledge about the world in a form that a computer system can use to solve complex tasks.

A good KR system should support:

  1. Representational Adequacy: Express all needed knowledge
  2. Inferential Adequacy: Allow deriving new knowledge
  3. Inferential Efficiency: Reason efficiently
  4. Acquisitional Efficiency: Acquire new knowledge easily

3.2 Mapping Between Representations

When designing KR, three levels of representation must be aligned:

  • Knowledge Level: What is known (declarative)
  • Logical Level: How knowledge is encoded (sentences)
  • Implementation Level: How sentences are stored physically

The mapping between levels must be efficient for the inference procedures used.

3.3 Approaches to Knowledge Representation

  1. Simple Relational Knowledge: Use tables/relations. Limited inference.
  2. Inheritable Knowledge: Class hierarchy with inheritance (e.g., semantic networks, frames).
  3. Inferential Knowledge: Use logic (predicate logic) — supports full inference.
  4. Procedural Knowledge: Encode knowledge as procedures (IF-THEN rules).

3.4 Semantic Networks

A semantic network is a graph where nodes represent concepts and edges represent relationships.

graph TD A[Animal] -->|is-a| B[Bird] B -->|is-a| C[Canary] C -->|has-property| D[yellow] C -->|has-property| E[sings] A -->|is-a| F[Dog] F -->|is-a| G[Rex] G -->|has-property| H[brown]

Features: Inheritance, semantic distance, semantic similarity. Used in natural language understanding and knowledge graphs (e.g., WordNet, Google Knowledge Graph).

3.5 Frames

A frame is a data structure representing a stereotypical situation with slots and fillers.

Frame: Bird
  isa: Animal
  has_part: wings
  has_part: feathers
  can_fly: yes
  default_color: varies

Frame: Canary (inherits from Bird)
  isa: Bird
  default_color: yellow
  can_fly: yes

Frame: Penguin (inherits from Bird)
  isa: Bird
  can_fly: no  # override
  habitat: Antarctic

Frames support default values, inheritance, and exception handling — unlike strict logic which requires everything explicitly.

3.6 Production Rules

Production rules encode knowledge in IF-THEN format:

IF (patient has fever)
AND (patient has cough)
THEN (possible_diagnosis is infection)

IF (infection = bacterial)
AND (not allergic to penicillin)
THEN (prescribe amoxicillin)

Advantages: Modular, easy to add/modify rules, transparent reasoning.

Limitations: Scaling, conflict resolution, no generalization.

3.7 Issues in Knowledge Representation

  1. Granularity: What is a single fact vs. a derived fact?
  2. Defaults: How to handle exceptions (most birds fly, but penguins don't)?
  3. Negation: How to represent "not" cleanly?
  4. Disjunction: How to express OR?
  5. Quantifiers: How to represent "all" and "some"?
  6. Inference direction: Forward (data-driven) vs Backward (goal-driven)?
  7. Belief Revision: How to update knowledge when new info arrives?

3.8 Logic-Based Representation

Propositional Logic:

  • Atomic propositions: $P$, $Q$, $R$
  • Connectives: $\land, \lor, \neg, \to, \leftrightarrow$
  • Truth values: true/false

Predicate Logic (FOL):

  • Predicates: $\text{Bird}(x)$, $\text{Friend}(x, y)$
  • Quantifiers: $\forall, \exists$
  • Functions: $\text{FatherOf}(x)$

Unit 4: Using Predicate Logic & Probabilistic Reasoning

4.1 First-Order Predicate Logic (FOL)

FOL is the foundation of many KR and reasoning systems. It extends propositional logic with:

  • Constants: Specific objects (e.g., $Ram$, $5$, $Bucharest$)
  • Variables: Stand for any object (e.g., $x$, $y$)
  • Predicates: Describe properties or relations (e.g., $Brother(x, y)$)
  • Functions: Map objects to objects (e.g., $Father(x)$)
  • Quantifiers: $\forall$ (all), $\exists$ (some)

4.2 Representing Simple Facts in Logic

Father(Ram, Shyam)
Mother(Sita, Ram)
Male(Ram)
Female(Sita)
Person(Ram)
King(Ram)
Person(Ram) → Mortal(Ram)
∀x (Person(x) → ∃y (Father(y, x)))
∀x (Student(x) → ∃y (Enrolled(x, y)))
∀x ∀y (Father(x, y) → Parent(x, y))
∀x (Parent(x, y) ∧ Male(x) → Father(x, y))

Predicate Logic examples for the exam:

  1. John is a student: $Student(John)$
  2. John studies AI: $Studies(John, AI)$
  3. Every student studies AI: $\forall x (Student(x) \to Studies(x, AI))$
  4. Some students study AI: $\exists x (Student(x) \land Studies(x, AI))$

4.3 Representing Instant and ISA Relationships

Instant Relationship: A specific individual is an instance of a class.

  • $King(John)$ — John is a king
  • $Brother(John, Mary)$ — John is a brother of Mary

ISA Relationship: A class is a subclass of another class.

  • $\forall x (King(x) \to Person(x))$ — Every king is a person
  • $\forall x (Elephant(x) \to Mammal(x))$ — Every elephant is a mammal

Subsumption: A specific concept is a subset of a more general concept.

  • $Elephant \subseteq Mammal$

4.4 Computable Functions and Predicates

Functions return a single value:

  • $FatherOf(John) = Bob$
  • $Square(3) = 9$
  • $Length(FatherOf(John))$ — composition

Equality $FatherOf(John) = FatherOf(Bob)$ — same person.

Predicates return true/false. They can express:

  • Properties: $Red(Car_1)$
  • Relations: $Greater(3, 2)$
  • Membership: $In(A, B)$

4.5 Resolution — Refutation Method

Resolution is a complete inference method for FOL. It works by refutation — to prove $G$, we assume $\neg G$ and derive a contradiction.

Resolution Rule (Propositional): From $P \lor Q$ and $\neg P \lor R$, derive $Q \lor R$.

Resolution Rule (FOL):

  • From $P(x) \lor Q(x)$ and $\neg P(A) \lor R$, derive $Q(A) \lor R$
  • Variables can be substituted via unification

Steps:

  1. Convert KB to CNF (Conjunctive Normal Form)
  2. Negate the goal
  3. Apply resolution until empty clause $\Box$ is derived

4.6 Resolution Example

Given:

  1. $\forall x (King(x) \to Person(x))$
  2. $King(John)$
  3. Goal: $Person(John)$

In CNF:

  1. $\neg King(x) \lor Person(x)$
  2. $King(John)$
  3. $\neg Person(John)$ (negated goal)

Resolution:

  • From (1) and (3): $\neg King(John)$
  • From (2) and above: $\Box$ (empty clause — contradiction!)

Therefore: $Person(John)$ is proved.

4.7 Unification

Unification finds a substitution $\theta$ that makes two logical expressions identical.

def unify(x, y, subst={}):
    if subst is None: return None
    if x == y: return subst
    if is_variable(x):
        return unify_var(x, y, subst)
    if is_variable(y):
        return unify_var(y, x, subst)
    if is_compound(x) and is_compound(y):
        return unify(x.args, y.args, unify(x.op, y.op, subst))
    if isinstance(x, list) and isinstance(y, list):
        if not x: return subst
        head_subst = unify(x[0], y[0], subst)
        return unify(x[1:], y[1:], head_subst)
    return None

Example: Unify $Knows(John, x)$ with $Knows(y, Mary)$ → $\theta = \{x/Mary, y/John\}$

4.9 Probabilistic Reasoning

Real-world knowledge is often uncertain. Probability theory provides a mathematical framework for reasoning under uncertainty.

Bayes' Theorem:

$$P(A|B) = \frac{P(B|A) \cdot P(A)}{P(B)}$$

where $P(A|B)$ is the posterior, $P(B|A)$ is the likelihood, $P(A)$ is the prior.

Example — Medical Diagnosis:

  • Disease prevalence: $P(D) = 0.001$
  • Test sensitivity: $P(+|D) = 0.99$
  • Test specificity: $P(-|\neg D) = 0.99$
  • $P(D|+) = \frac{0.99 \times 0.001}{0.99 \times 0.001 + 0.01 \times 0.999} \approx 0.09$ (only 9%!)

4.10 Bayesian Networks

A Bayesian Network is a directed acyclic graph representing probabilistic dependencies among variables.

Components:

  1. Nodes: Random variables
  2. Edges: Direct dependencies
  3. CPT (Conditional Probability Table): For each node, $P(X | Parents(X))$

Joint Distribution:

$$P(X_1, ..., X_n) = \prod_{i=1}^n P(X_i | Parents(X_i))$$

Inference: Compute posterior probabilities given evidence — exact (enumeration, variable elimination) or approximate (MCMC, Gibbs sampling).

4.11 Bayesian Network Example — Medical Diagnosis

graph TD A[Cold] --> C[Fever] B[Flu] --> C B --> D[BodyAche] A --> E[Cough] B --> E

Probabilities:

P(Cold) = 0.05
P(Flu) = 0.02

P(Cough | Cold, Flu) = {T,T: 0.95, T,F: 0.90, F,T: 0.85, F,F: 0.05}
P(BodyAche | Flu) = {T: 0.7, F: 0.1}

Given symptoms (Fever=T, Cough=T, BodyAche=T), compute $P(Cold | symptoms)$.

4.12 Dempster-Shafer Theory

Dempster-Shafer Theory handles uncertainty and ignorance more flexibly than Bayesian methods.

Key Concepts:

  • Frame of Discernment: Set of mutually exclusive hypotheses $\Theta$
  • Basic Probability Assignment (BPA): $m: 2^\Theta \to [0,1]$ where $m(\emptyset) = 0$, $\sum_A m(A) = 1$
  • Belief Function: $Bel(A) = \sum_{B \subseteq A} m(B)$ — lower bound on belief
  • Plausibility Function: $Pl(A) = 1 - Bel(\neg A)$ — upper bound on belief

Dempster's Rule of Combination:

$$m_1 \oplus m_2 (Z) = \frac{1}{1 - K} \sum_{X \cap Y = Z} m_1(X) \cdot m_2(Y)$$

where $K = \sum_{X \cap Y = \emptyset} m_1(X) \cdot m_2(Y)$ measures conflict.

Advantage over Bayes: Can represent ignorance explicitly. A BPA can assign mass to $\Theta$ meaning "don't know yet."

4.13 Fuzzy Sets

A fuzzy set $A$ over universe $U$ is defined by a membership function $\mu_A: U \to [0,1]$ that assigns each element a degree of membership.

Comparison with Classical Sets:

  • Crisp set: $\mu_A(x) \in \{0, 1\}$
  • Fuzzy set: $\mu_A(x) \in [0, 1]$ (continuous)

Example:

Let T = "Tall Person"
μ_T(160cm) = 0.0
μ_T(170cm) = 0.3
μ_T(180cm) = 0.7
μ_T(190cm) = 1.0

Operations on Fuzzy Sets:

  • $\mu_{A \cap B}(x) = \min(\mu_A(x), \mu_B(x))$ — AND
  • $\mu_{A \cup B}(x) = \max(\mu_A(x), \mu_B(x))$ — OR
  • $\mu_{\neg A}(x) = 1 - \mu_A(x)$ — NOT

4.14 Fuzzy Logic and Fuzzy Inference

Fuzzy Rules: IF $X$ is $A$ AND $Y$ is $B$ THEN $Z$ is $C$.

Mamdani Inference (Fuzzy Logic System):

  1. Fuzzification: Convert crisp input to fuzzy values
  2. Rule Evaluation: Apply fuzzy rules to get fuzzy output
  3. Aggregation: Combine fuzzy outputs
  4. Defuzzification: Convert fuzzy output back to crisp value (e.g., centroid method)

Applications:

  • Air conditioners, washing machines (control systems)
  • Automotive systems (ABS, traction control)
  • Camera autofocus, image processing
  • Stock market prediction, weather forecasting

5.1 Introduction to NLP

Natural Language Processing (NLP) is the field of AI concerned with the interaction between computers and human (natural) languages.

Goals of NLP:

  1. Understanding: Interpret meaning from text/speech
  2. Generation: Produce human-like text/speech
  3. Translation: Convert between languages
  4. Information Extraction: Pull structured data from text

Challenges: Ambiguity (lexical, syntactic, semantic, pragmatic), context dependence, world knowledge, idiom/sarcasm.

Syntactic Processing (Parsing) analyzes the grammatical structure of sentences.

Steps:

  1. Morphological Analysis: Identify word stems and affixes
  2. POS Tagging: Mark words with parts of speech (noun, verb, etc.)

5.3 Semantic Analysis

Semantic Analysis determines the meaning of a sentence beyond its structure.

Key tasks:

  • Word Sense Disambiguation (WSD): Choose correct meaning of polysemous words
  • Named Entity Recognition (NER): Identify names, places, dates
  • Semantic Role Labeling: Identify agent, action, object, instrument
  • Coreference Resolution: Determine which entities a pronoun refers to

Example: "John ate the apple" — Agent=John, Action=eat, Object=apple

5.4 Discourse and Pragmatic Processing

Discourse Processing: Analyzes relationships between sentences in a text.

  • Anaphora Resolution: "John went home. He was tired." — "He" refers to John
  • Discourse Structure: Topic shifts, sub-topics

Pragmatic Processing: Understands intent and context.

  • Speech Acts: Assertive, directive, commissive, expressive, declarative
  • Implicature: "Can you pass the salt?" — request, not question
  • Deixis: "this", "here", "now" — context-dependent

5.5 Forms of Learning

Machine Learning has several paradigms:

  1. Supervised Learning: Learn mapping $f: X \to Y$ from labeled examples $(x_i, y_i)$. Examples: classification (SVM, decision tree), regression (linear, polynomial)
  2. Unsupervised Learning: Find structure in unlabeled data. Examples: clustering (K-means, hierarchical), dimensionality reduction (PCA)
  3. Reinforcement Learning: Learn through interaction, maximizing cumulative reward. Examples: Q-learning, policy gradient
  4. Semi-supervised Learning: Combine labeled + unlabeled data
  5. Active Learning: Query the user for labels on uncertain examples
  6. Online Learning: Update model incrementally with each example
  7. Transfer Learning: Apply knowledge from one domain to another

5.6 Inductive Learning

Inductive Learning infers general rules from specific examples.

Concept Learning: Given examples of a concept (positive) and non-examples (negative), find a hypothesis that explains all positives and no negatives.

Candidate Elimination Algorithm:

  • Maintains Specific boundary S (most specific consistent hypothesis)
  • Maintains General boundary G (most general consistent hypothesis)
  • Updates S and G as each example is processed
  • Converges when S == G or hypothesis is fully determined

Version Space: Set of all hypotheses consistent with the data. Lies between S and G.

5.7 Decision Tree Learning

Decision Tree is a tree where each internal node tests an attribute, branches represent outcomes, leaves represent class labels.

ID3 Algorithm (Information Gain):

  1. Compute entropy of current set
  2. For each attribute, compute information gain
  3. Choose attribute with highest gain as split
  4. Recurse on subsets

$$Entropy(S) = -\sum_{i=1}^c p_i \log_2 p_i$$

$$Gain(S, A) = Entropy(S) - \sum_{v \in Values(A)} \frac{|S_v|}{|S|} Entropy(S_v)$$

Advantages: Easy to interpret, handles categorical/numerical data.

Issues: Overfitting, greedy choice (not global optimum), instability.

Pruning: Reduced error pruning, rule post-pruning.

from sklearn.tree import DecisionTreeClassifier
from sklearn.datasets import load_iris

X, y = load_iris(return_X_y=True)
clf = DecisionTreeClassifier(criterion='entropy', max_depth=3)
clf.fit(X, y)
print(f"Accuracy: {clf.score(X, y):.3f}")

5.8 Explanation-Based Learning (EBL)

EBL uses domain theory to explain why a specific example belongs to a concept, then generalizes the explanation into a reusable rule.

Algorithm:

  1. Explanation: Construct proof tree showing why example is classified positively
  2. Identification: Determine sufficient conditions for the proof
  3. Generalization: Replace specific constants with variables
  4. Compilation: Add resulting rule to knowledge base

Advantages:

  • Single example can yield useful general rule
  • Speed-up learning by exploiting domain theory
  • Rules are guaranteed to be correct (since they are derived from proof)

Example: From "Cup(X) ∧ Holds(X,Y) → LiftingPossible(X,Y)", generalize that any object X that is a cup and holds Y can lift Y.

5.9 Learning Using Relevance Information

Some features are more relevant than others for classification. Feature selection techniques:

  • Filter Methods: Use statistical measures (chi-square, mutual information)
  • Wrapper Methods: Use model performance to evaluate subsets
  • Embedded Methods: Feature importance from model (e.g., tree-based importance)

Mutual Information:

$$I(X; Y) = \sum_{x,y} p(x,y) \log \frac{p(x,y)}{p(x)p(y)}$$

High $I(X; Y)$ means feature $X$ is highly relevant to target $Y$.

5.10 Neural Network Learning

Artificial Neural Networks (ANNs) are computational models inspired by biological neurons.

Perceptron:

$$y = f\left(\sum_{i=1}^n w_i x_i + b\right)$$

where $f$ is an activation function (step, sigmoid, ReLU).

Backpropagation Algorithm:

  1. Forward pass: Compute output for given input
  2. Loss computation: $E = \frac{1}{2}(y - \hat{y})^2$
  3. Backward pass: Compute $\frac{\partial E}{\partial w}$ for each weight
  4. Weight update: $w_{new} = w - \eta \frac{\partial E}{\partial w}$

Multi-Layer Perceptron (MLP): Input → Hidden Layers → Output, using non-linear activations.

import torch
import torch.nn as nn

class NeuralNet(nn.Module):
    def __init__(self, input_size, hidden_size, num_classes):
        super().__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, num_classes)

    def forward(self, x):
        out = self.fc1(x)
        out = self.relu(out)
        out = self.fc2(out)
        return out

model = NeuralNet(4, 16, 3)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)

# Training loop
for epoch in range(100):
    outputs = model(X_train)
    loss = criterion(outputs, y_train)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

5.11 Genetic Learning

Genetic Learning applies genetic algorithms to learn from examples:

  1. Encode hypotheses as bit strings (chromosomes)
  2. Define fitness function based on accuracy on training data
  3. Apply selection, crossover, mutation
  4. Iterate to evolve best hypotheses

Advantages: Global search, parallelizable, handles complex fitness landscapes.

Disadvantages: Slow convergence, parameter tuning, no guarantee of optimum.

5.12 Expert Systems — Architecture

An Expert System is a computer system that emulates the decision-making ability of a human expert.

graph TD U[User] -->|Query| UI[User Interface] UI <-->|Show reasoning| UI UI --> IE[Inference Engine] IE <--> KB[Knowledge Base] IE <--> WM[Working Memory] KB -->|IF-THEN Rules| KB WM -->|Facts| WM IE -->|Advice| UI UI -->|Answer| U KA[Knowledge Acquisition] -->|Update| KB KE[Knowledge Engineer] --> KA

Components:

  1. Knowledge Base: Domain rules and facts
  2. Inference Engine: Forward/backward chaining to deduce conclusions
  3. Working Memory: Current problem state
  4. Explanation Facility: Justifies reasoning ("Why?" / "How?")
  5. Knowledge Acquisition Module: Adds new knowledge
  6. User Interface: Friendly interaction

5.13 Representing and Using Domain Knowledge

Forward Chaining (Data-Driven):

  1. Start with known facts in working memory
  2. Find rules whose antecedents match facts
  3. Add rule conclusions to working memory
  4. Repeat until goal is reached or no rules apply

Backward Chaining (Goal-Driven):

  1. Start with goal to be proven
  2. Find rules whose conclusions match the goal
  3. Recursively try to prove antecedents as subgoals
  4. Succeed when all antecedents are in working memory

When to use:

  • Forward: Many possible conclusions, data is readily available
  • Backward: One specific goal, data must be discovered
# Example rules
rules = [
    {'if': {'fever', 'cough'}, 'then': 'infection'},
    {'if': {'infection', 'high_wbc'}, 'then': 'bacterial'},
    {'if': {'bacterial', 'not_allergic_penicillin'}, 'then': 'prescribe_amoxicillin'},
    {'if': {'allergic_penicillin'}, 'then': 'prescribe_azithromycin'}
]

def forward_chain(facts):
    changed = True
    while changed:
        changed = False
        for rule in rules:
            if rule['if'].issubset(facts) and rule['then'] not in facts:
                facts.add(rule['then'])
                changed = True
    return facts

5.14 Expert System Shells

An Expert System Shell is an expert system with the domain-specific knowledge removed. It provides the general framework — inference engine, explanation facility, user interface.

Popular Shells:

  • EMYCIN: Based on MYCIN, medical diagnosis
  • OPS5: Production rule language by Carnegie Mellon
  • CLIPS: NASA-developed, C-based
  • Jess: Java-based, modern
  • Prolog: Logic programming language, often used for expert systems

Advantages of Shells: Reduces development time, separates reasoning from knowledge, provides tested infrastructure.

5.15 Knowledge Acquisition

Knowledge Acquisition is the process of gathering and encoding knowledge from human experts.

Methods:

  1. Interviews: Structured, unstructured, or focused
  2. Protocol Analysis: Expert thinks aloud while solving problem
  3. Observation: Watch expert perform tasks
  4. Repertory Grid Analysis: Elicit distinctions experts make
  5. Machine Learning: Induce rules from data automatically

Challenges:

  • Knowledge Bottleneck: Experts have tacit knowledge hard to articulate
  • Inconsistency: Experts may give different answers for similar cases
  • Rapport: Requires collaboration with expert
  • Verification: Validating correctness of encoded rules
